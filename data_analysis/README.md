# Анализ сохранённых результатов

Одна команда объединяет прежнюю диагностику дополнения MSDZip,
проверку фиксированного GeoSCD AND MSDZip и подробный разбор потери Recall.
Она использует завершённый H0/H1 benchmark с настоящими сохранёнными картами;
архивы и прежние скрипты из `scripts/` для запуска больше не нужны.

По умолчанию сравниваются **MSDZip mod256, AnyChange, DINOv2, GeoSCD,
RGB-DIFF и LPIPS**, а также уже выбранное **GeoSCD AND MSDZip**.
Сравнение выполняется отдельно на VAL и TEST, по каждому фасаду, состоянию
(`crack`, `paint_patch`, `unchanged`), семейству условий и конкретному сценарию.
Это классы процедурных изменений данного benchmark, а не семантические классы
COCO и не разметка реальных повреждений.

## Запуск

Из корня репозитория после `git pull --ff-only`:

```bash
conda activate scd_bench
FC_ANALYSIS_TAG="$(date -u +%Y%m%dT%H%M%S%NZ)"
python -u -s -m data_analysis \
  --run "$PWD/runs/20261010T131625089776Z-neural-codecs-comparison" \
  --fusion-run "$PWD/runs/20261011T112832126075755Z-geoscd-msdzip-frozen" \
  --gallery-limit 60 \
  --out "$PWD/runs/${FC_ANALYSIS_TAG}-method-recall-analysis"
```

`--fusion-run` необязателен для других исходных запусков. Для текущих данных
он проверяет точное повторение прежних VAL/TEST-чисел GeoSCD/MSDZip/AND:
попиксельных TP/FP/FN/TN, фасадных средних и исходных порогов.
Нужен полный исходный benchmark, а не экспорт только JSON-метаданных.
Каждый запуск создаётся в новом каталоге; существующие результаты сохраняются.

Вычисляются метрики по уже имеющимся картам. Модели, кодеки и обучение не
запускаются; GPU и веса не нужны. Зависимости — имеющиеся NumPy и Pillow.
Первичная проверка хешей читает файлы всего исходного benchmark, включая методы,
не вошедшие в новое сравнение. Поэтому она может занимать время на большом диске.

## Приоритет Recall

Текущие исходные пороги ранее выбирались по F1 на VAL либо задавались авторским
бинарным решением. Этот запуск не меняет прошлую калибровку задним числом.
Он показывает стоимость пересечения для Recall. Жёсткое AND само по себе
не может улучшить Recall относительно исходной маски GeoSCD.

Для каждого визуального метода MSDZip и исходная маска делят GT-положительные
пиксели на четыре группы: найденные обоими, найденные только MSDZip,
найденные только визуальным методом, пропущенные обоими. Отрицательные пиксели
делятся аналогично. GT=255 исключается только оценивателем.

- `lost_recall`: верные находки только визуального метода / все видимые
  GT-положительные пиксели H1. Это потеря Recall в процентных пунктах.
- `rejected_baseline_tp_fraction`: те же отброшенные находки / все TP исходного
  метода. Это доля утраченных верных обнаружений, другой знаменатель.
- `baseline_recall` / `confirmed_recall`: исходный Recall / Recall пересечения.
- `added_recall`: MSDZip-only TP / все видимые GT-положительные пиксели H1.
  Это потенциальное дополнение, без принятия нового TEST-правила OR.
- `removed_h0_fpr` / `removed_h1_fpr`: удалённые FP визуального метода / все
  отрицательные пиксели соответствующего H0/H1-случая.

Прежние пропуски GeoSCD не выдаются за потери, вызванные MSDZip.
Неопределённые доли записываются как `null`, а не как ноль. Средние считаются
по случаям внутри фасада, затем поровну по фасадам. Пиксельные суммы — только
диагностика; не независимые статистические наблюдения.

Для GeoSCD сохранённые MSDZip score и сырые bpb сравниваются у сохранённых TP,
отброшенных TP, удалённых/сохранённых FP, MSDZip-only TP и общих пропусков.
Печатаются число пикселей, mean/p10/p50/p90/min/max score и bpb, расстояние
`threshold - score`, а также средняя по каналам абсолютная RGB-разность (0–255).
Из uint8 перед вычитанием выполняется переход в int16.

Отдельно показаны отброшенные/сохранённые TP на границе GT-правки и остальные
видимые положительные пиксели. Граница — GT=1 рядом с известным GT=0 в
8-соседстве. GT=255 и пространство вне изображения не считаются фоном.
Эти признаки используются только для анализа ошибок, не для принятия решения.

Низкий score объясняет непосредственное срабатывание порога. Сравнение цветов,
bpb, границ и условий выявляет ассоциации; оно само по себе не доказывает,
почему модель не распознала важное изменение.

## Что сохраняется

- `summary.json` / `summary.txt`: все методы, VAL/TEST-средние, каждый фасад,
  классы и условия; JSON дополнительно содержит каждый конкретный сценарий,
  фасадные строки каждого среза, диагностику дополнения и происхождение.
- `facades.csv`: каждый метод на каждом фасаде.
- `classes.csv`: каждый метод по классу состояния, в среднем и по фасадам.
- `conditions.csv`: каждый метод по семейству условий, в среднем и по фасадам.
- `case_metrics.csv`: метрики и TP/FP/FN/TN каждого случая/метода.
- `recall_cases.csv`: разделение ошибок и потери/добавления Recall для каждого
  визуального метода относительно MSDZip.
- `score_diagnostics.csv`: score, bpb, RGB-разность и граничные группы GeoSCD.
- `gallery.html` и `gallery/`: RGB, GT, все предсказания, карта отброшенных
  верных находок GeoSCD и удалённых FP, MSDZip-score в единой шкале [0,1].
- `analysis_contract.json`, `selected_cases.json`, `input_artifacts.json`,
  `run.json`: выборка, фиксированные решения, хеши, среда и конечный статус.

Галерея сначала показывает худшую потерю Recall каждого фасада, затем другие
случаи. Это явно отмеченный разбор ошибок по GT после вычисления; решения не
меняются. `--gallery-limit` ограничивает только число изображений, численная
оценка всегда использует все исходные non-sham VAL/TEST-случаи.
Для переноса галереи сохраняйте HTML вместе с папкой `gallery/`.

Прежние OR/AND-диагностики для всех baseline сохранены в JSON как
`val_fusion_diagnostics`, только на VAL. На TEST оценивается единственное
ранее выбранное объединение GeoSCD AND MSDZip. Анализ ошибок других масок
не превращается в выбор новых TEST-комбинаций.

## Проверка и интерпретация

```bash
python -s -B -m unittest discover -s tests -p test_data_analysis.py -v
python -s -B -m unittest discover -s tests -v
```

Оценка остаётся исследовательской: процедурные изменения, ранее просмотренный
TEST, небольшой набор фасадов и отсутствие доверительных интервалов.
Новые правила с приоритетом Recall следует выбирать на TRAIN/VAL, например по
Recall при допустимом H0 FPR или бюджете инспекции; итоговую независимую оценку
проводить на ещё не использованном наборе. Этот анализ не является полной
системой оплаченных H0/H1-объяснений или доказательством научной новизны AND.
