# Работа над Facade Change Benchmark

Отвечай владельцу по-русски. Прочитай README.md, затем релевантную строку
[указателя компонентов](docs/2026-10-24-main-workflow.md) и названные там код/тесты.
Для научного изменения прочитай разделы 1–3 и нужную карточку
[master-map 2026-11-17](docs/2026-11-17_dissertation_research_master_map.md).
Обычное исправление не требует чтения всей истории исследований.

## Рабочий цикл

1. Проверь status, HEAD, remote и worktrees. Сохраняй чужие изменения;
   не применяй к ним reset/clean/stash. Проверь реальных потребителей, включая
   CLI, importlib, subprocess, конфигурации и документацию.
2. Меняй владельца операции, переиспользуя workflow, method registry и RunStore.
   Не создавай конкурирующий runner, ledger или копию evaluator. Похожая метрика
   может относиться к другому протоколу. Рефакторинг отделяй от изменения метода.
3. Проверь компонент, небольшой сквозной fixture и численный паритет.
   Обязателен `python -s -B -m unittest discover -s tests -v`.
   Датированные test-файлы с дефисами должны подключаться через существующие
   component `load_tests`; пропуск зависимости не подтверждает работу модели.
4. Codex Cloud выполняет CPU-проверки; `/home/sasha/...` относится к компьютеру
   владельца. В новой Cloud-среде используй `bash scripts/setup_cloud.sh`.
   Не обновляй рабочую среду без конкретной необходимости. Веса, полный benchmark
   и обучение не запускаются ради организационного изменения.
5. Соблюдай PEP 8. Редактируй существующие подходящие файлы; новые имена начинай
   с YYYY-MM-DD. Старые файлы не переименовывай только ради даты. Обновляй один
   действующий runbook сценария; историю запусков сохраняй с её статусом.
6. Делай содержательные небольшие коммиты и отправляй в согласованную ветку
   (для этой консолидации — `dev_late`), без force-push и переписывания main.
   В ответе дай ссылку на commit, точную команду `git pull --ff-only`, проверки
   и ограничения. Патчи/копии исходников — только по просьбе владельца.

## Научные ограничения

- Исходный сигнал — RGB uint8 на исходной решётке без EXIF-поворота. Alignment
  использует grayscale proxy и переносит исходный RGB; маски остаются боковой
  ветвью. `source_to_reference`: позднее наблюдение → раннее, без гипотезы
  «раннее здоровое». Сохраняй масштаб опоры, расширяй холст; вырожденная/огромная
  H должна приводить к отказу, а не скрытому resize.
- Поддержка учитывает геометрию, интерполяцию и alpha. Чёрный RGB может быть
  валиден; overlap не доказывает отсутствие окклюзий. Unknown не равен фону.
  ID категорий и порядок каналов бери из проверенной текущей онтологии.
- Единица split и статистики — физическое здание/фасад; виды, даты и производные
  не разделяются между split. Сохраняй текущие назначения и leakage checks по
  building_id, view_id и SHA-256. `facades-v4`: 70/10/20 по зданиям; одиночные и
  неизвестные адреса допускаются в semantic TRAIN без выдуманного building_id,
  но не создают пары. Их независимость от holdout не считается доказанной.
- Имя файла — гипотеза о дате/виде; metadata review — подтверждение. Неизвестные
  записи остаются в manifest. Готовые manifest, RGB и геометрия переиспользуются.
- Состояние, аномалия, временное изменение, прогноз и ответ — разные задачи.
  Разность COCO-масок не является подтверждённым событием. TRAIN-threshold и
  VAL-threshold протоколы не подменяются друг другом. Будущее исключается в
  causal/forecast режимах; retrospective доступ фиксируется явно.
- Ремонт начинает новый локальный эпизод; повторное повреждение — отдельное
  событие. Полезные признаки и контекст важнее битовой длины; codec необязателен.
- Каждый запуск имеет новый каталог, конфигурацию, входные/model/source hashes
  и конечный статус. Не ослабляй проверки ради старого cache. Используй текущие
  RunStore/Fingerprints; retry не перезаписывает историю. Найденное evidence
  и реально показанные модели пиксели/текст фиксируются отдельно.
- Данные, веса, приватные конфигурации и outputs не публикуются. Перед GPU
  проверь память/процессы; чужие процессы не останавливай. Модели загружай
  последовательно по действующей конфигурации. Старые ветки, исходные проекты,
  результаты и недоступный локальный `data/dataset_statistics.py` сохраняются.
