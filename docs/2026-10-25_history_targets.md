# Целевые маски для готовых историй

Существующие COCO-аннотации переносятся в координаты сохранённых RGB-кропов.
Повторный DINO, выравнивание и нарезка RGB не нужны. Дополнительный проход —
растеризация и перенос масок на CPU; оригиналы читаются для проверки SHA,
RGB декодируется только для небольшой галереи.

`review.csv` из `history-scores` — список возможных событий для проверки, а не
требование вручную заполнить тысячи строк до начала обучения. Новый `labels.csv`
содержит автоматические метки для пригодных переходов. Отдельная ручная выборка
нужна для независимой проверки качества обнаружения реальных изменений.

## Правила целевых классов и неизвестных областей

Маски сохраняют категории COCO, все их пересечения и порядок каналов по category ID.
По умолчанию целевыми считаются все аннотированные категории. `--categories NAME ...`
выбирает их подмножество по точным именам. Новых классов «автобус» или «дерево» нет.

| Ситуация | Пиксельная цель и использование |
|---|---|
| В обе даты область размечена, целевые классы совпали | `0`: совпадение на сравнимой размеченной области |
| В обе даты область размечена, целевые классы различаются | `1`: различие аннотаций выбранных классов |
| В одной/обе даты нет аннотации, нет геометрической поддержки, crowd либо конфликт снимков одного года | `255`: неизвестно, исключено из пиксельного сравнения |
| Различие укладывается в допуск границы | `255`, а не отрицательный пример |

Сохраняется существующий multilabel-контракт семантической ветви: отсутствие класса
считается отрицательной меткой только **внутри объединения аннотированных классов**.
Это предполагает полноту целевой разметки внутри такой области. Вне неё отрицательные
метки не создаются. Если аннотации неполны и внутри объединения, автоматические
метки также ненадёжны — галерея предназначена в том числе для этой проверки.

RGB подаётся целиком: дерево, автобус, тени и освещение остаются входным контекстом.
Геометрическая поддержка не считается детектором перекрытий. Например, исчезновение
маски трещины под автобусом не доказывает ремонт. Без сравнимой аннотации это неизвестно.

Из пиксельных целей получается метка перехода между последними двумя годами:

- `1`, если есть достаточная область устойчивого различия целевых аннотаций;
- `0`, если сравнимая размеченная область достаточно велика и стабильна, нет даже
  малого/пограничного различия и ни один размеченный целевой участок не остался
  без сравнимой поддержки;
- пустая метка во всех остальных случаях. Стабильная часть кропа не делает весь
  пример отрицательным, если другая целевая часть исчезла из разметки.

Даже `0` имеет область действия `annotation_support_only`: он не доказывает,
что весь неразмеченный контекст не изменился. Оба вида автоматических меток —
слабые цели для обучения, не подтверждённая разметка физических событий.
Появление/исчезновение дефекта в полностью неразмеченной области может остаться
неизвестным; нельзя получать полноту обнаружения таких событий по этим целям.

Начальные пороги: минимум 64 известных пикселя и 0.1% общей геометрической области,
минимум 8 изменившихся пикселей, допуск границы 1 пиксель канонического кропа.
Это настраиваемые стартовые параметры, не установленные исследованием критерии.
Очень тонкое изменение может остаться неизвестным. Параметры фиксируются до TEST;
для проверки чувствительности используются TRAIN/VAL и новые каталоги запусков.

Снимки одного года объединяются только там, где **все** их аннотации известны
и совпали. Разногласие даёт неизвестность, а не новый временной шаг.
Автоматического распознавания ремонта и сброса истории по маскам нет; известный
ремонт задаётся через проверенную разметку `history_start_year` в основном workflow.

## 1. Перенести маски и получить цели

Дождитесь завершения извлечения признаков: команда требует завершённый `index.json`.
Она привязывается к точному сохранённому манифесту истории, а не к изменяемому latest.

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only

conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare history-targets \
  --features data/histories/features/index.json \
  --out runs/2026-10-25-history-targets-001
```

Источник COCO определяется через сохранённую сессию выравнивания и её манифест.
Если старая история не содержит этой ссылки, нужен явный
`--annotation-manifest /path/to/reviewed/manifest.json`. Это подготовленный манифест
с `source.coco_json`, `source.coco_sha256`, категориями и метаданными изображений,
а не сам COCO. Соответствие устанавливается по SHA оригинального изображения;
проверяются здание, вид, год, split и размеры. Идентичность COCO ID не предполагается.
Изображение без соответствующей записи даёт неизвестные маски с отдельным счётчиком.

Перенос: сохранённая H из исходного снимка в раннюю опору, затем сдвиг на точный
`bbox_xywh` кропа. Для дискретных битовых масок используется nearest-neighbor.
Никаких новых ключевых точек или изменения геометрии. Каждый нужный оригинал
растеризуется один раз за проход, после чего его маски распределяются по кропам.

По умолчанию TRAIN/VAL, минимум три разных года к моменту события. TEST открывается
только при явном `--splits test`; это отдельный экспорт после фиксации протокола.
Прерванный экспорт продолжайте той же командой с `--resume`: готовые маски
наблюдений переиспользуются. Новые данные или параметры требуют нового каталога.

Выходы:

- `summary.json` — положительные/стабильные/неизвестные переходы, причины,
  покрытие и число целей по split и категориям;
- `gallery.html` — до 60 примеров, распределённых по зданиям и статусам:
  RGB и семантические маски по годам, карта разницы;
- `labels.csv` — готовые цели для обучения, происхождение и доля известных пикселей;
- `maps/*.npz` — перенесённые multilabel-битсеты и геометрическая поддержка;
- `targets/*.npz` — карта `0/1/255`, отдельные карты выбранных классов и category IDs;
- `index.json`, `experiment_contract.json`, `run.json`, `events.jsonl`, `units/*.json`
  — привязка к признакам, исходным аннотациям, коду, параметрам и хешам артефактов.

## 2. Обучить и сравнить модели

В TRAIN и VAL должны присутствовать оба класса меток. Проверка выполняется до
загрузки GPU; неизвестные кропы не превращаются в отрицательные для набора баланса.
Если пригодных примеров не хватает, `summary.json` показывает конкретную причину.

Короткая проверка всех восьми вариантов на существующих DINO-признаках:

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow train history-models \
  --features data/histories/features/index.json \
  --labels runs/2026-10-25-history-targets-001/labels.csv \
  --allow-derived-labels \
  --models pair pooled gru transformer --time-modes gaps none \
  --device cuda:0 --batch-size 64 --epochs 2 --seed 42 \
  --out runs/2026-10-25-history-mask-models-smoke-001
```

Для полного запуска замените `--epochs 2` на `--epochs 100 --patience 15`
и выходной каталог на `runs/2026-10-25-history-mask-models-001`.
CPU поддерживается через `--device cpu`. Разбиение по зданиям, отсутствие будущих
кадров во входе истории и равные суммарные веса зданий сохраняются.

`pair` учится на последней паре; `pooled` дополнительно получает среднее прошлого;
GRU и Transformer учат представление последовательности. Каждый вариант обучается
с интервалами лет (`gaps`) и без них (`none`). Это supervised-обучение по меткам
различий целевых аннотаций. Неизвестные события пропускаются в loss, но остаются
в исходном наборе и доступны для последующего inference всех историй.

`--allow-derived-labels` явно разрешает `review_status=derived`. Код проверяет
метки против завершённого исходного экспорта и хешей карт; исправленные вручную
значения нельзя продолжать выдавать за исходные автоматические метки. Для ручной
проверки отдельной выборки используется `accepted`, `comparable=yes` и фактический
`review_source` по [основному контракту](2026-10-25_history_models.md).

Происхождение `annotation_derived` сохраняется в `models.json`, CSV предсказаний
и метриках. Оценка согласия с автоматическими масками не называется независимой
проверкой временных событий. Для `benchmark history-models` на таких же целях
также требуется `--allow-derived-labels`.

Сами по себе пропуски целей не учат модель игнорировать автобусы. Для проверки
устойчивости нужны отдельно проверенные примеры «целевой участок виден и стабилен,
изменился только контекст» либо контролируемые синтетические помехи. Полностью
закрытый целевой участок не даёт известного отрицательного события.

## 3. Тот же обработчик для парных кропов

Общий код `facade_change/annotation_targets.py` отвечает за чтение COCO, проекцию
multilabel-масок, неизвестность, допуск границ и цели `0/1/255`. Исторический и
парный адаптеры используют эти же функции. Команда `history-targets --features ...`
и её `labels.csv` для обучения остаются совместимыми. Добавлен общий псевдоним
`workflow prepare targets`; оба имени вызывают один parser.

Для готового `data/crops` вместо `--features` передайте `--crops`:

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only

OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare history-targets \
  --crops data/crops \
  --out runs/2026-10-25-crop-targets-001
```

`--features` и `--crops` взаимоисключающие. `--history-root` и `--min-years`
относятся к историям; пары уже содержат ровно два разных года. По умолчанию
обрабатываются все готовые парные кропы TRAIN/VAL; TEST требует явного `--splits`.
Проверяются split, SHA изображений, метаданные, размеры и геометрия.
Источник COCO читается по хешу манифеста из crop-run, без поиска latest.
Явный `--annotation-manifest` доступен для старых наборов, как в режиме историй.

Парный адаптер использует `reference_to_crop` и `source_to_crop` из каждого
`crop.json`: эти матрицы **уже включают** сдвиг конкретного окна. Для сохранённого
GeoSCD применяется исходное плотное поле с nearest-сэмплированием масок. Истории
сохраняют свою общую раннюю опору и `bbox_xywh`; индексы парных кропов не выдаются
за общие физические участки истории. Размер RGB и положение окна не меняются.

Оригинал растеризуется один раз для всех его выбранных кропов. RGB не нарезается
и не декодируется повторно, кроме маленькой галереи; исходные файлы хешируются
для проверки происхождения. Работа выполняется на CPU, модели не загружаются.
Прогресс показывает проверку кропов, перенос аннотаций, получение различий и
финальную проверку входов. Прерванный запуск продолжается с `--resume`;
готовые карты наблюдений переиспользуются, завершённый каталог не затирается.

Результат имеет те же основные имена: `labels.csv`, `summary.json`, `gallery.html`,
`maps/`, `targets/`, `index.json` и журнал запуска. Индекс явно имеет
`kind=crop_annotation_targets`. CSV дополнительно содержит `dataset_crop_id`,
`pair_id`, пути исходных RGB-кропов и метод выравнивания. Эти метки предназначены
для парного анализа; для `train history-models` по-прежнему используется
**исторический** `history-targets-001/labels.csv`, связанный с DINO-последовательностями.
Метрики по перенесённым маскам описывают согласие с аннотациями, а не независимую
проверку физических временных событий.

Уже работающий `history-targets` держит загруженные функции в памяти. Этот коммит
не меняет `history_features`, `history_models`, код сетей, растеризатор и сохранённые
входы/выходы. Обновление можно принять во втором терминале и запустить парный
экспорт в **новый** каталог параллельно. Исторический экспорт должен завершиться
до запуска обучения по его CSV. Resume после смены отпечатка кода по-прежнему
требует исходную версию или новый run; активный процесс перезапускать не нужно.

## 4. Полная заданная матрица синтетических контролей

Маски реальных аннотаций и процедурная синтетика имеют разные источники целей.
Экспорт масок сам по себе аугментации не создаёт. Для синтетики используется
существующий `prepare synthetic`, который читает те же готовые парные кропы:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare synthetic \
  --crop-run data/crops \
  --config configs/2026-10-25_crop_controls.json \
  --out runs/2026-10-25-crop-synthetic-001
```

Новый конфиг повторяет четыре прежних состояния — `unchanged`, `crack`,
`paint_patch`, `self_paste` — и все 18 прежних сценариев наблюдения: clean,
шесть теней, два экспонирования, два контраста, два баланса белого, два blur,
два JPEG и одно перекрытие. Каждое состояние сочетается с каждым сценарием:
**72 примера на выбранный исходный кроп**. Одновременные комбинации разных помех
не добавляются; алгоритмы и параметры существующего генератора сохранены.

Выборка явно ограничена **двумя уникальными опорными кропами на здание** TRAIN/VAL,
по прежнему детерминированному правилу разнообразия видов/опор и SHA-ранжированию.
Если уникальных пригодных кропов меньше, берётся доступное число. Минимальное
геометрическое покрытие 0.8 соответствует текущему экспорту. Это полная матрица
сценариев на выбранных основах, а не 72-кратное размножение всех кропов датасета.
Ни один кроп TEST не декодируется этим конфигом. Другой объём выборки задаётся
копией конфига и новым `--out`, без изменения split.

Процедурные цели фиксируют только внесённое редактирование; наличие реального
дефекта в исходном RGB не меняет H0/H1. Перекрытие имеет известную искусственную
видимость. Это не маски деревьев/автобусов реального снимка и не новые COCO-классы.
Генератор сохраняет `selection.json`, `index.json`/CSV, `summary.json`, `gallery.html`,
галереи семейств и точные маски внесённых изменений. Обучение кодеков, инференс
методов и их комбинации запускаются затем отдельно через существующие стадии.

## Проверка реализации

```bash
python -s -B -m unittest discover -s tests -p test_history_features.py -v
python -s -B -m unittest discover -s tests -v
```

Синтетические проверки покрывают проекцию, RLE/полигоны, пересечения, crowd,
неизвестность и частичное перекрытие, альтернативы одного года, выбор классов,
допуск границ, хеши, продолжение экспорта, отсутствие чтения TEST-изображений
и сквозное CPU-обучение/оценку GRU с сохранением происхождения целей.
Качество на реальных фасадах и CUDA-производительность здесь не измерены.

Проверка 2026-10-25: общий набор — 1059 тестов, без ошибок, 3 пропуска
для внешних оригинальных ArIB/BCM/VTM компонентов. Обучение/оценка нового пути
проверены на CPU с PyTorch 2.5.1; реальные аннотации владельца здесь не запускались.

После добавления общего модуля и парного адаптера: 1070 тестов, без ошибок,
3 тех же пропуска; отдельно 74 проверки историй/масок прошли. На фиксированном
примере до/после совпали все 112 массивов и 16 записей событий (кроме путей и
идентификатора нового запуска). Старый загруженный обработчик успешно завершился
при обновлении его файла на диске во время проекции; старые метки приняты текущим
обучающим кодом. Проверены также смешанная H/GeoSCD-геометрия, отсутствие чтения
RGB при отключённой галерее, исключение TEST, resume и защита исходного crop-run
от использования как каталога результата. Реальные GPU-запуски здесь не выполнялись.
