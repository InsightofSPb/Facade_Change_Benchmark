# Геометрия GeoSCD и подготовка кропов

Этап 1–4 октября: третий способ совмещения, кропы из оригиналов, сохранение
разбиения по зданиям и небольшие процедурные контрольные примеры. DINOv2,
RSCD, AnyChange, SSIM и компрессионные модели этими командами не запускаются.

## 1. Геометрическая ветка GeoSCD

Адаптер использует VGGT и функции геометрии из
[официального GeoSCD](https://github.com/ZilingLiu/GeoSCD/tree/dd31369654e96d6843cc4bbcebce854a8bc2159b),
commit `dd31369654e96d6843cc4bbcebce854a8bc2159b`. SAM и детектор изменений
GeoSCD не загружаются. Название для статьи: **GeoSCD geometry-only (VGGT dense
reprojection)**; это сравнение геометрии, а не воспроизведение полного детектора.

Установка на компьютере владельца:

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
bash scripts/setup_geoscd.sh --download-weights
conda activate facade-geoscd
```

Скрипт создаёт отдельную среду Python 3.10 / Torch 2.6.0 / torchvision 0.21.0
с CUDA 11.8, клонирует фиксированный GeoSCD в соседний `GeoSCD-facade` и
скачивает официальные веса VGGT-1B. Среда `lposs` используется для уже работающих
SIFT/LoFTR и кропов. Без `--download-weights` веса не скачиваются; сам inference
тоже их не скачивает. Если веса уже есть, передай их путь через `--checkpoint`.
Не требуются SAM-веса или обучение. Версии зависимостей заданы в
`configs/2026-10-04_geoscd_geometry.requirements.txt`; фактическое окружение и
хеш весов фиксируются в каждом запуске.

Первый запуск: одна обычная пара и две пары, отклонённые прежними порогами.

```bash
python -B -m facade_change geoscd \
  --manifest runs/2026-10-03-first-anchor/manifest.json \
  --geoscd-root ../GeoSCD-facade \
  --checkpoint ../GeoSCD-facade/src/pretrained/model.pt \
  --device cuda:0 --pair 73:74 --pair 151:150 --pair 235:236 \
  --limit 0 \
  --comparison-run runs/2026-10-03-alignment-first-anchor \
  --out runs/2026-10-04-geoscd-smoke
```

Открой `comparison.html`: исходные снимки, SIFT/LoFTR и плотное совмещение
GeoSCD. После проверки smoke-прогона те же компоненты можно применить ко всему
фиксированному списку пар:

```bash
python -B -m facade_change geoscd \
  --manifest runs/2026-10-03-first-anchor/manifest.json \
  --geoscd-root ../GeoSCD-facade \
  --checkpoint ../GeoSCD-facade/src/pretrained/model.pt \
  --device cuda:0 --limit 0 \
  --comparison-run runs/2026-10-03-alignment-first-anchor \
  --out runs/2026-10-04-geoscd
```

Каждый `--out` должен быть новым каталогом. Если прежний SIFT/LoFTR прогон
лежит в другой папке, замени `--comparison-run` на неё. При сравнении проверяются
хеш исходного манифеста и идентичность пар.

### Координаты и ограничения

- Порядок входов: ранняя опора, поздний source. Первая карта GeoSCD содержит
  **координату source для каждого пикселя reference**: это карта обратного
  семплирования, а не гомография.
- Сохраняется официальный square-stretch RGB proxy: 1024 → 518. Геометрия
  выводится на решётке 518, без дополнительного изменения intrinsics/depth.
  Retinex и перенос цветов отключены. Финальные RGB берутся из оригиналов.
- Поправка к коду авторов: относительное положение камер вычисляется как
  `E_source @ inverse(E_reference)`, вместо предположения о единичной первой
  камере. Формат камеры — OpenCV world-to-camera.
- Native-координаты учитывают центры пикселей и размеры каждого оригинала.
  Интерполируется поле смещений: это сохраняет тождественное преобразование на
  границах. Поздний RGB семплируется непосредственно из оригинала один раз.
- Плотный результат имеет исходную решётку **reference**. Он не является
  расширенным union-холстом SIFT/LoFTR. Полный source остаётся в исходных данных;
  области вне reference не считаются временным изменением и не получают
  выдуманных координат на опоре.
- Геометрическая поддержка, alpha и предсказанные окклюзии сохраняются раздельно.
  Предсказанная окклюзия не является GT и не удаляет ошибки из области оценки.
  Поддержка не доказывает физическую видимость или точность совмещения.
- Соответствия в официальном коде округляются на решётке VGGT. Поднятие до native
  RGB не добавляет отсутствующую точность геометрии; мелкие детали нужно проверить.

Статус `computed_needs_review` означает вычисленный результат, которому нужна
проверка. Его нельзя сравнивать как «успешную пару» с автоматическим routing gate
SIFT/LoFTR. Для мини-сравнения в статье используем одинаковые пары и устойчивые
архитектурные точки в общей области reference: ручную пригодность совмещения,
ошибки геометрии и время. Фактическое качество и GPU-запуск на фасадах ещё
требуют локального прогона; CPU-проверки контракта этого не заменяют.
`manual_review.csv` — шаблон проверки с именами снимков. Для заполнения скопируй
его за пределы завершённого запуска: исходные артефакты и их хеши сохраняются.

## 2. Кропы из уже готового SIFT/LoFTR прогона

Эта команда использует сохранённую геометрию, без повторного matching и без
нового split. По умолчанию берётся LoFTR; SIFT используется, если только он
прошёл пороги. Каждая пара экспортируется один раз. Не прошедшие пары сохраняются
в `excluded_pairs.csv`, а исходные изображения остаются в том же gold/split.

```bash
conda activate lposs
python -B -m facade_change crop-dataset \
  --batch-run runs/2026-10-03-alignment-first-anchor \
  --methods loftr sift \
  --tile-size 256 --stride 128 --min-valid-fraction 0.8 \
  --controls 3 \
  --out runs/2026-10-04-crops
```

Из оригиналов получаются RGB пары 256×256, геометрические маски поддержки,
`not_comparable` и абсолютная RGB-разность. Разность — диагностический сигнал.
Окклюзии деревьями, машинами и лесами остаются предметом проверки. Порог 0.8
позволяет до 20% неподдержанных пикселей в кропе; эти пиксели явно отмечены маской.
Количество и распределение кропов определяются геометрией и могут отличаться от
70/10/20. Назначения зданий и исходных изображений сохраняются.

Экспорт включает общий JSON/CSV индекс с путями к RGB/маскам, `building_id`,
`view_id`, годами, split, идентичностью gold, хешами исходных снимков и геометрией;
копию `split.json`, сводку и галерею. Процедурные примеры индексируются отдельно.
`--controls 3` выбирает не более трёх исходных кропов **на весь набор**: четыре
варианта «изменение цвета есть/нет × изменение условий есть/нет» и два sham
контроля на каждый. Это максимум 18 примеров, с тем же зданием и split; они не
являются разметкой настоящих повреждений или ремонта.

Плотную геометрию GeoSCD этот экспорт автоматически не подмешивает: её сначала
проверяем отдельно. COCO остаётся разметкой отдельных наблюдений; истинная
разметка временных изменений здесь не создаётся. После локального экспорта и
просмотра имеем подготовленные RGB/маски/индекс для следующего этапа плана.

## Проверки кода

2026-10-04: `python -B -m unittest discover -s tests -v` — **122 теста прошли**
за 35.8 с. Новые проверки покрывают направление плотной карты, неравные native
решётки и границы, relative camera transform, alpha/невалидные проекции,
разделение окклюзий и support, выбор сохранённой геометрии, отсутствие повторного
matching, сохранение split/gold и общий бюджет контролей. `bash -n` проверил
синтаксис setup-скрипта. Установка новой CUDA-среды и загрузка VGGT в Cloud
не выполнялись; реальные результаты получаются приведёнными локальными командами.
