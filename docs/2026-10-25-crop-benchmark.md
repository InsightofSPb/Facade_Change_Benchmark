# Маски и бенчмаркинг выбранных парных кропов

Вход — завершённый `runs/2026-10-25-crop-augmented-001`. По логу владельца
подготовлены 500 настоящих пар кропов, 494 уникальные синтетические основы,
9 000 настоящих вариантов и 35 568 процедурных примеров. Переиспользуются RGB,
выравнивания и список отбора. Нужны перенос целевых масок и расчёт карт методов.

Команды `spatial-change` относятся к моделям историй из другого эксперимента.
Здесь проверяются парные кропы и помехи. У двух наборов разные координатные
решётки и наблюдения; их числа нельзя смешивать без явного общего протокола.

## 1. Перенести маски только на выбранные 500 пар

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only

OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare targets \
  --crops data/crops \
  --selection-plan runs/2026-10-25-crop-augmented-001 \
  --out runs/2026-10-25-crop-targets-001
```

`--selection-plan` принимает завершённый отбор или завершённые аугментации
с `cohort_selection.json`. Вход выше соответствует фактически использованным
RGB: берутся все 500 настоящих пар, а не только 494 процедурные основы.
Проверяются хеши crop-run, summary, индекса и split, уникальность ID и точное
совпадение строк с индексом. Отбор повторно не ранжируется. Для переноса масок
не требуется текущая версия генератора: используются сохранённые ID/геометрия.

Split проверяется по всему индексу, но геометрия, оригиналы и поддержка читаются
только для выбранных пар запрошенных split. По умолчанию ожидаются 312 TRAIN
и 188 VAL. Файлы невыбранных кропов и TEST не декодируются. Каждый нужный
оригинал растеризуется один раз; используются готовые H или плотные поля.

Основные выходы — 1 000 карт наблюдений в `maps/*.npz` и 500 карт переходов
в `targets/*.npz`: общая цель 0/1/255, отдельные классовые карты и category IDs.
Цель исходной пары переиспользуется для её 18 вариантов; 9 000 копий целей
не создаются. Остальные выходы: `labels.csv`, `summary.json`, `index.json`,
`gallery.html`, run/contract и существующий append-only ledger.

Неразмеченные области остаются неизвестными. Автобусы, деревья и тени остаются
в RGB. Строгая метка события unknown может сосуществовать с известными
пиксельными целями части окна; весь пример от этого не становится отрицательным.
Ручная разметка всех строк не требуется.

`prepare history-targets --features ...` сохраняет прежние аргументы и поведение;
`--selection-plan` относится только к `--crops`. Прерванный перенос продолжается
той же командой с `--resume`. Завершённые результаты неизменяемы.

## 2. Небольшая CPU-проверка двух ветвей

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow benchmark crops \
  --dataset-run runs/2026-10-25-crop-augmented-001 \
  --targets-run runs/2026-10-25-crop-targets-001 \
  --methods rgb_diff ssim \
  --max-pairs-per-split 5 \
  --device cpu \
  --out runs/2026-10-25-crop-benchmark-smoke-001
```

Берутся до 5 настоящих пар TRAIN и 5 VAL, по SHA-256 ID до просмотра оценок.
Процедурная ветвь получает соответствующие уникальные ранние основы через
`synthetic_members`. Сохраняются все сценарии и состояния, а не случайно
перемешанные отдельные аугментации. Точный список находится в selection.json.

Для полного прогона той же командой задаются `--max-pairs-per-split 0` и новый
`--out runs/2026-10-25-crop-benchmark-001`. Это 44 568 сравнений на метод,
89 136 для двух методов. `--branches synthetic` выбирает только процедурную
ветвь, `--branches real` — настоящую. Для real нужен targets-run.
Готовый полный экспорт масок того же crop-index тоже можно переиспользовать:
из него выбираются нужные ID. Несовпадение снимка данных или каналов — отказ
до создания моделей.

Реестр методов общий с прежним бенчмарком: RGB-DIFF, SSIM, LPIPS, DINOv2,
Semantic DINO, AnyChange, GeoSCD, RSCD и компрессионные адаптеры. Дополнительным
моделям передаётся прежний `--methods-config configs/methods.local.json`:
объект methods, локальные исходники/веса и worker Python. Веса не скачиваются;
legacy pickle требует явного `--trust-checkpoint`. MSDZip требует checkpoint_path
соответствующего метода и сохраняет прежние проверки происхождения весов.
GPU-методы работают последовательно через существующий isolated worker;
перед CUDA записываются память и процессы, чужие задачи не останавливаются.

## Входы, цели и неизвестные области

Синтетика сравнивает A с T(edit(A)). Истина описывает внесённое редактирование,
а не все реальные дефекты A. Unchanged и self-paste имеют H0, crack и paint_patch
— H1. Self-paste сохраняется как контроль, но исключается из калибровки и
основных средних. Модель получает RGB и исходную поддержку опоры, без GT и
знания искусственного перекрытия. Скрытое изменение исключается из оценки.

Настоящая ветвь сравнивает A с T(B). На входе модели — RGB и исходное
геометрическое пересечение пары, одинаковое для всех вариантов. Непрозрачная
помеха остаётся в RGB. Только оценщик исключает её пиксели из общей и классовых
целей. Остальные фотометрические помехи не меняют целевые классы.

Пиксель 255 исключается из TP/FP/FN/TN, а не превращается в 0. Полностью
скрытая/неизвестная область имеет 0 оцениваемых пикселей и неопределённые метрики.
Настоящие цели — различия исходных аннотаций на сравнимой размеченной области;
независимая разметка физических повреждений/ремонта этим не создаётся.

## Калибровка и метрики

Новый явный протокол — `crop-development-clean-train-v1`. Прежний
`benchmark synthetic` сохраняет VAL-калибровку и TEST-проверку.

Здесь один порог на метод и ветвь выбирается только на чистых TRAIN-примерах.
Критерий: максимальный средний по зданиям F1 известных положительных областей;
при равенстве — меньший FPR известных отрицательных пикселей, затем больший
порог. Сначала усредняются примеры здания, затем здания имеют равный вес.
Обычная сетка — 101 значение от 0 до 1; расширенная сетка RSCD сохранена.
Правило — строгое float32 score > threshold, без min/max нормализации карты.

Порог фиксируется для всех помех и VAL. Отдельные пороги по тени, JPEG, классу
или VAL не подбираются. Методы native-mask используют исходное бинарное
предсказание без подмены непрерывным прокси и без калибровки.

Сохраняются F1, IoU, precision, recall, FPR, TP/FP/FN/TN и числа известных,
положительных и игнорируемых пикселей. F1/IoU/precision/recall — для областей
с известными положительными пикселями; стабильные области участвуют в
счётчиках и FPR. Пропуски — null, не идеальное распознавание пустого класса.

Для настоящих пар дополнительно оцениваются изменения каждого целевого класса.
Одна карта обычного детектора сравнивается с известной картой изменений класса.
Это не IoU семантических состояний и не утверждение, что RGB-DIFF предсказывает
название класса. Карты классов на вход модели не поступают.

Отчёт разделён по методам, ветвям, TRAIN/VAL, классам, сценариям и H0/H1.
Агрегирование: среднее по пригодным примерам здания, затем равное среднее
по зданиям, с числом внесших вклад зданий для каждой метрики. TRAIN — диагностика
после выбора порога; основное сравнение здесь — VAL. TEST не используется.
Метрики двух ветвей не смешиваются в одно общее F1.

Выборка обогащена по аннотациям; окна и временные пары коррелированы.
Это среднее по выбранным кропам здания, а не IoU объединения всего фасада.
Доверительные интервалы и независимая итоговая TEST-оценка не создаются.

## Выходы и продолжение

summary.json: численность, вычисленные/переиспользованные карты и основные VAL
средние. cases.csv: примеры/методы; classes.csv: настоящие пары по классам;
metrics.json: все агрегаты и числа зданий; threshold_selection.json: пороги
и TRAIN-кривые. gallery.html показывает RGB, цель, оценку и предсказание;
неизвестность серая. До 48 примеров выбраны детерминированно с распределением
по ветвям, split и зданиям.

Оценки, raw scores, native predictions и дополнительные выходы методов
сохраняются в сжатых maps/*.npz, с атомарными units/*.json и существующим ledger.
Полный прогон создаёт 44 568 карт на метод; объём зависит от дополнительных
каналов адаптера. Все карты одновременно в RAM не удерживаются.

Прерванный бенчмарк продолжается той же командой плюс --resume. Готовые карты
проверяются по хешам и повторно не инферируются. Код, библиотеки, веса, worker
и каналы должны совпадать; при resume возможна загрузка модели для проверки
идентичности. Завершённый результат неизменяем; новые методы/данные требуют
нового out. RGB и признаки/модели историй этим этапом не пересоздаются.
