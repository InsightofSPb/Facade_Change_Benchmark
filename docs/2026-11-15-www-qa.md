# WWW: supplied-region QA, 2026-11-15

Это реализация протокола, не результат сравнения качества. Единица исследования —
здание. Заданный регион не означает автоматическое обнаружение изменений на всём
фасаде. Реальные модели в Cloud не запускались.

Актуальная подготовка **all-candidates + V4**, отдельное сохранение пилотных
решений и уточнение C−A описаны в
[обновлении от 2026-11-16](2026-11-16-www-ca-v4-preparation.md).
Команды старых smoke ниже — история протокола; не запускайте их цепочкой для
нового review. Текущая подготовка не требует GPU, индексации или approval.

## Первый этап: публичный runner

`python -m facade_change.agentic www run` читает **только указанный** публичный
`questions.json`, его RGB/support и указанный публичный индекс/корпус. Приватные
соседние ответы, аннотации и превью не открываются. Три условия:

- `photos_only`: одинаковая исходная локальная история;
- `fixed_retrieval`: однократный поиск по вопросу, зданию, обязательным датам и
  последнему локальному изображению;
- `bounded_agentic_retrieval`: до двух поисков, выбор запроса/локального изображения
  моделью; разрешён финальный ответ без поиска.

Одинаковы Qwen, предобработка, русский текст задачи, схема ответа, исходные фото,
фильтры и максимальные бюджеты B/C. Jina вызывается существующим `ModelPool`,
последовательное управление GPU и технический OOM retry остаются прежними.
Поиск — max cosine между текстовыми/визуальными представлениями реального
Jina-CLIP-v2, затем evidence_id при равенстве. Лексического fallback нет.

Начальные **предварительные**, ещё не проверенные на WSL GPU ограничения: шесть
локальных фото, четыре архивные записи, два архивных фото, до четырёх bbox.
У B один поиск top-4; у C до двух top-2, ранее показанные записи исключаются.
Это вместимость шестидатных пилотных вопросов плюс два архивных фото при max_images=8,
а не утверждение о достаточности VRAM. Ограничения Qwen токенов/изображений/времени
берутся из существующей конфигурации. `--protocol` может явно уменьшить лимиты;
обязательные даты не отбрасываются. Изменение замороженного протокола требует
нового запуска. Перед полным прогоном нужно измерить 2–3 случая на конфигурации 16k.

Фиксируются фактические расходы **всех** Jina/Qwen вызовов, повторные изображения,
cache hits и технические retry. Суммарный лимит генеративного контекста относится
к Qwen; Jina ограничен числом поисков и собственным max_text_tokens. Равные
максимумы не означают равное потребление. Кэш не расходует новые токены, но
логические лимиты QA учитывают source_usage, поэтому кэш не даёт лишних действий.

Ответ зависит от task: earliest_evidence называет наблюдение/дату присутствия,
temporal_change — интервал сравнения, archival_qa — ответ по источникам. Это
не дата возникновения повреждения. Цитаты проверяются по реально показанным ID;
проверка ID не оценивает смысловую поддержку текста. Bbox необязательны, но
заданные координаты проверяются строго. Native-рамка архива не превращается в
локальную рамку; документ не предоставляет пространственную локализацию.

Архив импортируется `www archive-import --package ... --out ...` по общему
контракту `www_archival_evidence_package` v1. Даты, права, источники, page/parent,
реальные SHA и размер файлов проверяются; ничего не скачивается. Индекс строится
`www archive-index --corpus ... --config ... --out ...`. Неопределённые identity
сохраняются в корпусе, но не служат подтверждением: начальная политика допускает
только verified, совпадающее здание и совместимый вид. Все исключения записываются.
Даты доступности не подменяются датами съёмки. Cutoff вопросов/корпуса должен
совпадать; поздний сбор требует новой согласованной версии, не backdating.

Все outputs создаются в новом каталоге: contract.json, run.json, events.jsonl,
results.json, predictions-<condition>.json, gallery.html, per-question preparation,
messages, exposure, полные запросы/ответы, costs и bbox overlays с меткой MODEL.
`--resume-from` переносит только валидные completed/abstained результаты при
идентичных вопросах/корпусе/конфигурации/исходниках/промпте и неизменных ресурсах.
Ошибки выполняются заново; старый запуск не меняется. JSON/worker ошибки — error,
не abstained. Оборванный JSON не исправляется. `--quiet` отключает прогресс;
итоговый JSON остаётся в stdout.

Без архива нужен явный `--allow-empty-archive`: такой результат помечается
`plumbing_no_archive` и не является сравнением retrieval. Любой inference без
отдельной approved offline оценки остаётся unscored.

## Второй этап: inventory, review и offline endpoints

`www inventory` читает все canonical tracks и splits, проверяет оригинальные
full-frame SHA, сохраняет ссылки на полные кадры и датированные thumbnail-превью.
Отсутствующие оригиналы, неопределённая identity, недостаточная история,
повторение SHA между зданиями/splits и непроверенное прежнее использование
явно отражаются в исключениях. Входные снимки и alignment не пересоздаются.
`question_counts_complete=false` означает, что supplied candidates не покрывали
этот split. Для полных proposal counts сначала выполните `qa generate` по всем
splits на **той же** версии histories и annotation index.

Адрес берётся только из явно сохранённого поля address исходного manifest либо
из `--addresses`: `{"buildings":[{"building_id":"...","address":"...",
"aliases":[],"source":{"path":"...","sha256":"..."}}]}`. Неизвестные адреса
сохраняются как unknown, без транслитерации ID в доказанный адрес.

VAL — development. Для TEST по умолчанию статус `earlier_exposure_not_audited`.
TRAIN не становится независимой evaluation-когортой. `--exposure-audit` принимает
`kind:www_exposure_audit`, `protocol_sha256`, `protocol_source:{path,sha256}` и
`buildings:[{building_id,cohort,prior_exposure,reviewer,audit_sources,reason}]`.
Evaluation допустима лишь для TEST, `cohort:evaluation`, `prior_exposure:none_found`,
с reviewer и непустыми `audit_sources:[{path,sha256}]`; файлы/хеши проверяются.
Это фиксирует проведённый человеком аудит предыдущих обучений/демо/отладок,
а не автоматически доказывает отсутствие любого прежнего использования.
Известные использованные здания можно явно отнести к development.

`www batch` выбирает до заданного размера round-robin по building/family:
сначала число дат и временной охват, затем SHA256(seed,question_id).
По умолчанию не более 12 вопросов на здание, anchor-box IoU между выбранными
регионами одного вида не больше 0.5. Действительные размеры/исключения сохраняются.
Геометрическое ограничение не заменяет review физических event_id. Deterioration,
repair, stable и unassessable устанавливает рецензент; candidate families не GT.
100 вопросов / 15–20 зданий — цель сбора, не известное количество; шесть VAL
зданий не превращаются в большее число независимых объектов из-за новых кропов.

`www handoff` читает только два указанных private JSON внутри coordination ZIP,
сохраняет все исходные тексты и уточнение case 03. Получается 5 earliest, 8 visible
change, 3 no-substantial-change. **Approved=0, reviewed_boxes=0.** Без `--candidates`
возможна переносимая проверка handoff, но соответствие исходным owner-файлам
остаётся pending. С `--candidates` требуется точный SHA из handoff и совпадение
вопросов, RGB/geometry, дат и owners. Пакет не является публичным архивным корпусом.

`www review-page` создаёт приватные gallery.html/review.html и drafts.private.json.
Числа координат редактируются; отдельный checkbox подтверждает каждую рамку.
Изменение координат/ID снимает подтверждение. Export включает только явно
выбранные решения, сохраняет reviewer, rationale, expected_revision и вопрос.
При confirmed_change требуются подтверждённые event_id/bbox. Затем **существующий**
`qa review` повторно проверяет manifest/revision/координаты/маски. Никакого approval
при загрузке страницы нет. Текст handoff подставляется, повторно писать его не нужно.
Для следующей пачки исправлений укажите `--previous .../reviewed.json` и при создании
страницы, и при применении `qa review`.

В drafts различаются положительные факты исходной человеческой аннотации одного
снимка, автоматические temporal proposals и human-reviewed temporal labels.
Предложения bbox — до четырёх крупнейших компонент различия **известных** bitset
аннотаций на общей поддержке. Это подсказки для RGB review, не временные GT.
Ни XOR, ни bbox не превращаются в temporal-change маску.

`www public` экспортирует whitelist исходных полей без annotation/review/proposal
данных. Такой candidate smoke явно unscored. `--limit 3` создаёт отдельный
замороженный manifest: максимальное число дат в каждой task, затем заполнение
по исходному selection order. При равенстве сохраняется исходный порядок;
это позволяет проверить длинную историю из шести фото уже в pilot smoke. Runner
всегда исполняет весь переданный manifest. Полный и 16-case прогоны используют тот
же runner, без другой реализации. Новая дата `--knowledge-cutoff` создаёт новую
версию; старые кандидаты, текстовый handoff и даты наблюдений не меняются.

Для primary scoring сначала нужны `qa review` → `qa export`. Затем `www plan`
замораживает approved cohort, явный reviewed `archival_stratum:true/false`,
development/evaluation и полный контракт model/config/questions/corpus/prompt.
Plan должен предшествовать запуску; `www score` отвергает поздний plan и любые
несовпадающие версии. Ранние candidate smoke не становятся scored задним числом.
После изменения freeze потребуется новая согласованная версия кандидатов/review/
export/plan; нельзя заменить cutoff внутри уже одобренного manifest.

Primary endpoint — корректность структурных полей по задачам, с fixed denominators,
families, building macro и paired building differences B−A, C−B, C−A. Missing/errors
остаются в cohort; runtime errors не считаются abstention. Insufficient evidence
отличается от no_change. Earliest scoring сохраняет дату и точность; явно reviewed
`equivalent_observation_ids` допустимы только на той же дате. Для archival_qa
assessment `archival_fact` требует supporting IDs и непустой список
`acceptable_structured_answers:[{decision:"supported",observation_ids:[],date_interval:...}]`.
Допустимые интервалы/precision/uncertainty перечисляются рецензентом, не угадываются.
Такая структурная оценка не проверяет смысл свободного текста.

Localization использует `qa evaluate`: one-to-one matching физических event_id,
IoU 0.25/0.5, K=1/3/5/10, precision/recall и производный F1. Сохранён repair
9aa159c: temporal pixel score требует покрытия **всего фиксированного** reviewed
reference support. При отсутствии настоящих reviewed temporal masks pixel/area
результат остаётся unavailable. Есть отдельные development/evaluation и archival
localization strata; объединённая таблица также сохранена.

Known-support hit/recall вычисляется по reviewed `supporting_evidence_ids` архива,
а validity — по реально exposed IDs. Неизвестные альтернативные источники не
объявляются нерелевантными. `known_support_exhaustive=false` — обычный начальный
случай. `blind-review.private.csv` и gallery.html скрывают название условия;
blind-key.private.json хранится отдельно. Человек оценивает фактическую поддержку,
противоречия и релевантность изображения/источника. Галерея показывает именно
экспонированный текстовый excerpt, не скрытое продолжение. Reviewed bbox overlays
лежат отдельно в `reviewed-overlays.private/`, никогда не подаются модели.

`annotation-diagnostics.private.json` отдельно оценивает drafting signals против
reviewed labels: precision/recall possible-change proposals и соответствие самой
ранней положительной аннотации reviewed visible presence. Это не четвёртое
условие модели и не источник gold для primary endpoint. Парные доверительные
интервалы добавлены в обновлении от 2026-11-16 ниже; тестов значимости нет.
Отчёт указывает число независимых зданий; выводов об улучшении нет.

## Совместимость archive v2 и reviewed archive earliest — дополнение 2026-11-15

`www archive-import` теперь сохраняет legacy `observation_date.precision:
mixed_document` **без нормализации**, только для `record_type:document`,
`parent_evidence_id:null`, `start:null`, `end:null`. Это недатированный родительский
документ с разными датами внутри, не датированное наблюдение фасада. Фото, включая
`image_in_document`, с таким precision отклоняются. Любой иной неизвестный precision
также остаётся ошибкой. Канонический `unknown` для родительских документов v3
по-прежнему принимается.

Дата публикации не превращается в дату съёмки. Capture dates дочерних изображений,
date_source/basis, parent/page lineage, права, даты сбора/доступности и SHA assets
сохраняются. В новом import run дополнительно лежит `source_package.json` — точная
байтовая копия исходного public package JSON; её SHA совпадает с
`config.json:package_sha256`. Исходный JSON и ZIP не меняются. `corpus.json`
содержит пути к скопированным assets, а `record_hashes.json` — хеши этих записей.

### Приватная reference-метка из архива

Существующие local-only labels с `earliest_observation_id`, строкой `present_by`
и `onset:unknown` работают как прежде. Для архивного фото рецензент явно добавляет
в **приватный label** `earliest_archive` и `present_by_interval`, удаляя скалярный
`present_by`. Ниже фрагмент схемы с placeholders; это **не одобрение реального
источника и не готовый decisions manifest**:

```json
{
  "assessment": "earliest_presence",
  "earliest_observation_id": "<reviewed photo evidence_id>",
  "present_by_interval": {
    "start": "2011-03-01",
    "end": "2011-03-31",
    "precision": "month"
  },
  "onset": "unknown",
  "archival_status": "verified_useful",
  "supporting_evidence_ids": ["<same reviewed photo evidence_id>"],
  "earliest_archive": {
    "corpus_path": "/home/sasha/Facade_Change_Benchmark/runs/2026-11-15-www-archive-v2-compat-001/corpus.json",
    "corpus_sha256": "<actual SHA-256 of corpus.json>",
    "record_sha256": "<value for this ID in record_hashes.json>",
    "asset_sha256": "<actual SHA-256 of the exposed image asset>",
    "building_id": "<case.building_id>",
    "view_id": "<case.view_id>",
    "region_id": "<case.region_id>",
    "match_basis": "<human visual justification that this image shows the same target region>"
  }
}
```

Остальные обязательные поля label (`reference_answer`, `observability`, limitations,
events и predeclared `archival_stratum`) и reviewer/rationale/revision остаются в
существующем review template. `events` у earliest пуст. Нового CLI-параметра для
review/export нет: привязка задаётся в `--decisions` и повторно проверяется при
review, export, plan и score. Её можно редактировать в существующем JSON-поле
приватной review.html. Источник и видимую область нужно проверить вручную до
approval, при необходимости обновив reference_answer; код не выбирает match.

Проверяются полный corpus SHA, record SHA, реальные media bytes, известный capture
interval, одинаковый retrospective cutoff, verified building и совместимый view.
Известный другой view запрещён. Если view в публичной записи null, приватный
review всё равно должен явно подтвердить целевой view/region и match_basis.
Это семантическое соответствие, не homography и не разрешение переносить native
координаты архива на локальный crop. Для одного evidence_id используется тот же
первый image asset по `(page_index or 0, path)`, который показывает runner.
Нельзя оценивать один asset, а ссылаться на другой под общим ID; отдельным фото с
разными датами нужны отдельные публичные записи с собственной lineage.

`present_by_interval` в точности повторяет `start/end/precision` capture date из
связанной записи. Поддерживаются year, month, day и документированный interval.
Март `2011-03-01…2011-03-31 / month` не становится точной датой 31 марта.
Неизвестная capture date и родительский PDF не могут задать dated earliest, даже
если publication_date известна. Onset всегда остаётся unknown.
Существующие локальные equivalent IDs сохраняются; для нового архивного target
эквивалентами могут быть его собственный ID и явно перечисленные локальные
наблюдения с точно совпадающим интервалом и precision. Другие архивные записи
без отдельной проверенной привязки не принимаются как эквиваленты.

Reference едина для A/B/C и утверждается **до просмотра результатов моделей**.
`www plan` связывает её с corpus SHA выбранного `--archive-index`; другой или
отсутствующий корпус — ошибка. Plan сохраняет `archive_corpus_sha256`, который
проверяет и score. Частные поля запрещены на публичной границе, gold-фото не
добавляется в начальные `questions[].observations`. Даже photos_only оценивается
против той же reference, хотя не получает архив.

Поэтому корректный ответ «видно уже в локальном 2009» может быть допустимым
ответом по доступным этому условию свидетельствам, но получить 0 по corpus-wide
earliest endpoint, если единая reviewed reference — архивное фото 2008.
Это не runtime error, не автоматически abstention и не доказательство ложности
локального наблюдения. Capture interval и ID проверяются в WWW primary score;
свободный текст по-прежнему требует отдельного semantic review.

Все 16 прежних текстовых решений, включая case 03, остаются суждениями о
показанных локальных снимках. Эта правка не одобряет реальный defect match 2012
года или более ранний источник, архивную поддержку, bbox либо temporal masks.
Смена reference требует явной новой review revision/export/plan, без правки старых
артефактов и без ретроспективной подгонки reference под ответы A/B/C.

### Транспорт, даты и координаты

Один общий `parse_reply` используется при live inference, в `validate_answer`
(также offline/resume) и диагностическом replay. Он принимает один JSON object
либо одну внешнюю JSON fence. Допустимы только пробелы и backticks после полностью
разобранного объекта внутри fence; текст внутри объекта не исправляется.
Несколько объектов, произвольная проза, оборванный JSON, повторяющиеся ключи и
нечисловые/бесконечные JSON numbers отвергаются. Лимит ответа — прежние 100000 символов.
Только отсутствующий `boxes` у final получает `[]`; явные null/строки/объекты вместо
списка остаются ошибкой. Даты, uncertainty, citations и координаты не достраиваются.

Исходный текст сохраняется в `calls/*-qwen.json` и `messages.json`. Новый
`reply-NNN.json` содержит SHA исходного call, parsed object, перечень косметических
нормализаций и ошибку валидации, включая отклонённые ответы. `final_raw.json` хранит
разобранный объект принятого final; точный исходный текст всегда остаётся в call.

Public `response_contract` содержит scaffold полей, все показанные photo dates/IDs
и требуемые endpoints; он не выбирает правильный ответ. Для earliest требуется
каноническая дата выбранного источника: `2013/2013/year`, без автоматического
расширения в дни года; архивные month/day/interval сохраняются точно. `uncertain`
обязателен: для earliest это определённость датированного свидетельства, не onset.
Для change/no_change precision всегда `interval`; для change `uncertain=true`
означает неизвестный момент возникновения внутри интервала. Прежняя допустимость
явного boolean для no_change сохранена. Retry перечисляет отсутствующие поля и
конкретные expected/received из публичного протокола. Число попыток не изменено.

Размер каждого показанного RGB указан как `[height,width]`; bbox — абсолютные
пиксели в заявленной системе координат, не доли 0..1 и не шкала 0..1000.
Дробные значения не масштабируются автоматически. Положительная дробная рамка
может быть геометрически допустима; это не подтверждает точность локализации.
Проверки владения координатами, citations и common support сохранены.

### Проверка ресурсов живого worker

`ModelPool` хранит собственный неперсистентный verifier. Первое использование
полностью читает SHA; повторный warm call может использовать этот digest только
при совпадении resolved path, device/inode, size, mtime_ns и ctime_ns. Новая pool
или PID требуют нового чтения. Замена файла, symlink target или метаданных вызывает
перепроверку; изменение во время хеширования завершает вызов ошибкой без approval.
Проверяются ресурсы перед повторным использованием worker и после его ответа,
включая впервые появившиеся в provenance лениво загруженные веса.

Полное хеширование сохранённых response-cache artifacts/resources и resume
сохранено. Изображения и другие model-visible inputs продолжают хешироваться
каждый вызов. Ресурсы configured checkpoint в cache key используют тот же verifier.
Модель, окружение, GPU scheduling и бюджеты не менялись.

В `calls/*/response.usage.resource_validation` (для WWW: `calls/*-qwen.json` →
`response.usage.resource_validation`), а также в `workers/pool.jsonl` записываются
`seconds`, `bytes_hashed`, `files_hashed`, `stat_cache_hits`. Это отдельная стоимость
проверки ресурсов **в родительском процессе**, включая cache checks; worker startup
и его собственные начальные хеши в неё не входят. Она уже включена в общую
elapsed_seconds и не прибавляется к ней повторно. Остальная разница outer/worker
времени не объявляется временем хеширования. Ускорение GPU пока не измерено.

earliest_damage / possible_change / stable_control / uncertain_control.
Рецензент вправе установить другое assessment. Никакого approval при экспорте нет.

Порядок детерминирован: round-robin по физическим зданиям и семействам, максимум
12 вопросов на физическое здание, затем число дат/временной охват и фиксированный
seed. Для одинакового anchor SHA/view/интервала подавляются кропы с пересечением
больше 50% площади меньшего кропа, в том числе вложенные и между разными задачами.
Для двух earliest-вопросов сравнивается начальная дата. Раздельные временные
эпизоды сохраняются. Это предварительное устранение дублей; совпадение событий
между разными anchors/views требует ручной проверки physical event_id.

`summary.json` содержит requested/selected/shortfall, target_shortfalls,
physical_buildings, excluded и eligibility_reasons; полный список исключённых
ID находится в `batch/selection.private.json`. Недобор не заполняется дублями,
непроверенными TEST-зданиями или изменением лимитов. Для 100 случаев при cap=12
нужно минимум девять подходящих физических зданий; реальная доступность
каждого семейства может потребовать большего числа. VAL остаётся development;
unknown exposure не считается независимой evaluation.

### Identity и история экспозиции

`identity-review.json` первоначально содержит две **pending** гипотезы:
Voskova_10/Voskova_12 и baskov_32/baskov_34. Такие участники исключаются из новой
выборки до review; сохранённые пилотные решения остаются доступными. Для каждой
группы человек выбирает `same_building` или `distinct`, указывает reviewer,
rationale и `sources:[{path,sha256}]` реальных проверенных материалов.
`physical_building_id` — один из исходных IDs; исходные IDs не переписываются.
Перекрывающиеся группы и изменённые source bytes отвергаются.

Редактируйте **отдельную копию** mapping и затем создайте новый пакет с
`--identity-map /absolute/path/to/reviewed-identity.json`. Не изменяйте mapping
в уже сохранённом run: его path/hash связан с inventory, selection и review.
Для отдельных команд используйте тот же mapping в `www inventory`,
`www review-page`, `www plan` и `www run`; batch наследует inventory, score —
замороженный execution contract. Для reviewed archival earliest, требующего
алиаса, `earliest_archive.identity_source` явно связывает те же path/sha256.
Несовпадение inventory/plan/reference/run/score отклоняется.

Объединение разрешает только проверенную физическую identity. Разные известные
view_id по-прежнему несовместимы; существующее правило неизвестного архивного
view_id остаётся прежним. Архивные source IDs и индекс не меняются. История split
сохраняется в original_split/physical_group_splits; конфликт train/val/test внутри
физического здания блокирует включение, а не исправляется переносом строк.
Известная экспозиция любого reviewed alias переводит всю группу в development,
включая алиас без tracks в текущем histories. Исходный exposure audit и исходный
cohort сохраняются. Evaluation требует полного аудита всех членов группы.
Публичные манифесты прежних экспериментов можно передать повторяемым
`--exposed-questions`; модельные ответы для этого не читаются.

### Страница review и отдельные архивные рамки

`index.html` связывает новые вопросы, исходные человеческие решения и inventory.
`review/review.html` показывает вопрос, датированные локальные RGB, архивные
изображения/сохранённые PDF, ссылки источников, даты съёмки/публикации/доступности,
date_source, lineage, SHA и eligibility. Потенциальные источники предложенного
алиаса могут показываться для private review с явным статусом eligibility=false;
это не разрешение подавать их модели. Само соответствие архивного снимка области
остаётся unreviewed. Архивные картинки загружаются при раскрытии раздела.

Вопрос, структурный ответ и event-box proposals редактируются прежним способом.
Все решения требуют явного выбора; server-side `qa review` остаётся обязательным.
Кнопка архивного correspondence сохраняет отдельный файл
`2026-11-16-www-archive-correspondence.private.json`, `temporal_gold:false`.
Рамки относятся к указанному архивному RGB/SHA в observation_native pixels;
уменьшение preview влияет только на рисование, не на экспорт координат.
Эти черновики не входят в label.events, не передаются модели и не превращаются
в GT временного изменения. Общая поддержка не оценивает точность локализации.

Старый handoff копируется без изменения байтов и показывается отдельным разделом.
Требуется точный исходный candidate SHA; подмена кандидатов новым генератором
не переносит решения автоматически. Для другой candidate revision сохраните
старую страницу отдельно и выполните явный review новой связки. Параметр
`--previous` сохраняет прежнюю review revision; старые labels на диске не меняются.

### Дополнение метрик

Существующие structured endpoints, earliest precision/date/observation проверки,
localization IoU/K, fixed-support pixel diagnostics, стоимость и blind factual
review сохранены. Добавлен `change_stability.macro_f1`: среднее F1 двух фиксированных
классов change/no_change только по reviewed confirmed_change/confirmed_stability.
Ошибка, missing или abstention остаются в этом наборе и дают FN истинного класса;
при нулевом знаменателе F1 класса равен 0. При отсутствии обоих классов метрика
unavailable. Insufficient-evidence references не становятся stability.

Парные B−A, C−B и C−A 95% percentile confidence intervals вычисляются для
building-macro structured accuracy и change/stability macro-F1. Bootstrap:
**2000 повторов, seed=20261116**, пересэмплируются физические здания целиком с
возвращением и со всеми их вопросами; A/B/C используют одни frozen references
и одинаковые выбранные кластеры. Для binary F1 используются здания с binary
references; здания только с earliest/insufficient cases не создают фиктивные
нулевые F1. Менее двух подходящих зданий — interval=null с причиной. Числа зданий
и параметры записываются в отчёт, новый plan фиксирует их до inference.
Для legacy plan явно отмечено применение fixed code defaults. Это не тест
значимости и не оценка обобщения при нескольких независимых зданиях.

Фактическая поддержка по-прежнему требует blind human review:
`blind-review.private.csv` + gallery, отдельный `blind-key.private.json`.
Reference answers не меняются для улучшения метрик. Ранний unscored pilot не
становится scored задним числом; для новой оценки нужен новый frozen plan/run.
