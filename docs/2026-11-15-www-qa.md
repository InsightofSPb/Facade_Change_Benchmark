# WWW: supplied-region QA, 2026-11-15

Это реализация протокола, не результат сравнения качества. Единица исследования —
здание. Заданный регион не означает автоматическое обнаружение изменений на всём
фасаде. Реальные модели в Cloud не запускались.

## Первый этап: публичный runner

`python -m facade_change.agentic www run` читает **только указанный** публичный
`questions.json`, его RGB/support и указанный публичный индекс/корпус. Приватные
соседние ответы, аннотации и превью не открываются. Три условия:

- `photos_only`: одинаковая исходная локальная история;
- `fixed_retrieval`: однократный поиск по вопросу, зданию, обязательным датам и
  последнему локальному изображению;
- `bounded_agentic_retrieval`: до двух поисков, выбор запроса/локального изображения
  моделью; разрешён финальный ответ без поиска.

Одинаковы Qwen, предобработка, русский текст задачи, схема ответа, исходные фото,
фильтры и максимальные бюджеты B/C. Jina вызывается существующим `ModelPool`,
последовательное управление GPU и технический OOM retry остаются прежними.
Поиск — max cosine между текстовыми/визуальными представлениями реального
Jina-CLIP-v2, затем evidence_id при равенстве. Лексического fallback нет.

Начальные **предварительные**, ещё не проверенные на WSL GPU ограничения: шесть
локальных фото, четыре архивные записи, два архивных фото, до четырёх bbox.
У B один поиск top-4; у C до двух top-2, ранее показанные записи исключаются.
Это вместимость шестидатных пилотных вопросов плюс два архивных фото при max_images=8,
а не утверждение о достаточности VRAM. Ограничения Qwen токенов/изображений/времени
берутся из существующей конфигурации. `--protocol` может явно уменьшить лимиты;
обязательные даты не отбрасываются. Изменение замороженного протокола требует
нового запуска. Перед полным прогоном нужно измерить 2–3 случая на конфигурации 16k.

Фиксируются фактические расходы **всех** Jina/Qwen вызовов, повторные изображения,
cache hits и технические retry. Суммарный лимит генеративного контекста относится
к Qwen; Jina ограничен числом поисков и собственным max_text_tokens. Равные
максимумы не означают равное потребление. Кэш не расходует новые токены, но
логические лимиты QA учитывают source_usage, поэтому кэш не даёт лишних действий.

Ответ зависит от task: earliest_evidence называет наблюдение/дату присутствия,
temporal_change — интервал сравнения, archival_qa — ответ по источникам. Это
не дата возникновения повреждения. Цитаты проверяются по реально показанным ID;
проверка ID не оценивает смысловую поддержку текста. Bbox необязательны, но
заданные координаты проверяются строго. Native-рамка архива не превращается в
локальную рамку; документ не предоставляет пространственную локализацию.

Архив импортируется `www archive-import --package ... --out ...` по общему
контракту `www_archival_evidence_package` v1. Даты, права, источники, page/parent,
реальные SHA и размер файлов проверяются; ничего не скачивается. Индекс строится
`www archive-index --corpus ... --config ... --out ...`. Неопределённые identity
сохраняются в корпусе, но не служат подтверждением: начальная политика допускает
только verified, совпадающее здание и совместимый вид. Все исключения записываются.
Даты доступности не подменяются датами съёмки. Cutoff вопросов/корпуса должен
совпадать; поздний сбор требует новой согласованной версии, не backdating.

Все outputs создаются в новом каталоге: contract.json, run.json, events.jsonl,
results.json, predictions-<condition>.json, gallery.html, per-question preparation,
messages, exposure, полные запросы/ответы, costs и bbox overlays с меткой MODEL.
`--resume-from` переносит только валидные completed/abstained результаты при
идентичных вопросах/корпусе/конфигурации/исходниках/промпте и неизменных ресурсах.
Ошибки выполняются заново; старый запуск не меняется. JSON/worker ошибки — error,
не abstained. Оборванный JSON не исправляется. `--quiet` отключает прогресс;
итоговый JSON остаётся в stdout.

Без архива нужен явный `--allow-empty-archive`: такой результат помечается
`plumbing_no_archive` и не является сравнением retrieval. Любой inference без
отдельной approved offline оценки остаётся unscored.

## Второй этап: inventory, review и offline endpoints

`www inventory` читает все canonical tracks и splits, проверяет оригинальные
full-frame SHA, сохраняет ссылки на полные кадры и датированные thumbnail-превью.
Отсутствующие оригиналы, неопределённая identity, недостаточная история,
повторение SHA между зданиями/splits и непроверенное прежнее использование
явно отражаются в исключениях. Входные снимки и alignment не пересоздаются.
`question_counts_complete=false` означает, что supplied candidates не покрывали
этот split. Для полных proposal counts сначала выполните `qa generate` по всем
splits на **той же** версии histories и annotation index.

Адрес берётся только из явно сохранённого поля address исходного manifest либо
из `--addresses`: `{"buildings":[{"building_id":"...","address":"...",
"aliases":[],"source":{"path":"...","sha256":"..."}}]}`. Неизвестные адреса
сохраняются как unknown, без транслитерации ID в доказанный адрес.

VAL — development. Для TEST по умолчанию статус `earlier_exposure_not_audited`.
TRAIN не становится независимой evaluation-когортой. `--exposure-audit` принимает
`kind:www_exposure_audit`, `protocol_sha256`, `protocol_source:{path,sha256}` и
`buildings:[{building_id,cohort,prior_exposure,reviewer,audit_sources,reason}]`.
Evaluation допустима лишь для TEST, `cohort:evaluation`, `prior_exposure:none_found`,
с reviewer и непустыми `audit_sources:[{path,sha256}]`; файлы/хеши проверяются.
Это фиксирует проведённый человеком аудит предыдущих обучений/демо/отладок,
а не автоматически доказывает отсутствие любого прежнего использования.
Известные использованные здания можно явно отнести к development.

`www batch` выбирает до заданного размера round-robin по building/family:
сначала число дат и временной охват, затем SHA256(seed,question_id).
По умолчанию не более 12 вопросов на здание, anchor-box IoU между выбранными
регионами одного вида не больше 0.5. Действительные размеры/исключения сохраняются.
Геометрическое ограничение не заменяет review физических event_id. Deterioration,
repair, stable и unassessable устанавливает рецензент; candidate families не GT.
100 вопросов / 15–20 зданий — цель сбора, не известное количество; шесть VAL
зданий не превращаются в большее число независимых объектов из-за новых кропов.

`www handoff` читает только два указанных private JSON внутри coordination ZIP,
сохраняет все исходные тексты и уточнение case 03. Получается 5 earliest, 8 visible
change, 3 no-substantial-change. **Approved=0, reviewed_boxes=0.** Без `--candidates`
возможна переносимая проверка handoff, но соответствие исходным owner-файлам
остаётся pending. С `--candidates` требуется точный SHA из handoff и совпадение
вопросов, RGB/geometry, дат и owners. Пакет не является публичным архивным корпусом.

`www review-page` создаёт приватные gallery.html/review.html и drafts.private.json.
Числа координат редактируются; отдельный checkbox подтверждает каждую рамку.
Изменение координат/ID снимает подтверждение. Export включает только явно
выбранные решения, сохраняет reviewer, rationale, expected_revision и вопрос.
При confirmed_change требуются подтверждённые event_id/bbox. Затем **существующий**
`qa review` повторно проверяет manifest/revision/координаты/маски. Никакого approval
при загрузке страницы нет. Текст handoff подставляется, повторно писать его не нужно.
Для следующей пачки исправлений укажите `--previous .../reviewed.json` и при создании
страницы, и при применении `qa review`.

В drafts различаются положительные факты исходной человеческой аннотации одного
снимка, автоматические temporal proposals и human-reviewed temporal labels.
Предложения bbox — до четырёх крупнейших компонент различия **известных** bitset
аннотаций на общей поддержке. Это подсказки для RGB review, не временные GT.
Ни XOR, ни bbox не превращаются в temporal-change маску.

`www public` экспортирует whitelist исходных полей без annotation/review/proposal
данных. Такой candidate smoke явно unscored. `--limit 3` создаёт отдельный
замороженный manifest: максимальное число дат в каждой task, затем заполнение
по исходному selection order. При равенстве сохраняется исходный порядок;
это позволяет проверить длинную историю из шести фото уже в pilot smoke. Runner
всегда исполняет весь переданный manifest. Полный и 16-case прогоны используют тот
же runner, без другой реализации. Новая дата `--knowledge-cutoff` создаёт новую
версию; старые кандидаты, текстовый handoff и даты наблюдений не меняются.

Для primary scoring сначала нужны `qa review` → `qa export`. Затем `www plan`
замораживает approved cohort, явный reviewed `archival_stratum:true/false`,
development/evaluation и полный контракт model/config/questions/corpus/prompt.
Plan должен предшествовать запуску; `www score` отвергает поздний plan и любые
несовпадающие версии. Ранние candidate smoke не становятся scored задним числом.
После изменения freeze потребуется новая согласованная версия кандидатов/review/
export/plan; нельзя заменить cutoff внутри уже одобренного manifest.

Primary endpoint — корректность структурных полей по задачам, с fixed denominators,
families, building macro и paired building differences B−A, C−B. Missing/errors
остаются в cohort; runtime errors не считаются abstention. Insufficient evidence
отличается от no_change. Earliest scoring сохраняет дату и точность; явно reviewed
`equivalent_observation_ids` допустимы только на той же дате. Для archival_qa
assessment `archival_fact` требует supporting IDs и непустой список
`acceptable_structured_answers:[{decision:"supported",observation_ids:[],date_interval:...}]`.
Допустимые интервалы/precision/uncertainty перечисляются рецензентом, не угадываются.
Такая структурная оценка не проверяет смысл свободного текста.

Localization использует `qa evaluate`: one-to-one matching физических event_id,
IoU 0.25/0.5, K=1/3/5/10, precision/recall и производный F1. Сохранён repair
9aa159c: temporal pixel score требует покрытия **всего фиксированного** reviewed
reference support. При отсутствии настоящих reviewed temporal masks pixel/area
результат остаётся unavailable. Есть отдельные development/evaluation и archival
localization strata; объединённая таблица также сохранена.

Known-support hit/recall вычисляется по reviewed `supporting_evidence_ids` архива,
а validity — по реально exposed IDs. Неизвестные альтернативные источники не
объявляются нерелевантными. `known_support_exhaustive=false` — обычный начальный
случай. `blind-review.private.csv` и gallery.html скрывают название условия;
blind-key.private.json хранится отдельно. Человек оценивает фактическую поддержку,
противоречия и релевантность изображения/источника. Галерея показывает именно
экспонированный текстовый excerpt, не скрытое продолжение. Reviewed bbox overlays
лежат отдельно в `reviewed-overlays.private/`, никогда не подаются модели.

`annotation-diagnostics.private.json` отдельно оценивает drafting signals против
reviewed labels: precision/recall possible-change proposals и соответствие самой
ранней положительной аннотации reviewed visible presence. Это не четвёртое
условие модели и не источник gold для primary endpoint. Bootstrap/значимость не
вычисляются. Отчёт указывает число независимых зданий; выводов об улучшении нет.
