# BCM-Net: точное нейронное кодирование пары, 2026-10-07

BCM-Net — авторская система из статьи Xiangrui Liu, Meng Wang, Shiqi Wang,
Sam Kwong, *Bilateral Context Modeling for Residual Coding in Lossless 3D
Medical Image Compression*, IEEE TIP, 2024,
[DOI 10.1109/TIP.2024.3378910](https://doi.org/10.1109/TIP.2024.3378910).
В оригинале видеокодек VTM создаёт приближённую реконструкцию последовательности
медицинских срезов, а BCM-Net точно кодирует остаток. Сумма декодированной базы
и декодированного остатка восстанавливает исходные значения. Lossy внутри базы
не означает потери в окончательном результате: обязательна проверка RGB uint8
после полного декодирования.

## Исходники и граница адаптации

- [Авторский BCM-Net](https://github.com/LiuXiangrui/BCM-Net), commit
  `6ba35a99228d03bd0831501d79c62715c06ded2e`.
- [Авторская папка весов](https://drive.google.com/drive/folders/1Ogi8ZKouMTsHS59nr_xdu1wQIEGhFbuB?usp=sharing).
  MRNet/Axial.pth — модель для 8-битных монохромных медицинских срезов,
  не обученная модель фасадов. Опубликованная папка не задаёт проверенный нами
  checksum: каждый используемый checkpoint получает SHA-256 в запуске.
- [VTM HHI](https://vcgit.hhi.fraunhofer.de/jvet/VVCSoftware_VTM), tag `VTM-15.0`,
  commit `2e935808159fefa3c85a599c3b79615cd9555429`.
  [ffvvc mirror](https://github.com/ffvvc/VVCSoftware_VTM) имеет тот же annotated
  tag `a5df53d0b9ee69fed8c2e4dc9d04a3cb0b247d28` и peeled commit;
  это зеркало, не независимая версия алгоритма.

В Git нашего проекта сохраняется только манифест
`third_party/bcm_net_provenance.json`. Setup клонирует авторские деревья в
игнорируемые `third_party/bcm_net` и `third_party/vtm`. Все 14 файлов BCM-Net
проверяются по SHA-256 оригинальных байтов; также проверяются VTM commit,
конфигурации и ключевые build/format-файлы. Существующие checkout не сбрасываются,
изменённые исходники приводят к отказу. В авторском BCM-Net нет файла лицензии;
его код не перепубликуется в Git этого проекта.

Оригинальная архитектура: `channels_F=64`, `channels_M=120`, `channels_X=1`,
`K=10`, `R=8`, `bit_depth=8`. Наше применение к двум наблюдениям фасада —
адаптация предметной области: R, G, B проходят независимо как три исходные
монохромные последовательности. RGB не переводится в YUV, не меняется его
разрешение и не подменяется семантическими масками. Это не воспроизведение
медицинского benchmark из статьи и не новая авторская RGB-видеомодель.

Авторский остаточный GOP равен 8. Для двух кадров его функция `get_ref_idx`
даёт второму кадру опору 0 и убирает отсутствующую будущую опору;
полная двунаправленная схема длинного GOP здесь не оценивается.

## VTM и стоимость

Используются оригинальные
`cfg/encoder_randomaccess_vtm_gop16.cfg` и `cfg/per-class/classSCC.cfg`.
Последний включает IBC, HashME, BDPCM и PLT. Вход монохромный (`400`),
8-битный; выход базы также 8-битный. Обычная сборка VTM уже поддерживает
8/10 бит: изменение `JVET_R0351_HIGH_BIT_DEPTH_ENABLED` для 16 бит не требуется.
GCC 13 требует явного подключения стандартного `<cstdint>`: setup задаёт
`-DCMAKE_CXX_FLAGS='-include cstdint -Wno-error=deprecated-declarations -Wno-error=address'`,
сохраняя все байты исходников VTM. Второй флаг оставляет предупреждение о
старом `std::unary_function` предупреждением при авторском `-Werror`.
При GCC ≥12 добавляется `-Wno-error=array-compare` для предупреждения об
авторском сравнении массивов в IntraSearch.h; `address` относится к проверке
адреса массива `enabledFlag` в EncAdaptiveLoopFilter.cpp. Другие compiler errors
не подавляются.

Оба кадра каждого канала кодируются настоящим VTM; A не используется вместо
декодированной lossy-базы. Авторский RA_gop16 включает temporal filtering
с будущей опорой; для причинной оценки B|A adapter явно задаёт
`--TemporalFilterFutureReference=0`. Исходные конфигурации не редактируются.
База и correction A должны быть инвариантны при изменении B: это отдельный
проверяемый control. Второй access unit имеет RA B-slice с прошлой опорой;
его нельзя называть настоящим P-frame.

Adapter также задаёт `--AccessUnitDelimiter=1`:
VTM-15.0 действительно поддерживает эту опцию, AUD имеет NAL type 20.
Стоимость B включает весь его VTM access unit, start codes и заголовки,
четыре авторских residual streams, 16 байт их длин и 4 байта полной длины
базового stream на канал. Последние зависят от B и поэтому также оплачиваются B.
Общие 6 байт N/Width/Height каждого авторского контейнера и остальные байты
A относятся к A. `charged_bytes`, `reference_i_bytes` и `stream_bytes`
суммируются по трём RGB-каналам; `charged_bytes + reference_i_bytes`
равно полному `stream_bytes`. Каждый контейнер действительно декодируется.

В режиме `theoretical` измеряется другой показатель: реальные байты VTM B,
60 байт длин base/residual streams и их NLL. Это не размер полного закодированного
контейнера и не подтверждение побайтного roundtrip. Для проверки сохранности
использовать `bitstream`.

Основная единица — тайл 32×32 RGB со stride 16, с прежней геометрической
поддержкой и нейтральным padding. Сумма независимых перекрывающихся тайлов
не является скоростью компрессии целого изображения. Изменения вне поддержки
не входят в метод; выход там NaN. Lossless-гарантия относится к поданным байтам
после выравнивания и маскирования, не к обратимости предыдущей интерполяции.

## Подготовка на компьютере владельца

Setup создаёт отдельную среду `facade-bcm`; `scd_bench`, `facade-codecs` и `lposs`
не изменяются. Используется подмножество зависимостей оригинального Dockerfile,
которое нужно сети и entropy coder: Python 3.10, torch 1.13.1+cu117,
einops 0.6.1, torchac 0.9.3, tqdm 4.65.0. NumPy закреплён на 1.26.4 для
совместимости с torch 1.x. Медицинские загрузчики, torchvision и torchaudio
не нужны адаптеру. Pillow 11.3.0 — отдельная зависимость фасадного adapter/CLI,
читающего PNG; это не зависимость оригинальной сети. Импорт torchac компилирует
его небольшой C++ backend;
нужны g++ и ninja. `MAX_JOBS=2` ограничивает компиляцию torchac,
`BCM_BUILD_JOBS=2` — сборку VTM; оба значения можно задать явно.

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
bash scripts/setup_bcm_codec.sh
conda activate facade-bcm
python -s -c 'import torch, torchac, einops; print(torch.__version__, torch.version.cuda)'
```

Если HHI недоступен, зеркало выбирается явно и проходит ту же проверку commit:

```bash
BCM_VTM_REPOSITORY=https://github.com/ffvvc/VVCSoftware_VTM.git \
  bash scripts/setup_bcm_codec.sh
```

Для проверки одних исходников без установки пакетов и компиляции:

```bash
bash scripts/setup_bcm_codec.sh --sources-only
```

После сборки: `third_party/vtm/bin/EncoderAppStatic` и
`third_party/vtm/bin/DecoderAppStatic`. Передавать adapter абсолютные пути
к этим бинарникам и обеим конфигурациям. `--skip-vtm-build` оставляет сборку
для отдельного вызова CMake.

Веса автоматически не скачиваются. При необходимости pretrained smoke
скачать их вручную по авторской ссылке. Необязательный gdown выполняется
только явным вызовом, внутри отдельной среды и в игнорируемую папку:

```bash
python -s -m pip install gdown==5.2.0
python -s -m gdown --folder \
  'https://drive.google.com/drive/folders/1Ogi8ZKouMTsHS59nr_xdu1wQIEGhFbuB?usp=sharing' \
  -O weights/bcm-author
```

Авторский README предлагает исправить torch по
[PR #99980](https://github.com/pytorch/pytorch/pull/99980/commits/222b25601ba54ebbe17a8597d37bad56e7b0b5ec).
Setup не редактирует ни torch, ни авторские файлы. Совместимость вызовов сети
должна быть проверена отдельно adapter-тестом; успешный импорт не равен
успешному encode/decode и не подтверждает CUDA на RTX 4060 Ti.

## Обучение и проверка

Для исследовательского запуска требуется обучение неизменённой архитектуры
на фасадных H0 из TRAIN; VAL служит для выбора checkpoint/настроек,
TEST не читается при обучении. Отдельно сохраняются реальные реконструкции
VTM и их хеши: исходный A не является заменой базы для обучения.
Запуск должен сохранять конфигурацию, source/binary/checkpoint SHA-256,
sampling manifest, историю, provenance базы и конечный status.

До полного benchmark обязательны A=A, локальная правка и переходы 0↔255,
фактический bitstream и полное декодирование с побайтным сравнением RGB.
Фасадная точность, расход 16 GB VRAM и время полного benchmark ещё требуют
отдельного измерения. Настройки QP определяют размер базы и коррекции;
они не разрешают ненулевую ошибку окончательной реконструкции.

Обучение запускается из корня проекта в `facade-bcm`.
`DATASET` — каталог подготовленного dataset-run, `REUSE_RUN` — уже завершённое
сравнение десяти кропов/60 случаев. `BCM_RUN`, `CODEC_RUN`, `CODEC_CONFIG` и
`CHECK_RUN` должны быть новыми путями вне прежних неизменяемых запусков.
`MRNET_CHECKPOINT` — существующий локальный `MRNet/Axial.pth`; если нужно
обучение с новой инициализацией, удалить аргумент `--init-checkpoint` явно.

```bash
python -s -m facade_change bcm-train \
  --dataset-run "$DATASET" --out "$BCM_RUN" \
  --source-root third_party/bcm_net \
  --vtm-encoder third_party/vtm/bin/EncoderAppStatic \
  --vtm-decoder third_party/vtm/bin/DecoderAppStatic \
  --vtm-config third_party/vtm/cfg/encoder_randomaccess_vtm_gop16.cfg \
  --vtm-scc-config third_party/vtm/cfg/per-class/classSCC.cfg \
  --init-checkpoint "$MRNET_CHECKPOINT" \
  --device cuda:0 --epochs 3 --max-train-patches 160 --max-val-patches 16 \
  --batch-size 1 --tile-size 32 --lr 0.0001 --seed 42

BCM_WORKER_PYTHON="$(python -s -c 'import sys; print(sys.executable)')"
conda activate scd_bench

python -s scripts/configure_codecs.py \
  --reuse-run "$REUSE_RUN" --out "$CODEC_RUN" --config-out "$CODEC_CONFIG" \
  --worker-python "$BCM_WORKER_PYTHON" \
  --bcm-training-run "$BCM_RUN" --bcm-source-root third_party/bcm_net \
  --cost-mode bitstream --neural-device cuda:0

python -s -m facade_change methods-check \
  --config "$CODEC_CONFIG" --out "$CHECK_RUN" \
  --methods bcm_net_rgb --bitstream-check
```

Helper использует VTM paths из завершённого обучения; при переносе дерева
есть явные `--bcm-vtm-encoder`, `--bcm-vtm-decoder`, `--bcm-vtm-config` и
`--bcm-vtm-scc-config`. Сохраняется та же selection прежнего сравнения;
RSCD пересчитывается с исправленными настройками, ранее пригодные карты
других методов используются повторно после проверки хешей.
Сравнение запускается в прежней основной среде `scd_bench`; BCM работает
отдельным процессом через сохранённый Python из `facade-bcm`. В основной среде
сохраняются её существующие зависимости других методов. JPEG-LS/H.264 в
отдельном worker используют системный FFmpeg.

Только после успешных controls запускать продолжение сравнения:

```bash
python -s -m facade_change h0h1-benchmark --config "$CODEC_CONFIG"
```

Не использовать медицинские TestMRNet.py как команды нашего TRAIN/VAL/TEST
pipeline. Приведённые команды — воспроизводимые инструкции для владельца;
полное обучение и benchmark в Cloud не запускались.

## Выполненные программные проверки

На CPU с torch 2.6.0, einops 0.6.1 и torchac 0.9.3 выполнены:

- backward через оригинальную сеть для нового дифференцируемого NLL;
- полный VTM-15.0 + исходный BCM entropy coder, упаковка в авторские containers,
  декодирование identity, локальной правки и переходов 255→0 и 0→255;
- неизменность байтов reference A при трёх разных B для одного A;
- один epoch на одном синтетическом TRAIN-тайле и одном VAL-тайле, сохранение
  лучшего checkpoint и проверка хешей;
- загрузка этого checkpoint в отдельный benchmark worker и фактический
  `methods-check --bitstream-check` для всех четырёх controls.

Все эти roundtrip-проверки восстановили поданные RGB-байты точно. Это проверка
реализации, а не оценка качества детекции или достаточности обучения.
Авторские медицинские веса не скачивались; загрузчик повторяет выбор
`checkpoint['network']` или plain state_dict из авторского TestMRNet.py.
Среда torch 1.13.1+cu117, GPU владельца и полное фасадное обучение ещё
требуют домашней проверки.

Настоящий VTM выполняет три CPU-кодирования для каждого RGB-тайла.
В этом маленьком Cloud-прогоне подготовка базы занимала около 3 секунд на тайл;
это не оценка скорости домашнего GPU. Стартовать с короткого обучения
`--epochs 1 --max-train-patches 8 --max-val-patches 4` и четырёх controls.
Полное сравнение перекрывающихся тайлов существенно дольше preflight.
Даже theoretical mode сохраняет настоящий VTM и его измеренные base bits.

В Cloud проверены синтаксис setup, реальное `--sources-only` и CLI help.
Оба бинарника оригинального VTM успешно собраны с `-j2` в ограниченном
300-секундном вызове после перечисленных compiler-флагов; `--help`
подтверждает Version 15.0, GCC 13.3. Все проверяемые байты источников после
сборки совпадают с pin. Это подтверждает сборку; Python 3.10/torch 1.13.1+cu117
и CUDA владельца отдельно требуют выполнения roundtrip controls.
