# Рамки мышью в WWW review

Локальные фото в `www review-page` поддерживают протягивание рамки мышью.
Координаты вычисляются по реальному размеру canvas на экране и сохраняются в
`region_crop_pixels`, с указанием `region_id`. Размер исходной решётки показан
над изображениями. Масштаб браузера не меняет систему координат экспортируемой
рамки. Архивные native correspondence boxes остаются отдельным приватным черновиком.

Протяните рамку на любом локальном фото или нажмите «Добавить рамку мышью»,
затем протяните её. Для существующей рамки есть «Перерисовать мышью» и
«Удалить рамку». Рамка отображается на всех локальных фото в общей решётке.
Проверьте сопоставимость участка по датам: сама общая решётка не доказывает
видимость или правильность совмещения. После проверки введите физический
`event_id` и отметьте «Координаты проверены вручную». Новый рисунок и правки
чисел сбрасывают подтверждение; выбор `approved` и включение в экспорт отдельны.
Клик без площади и отменённое перетаскивание не создают событие. Несовпадение
размера RGB с решёткой запрещает рисование, без скрытого изменения масштаба.

Верхнее поле теперь явно подписано «Вопрос для модели». Описание изменений
нужно писать в `reference_answer` приватного структурного ответа ниже.
Приватные заметки подписаны отдельно. Исходные вопросы, метки, approvals,
отбор, scoring, inference и provenance контракт экспортируемых решений не менялись.

## Обновление уже созданной страницы в WSL

`git pull` обновляет шаблон, но ранее созданный `review.html` остаётся прежним.
Сначала сохраните введённый текст отдельно: несохранённые правки открытой
страницы не переносятся в новую автоматически. У `candidate` экспорт сохраняет
вопрос и заметки, но не структурный JSON ответа. Автосохранения в этом редакторе нет.
Если решения уже применены через `qa review`, при пересборке добавьте
`--previous` с точным `reviewed.json`; не переносите их на другой candidates manifest.

Команда ниже использует сохранённый отбор и identity mapping домашнего пакета
`2026-11-16-www-home-v41-001`. Она создаёт новую страницу без повторного отбора
и без GPU. При другом расположении пакета замените соответствующие пути.
Каталог `review-mouse-002` должен отсутствовать.

```bash
cd /home/sasha/Facade_Change_Benchmark &&
git pull --ff-only &&
set -o pipefail &&
/home/sasha/miniconda3/envs/change-agentic-rag/bin/python -u -m facade_change.agentic www review-page \
  --candidates /home/sasha/Facade_Change_Benchmark/runs/2026-11-15-www-candidates-all-001/candidates.json \
  --selection /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-home-v41-001/review/batch/selection.private.json \
  --identity-map /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-home-v41-001/review/identity-review.json \
  --archive-corpus /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-home-v41-001/archive/corpus.json \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-home-v41-001/review-mouse-002 \
  2>&1 | tee /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-home-v41-001/review-mouse-002.console.log
```

Откройте `runs/2026-11-16-www-home-v41-001/review-mouse-002/review.html`.
Проверка границ и обязательное ручное подтверждение остаются в экспорте.

## Проверки

`node tests/test_2026_11_16_www_review_ui.js` проверяет изменение масштаба,
рисование в обратном направлении, границы, отмену, перерисовку, удаление,
отказ при пустых координатах и необходимость отдельного подтверждения.
Прежние проверки разделения archive correspondence и событий, а также
явной области earliest-вопроса сохранены.

Проверены также пять CPU-тестов `test_2026_11_15_www_curation.py` и сквозной
синтетический путь: генерация настоящего review HTML → DOM pointer events →
экспорт решения → `qa review` → `qa export`. Приватный ответ отсутствует в
публичном questions JSON. Chromium в этой Cloud-среде не запустился из-за
запрета системного `socket()`; DOM-проверка не заменяет проверку мышью в WSL-браузере.
GPU и реальные человеческие approvals не запускались.
