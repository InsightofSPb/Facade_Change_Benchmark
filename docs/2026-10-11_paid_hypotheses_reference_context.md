# Первые проверки оплаченных H0/H1 и контекста опоры

## Подготовка историй без занятия GPU

Следующие команды готовят два отдельных поднабора. Они не обучают модель памяти
и сами по себе не дают сравнения качества методов. Используйте актуальный запуск
подготовки данных с уточнёнными метаданными, сохраняя прежние назначения split:

```bash
FC_DATASET_RUN="/absolute/path/to/current-dataset-preparation"
python -u -s -m facade_change prepare-history \
  --dataset "$FC_DATASET_RUN" \
  --splits train val --crops-per-building 1 --final-event mixed \
  --out "runs/$(date -u +%Y%m%dT%H%M%S%N)-synthetic-histories"
```

Для каждого выбранного кропа создаются две пятикадровые истории: без добавленных
изменений и с событиями. «Чистая» здесь означает отсутствие новых процедурных
событий; исходный фасад не объявляется здоровым. На кадре 3 появляется трещина,
на кадре 4 она сохраняется без нового события, на кадре 5 — рост, частичное
восстановление или процедурное отслоение. Тип последнего события можно задать
через `--final-event growth|partial_repair|delamination`; `mixed` распределяет
эти варианты детерминированно между выбранными кропами.

Условия наблюдения генерируются независимо от событий и совпадают между двумя
ветвями одного кропа. Размытия нет; геометрия пока тождественная, без синтеза
ракурса. Частичное восстановление — идеальное возвращение исходного участка,
отслоение — текстурированный процедурный аналог, а не физическая модель дефекта.
Фиксированные моменты событий служат контролируемой проверке сохранения состояния;
такой набор не предназначен для обучения предсказателя, использующего номер кадра.

Отдельно записываются текущее повреждение, когда-либо повреждённая область,
новое изменение, новое повреждение, восстановленная область и видимость.
Ремонт является событием изменения, но не новым повреждением. Закрытый пиксель
на любом из двух соседних кадров получает ignore=255 в оценочной маске;
скрытая синтетическая истина сохраняется отдельно. Для одинаковых целевых кадров
есть списки контекста: самый ранний кадр, предыдущий и вся прошлая история,
без доступа к будущему. Это позволяет дальше сравнить способы использования памяти.

Выбираются только подтверждённые TRAIN/VAL-фасады; TEST и неизвестные адреса
не используются. COCO-маски не участвуют в генерации. Результат:
`manifest.json`, `selection.json`, `config.json`, `split.json`, `summary.json`,
`run.json`, `gallery.html` и PNG в `bases/`. Исходные RGB и подготовленный датасет
не изменяются.

### Кандидаты реальных переходов классов

Сначала получите выравнивание текущего VAL на CPU. Прежние alignment-запуски
можно использовать только при совпадении идентичностей, split и метаданных пар;
сменившаяся нумерация COCO допустима, изменившаяся принадлежность split — нет.

```bash
FC_ALIGNMENT_RUN="runs/$(date -u +%Y%m%dT%H%M%S%N)-val-sift"
python -u -s -m facade_change batch \
  --manifest "$FC_DATASET_RUN/prepared/manifest.json" \
  --methods sift --device cpu --split val --limit 0 \
  --out "$FC_ALIGNMENT_RUN"
```

Затем извлеките кандидаты из прошедших геометрические проверки пар. Если отдельные
пары не выровнялись, они сохранятся в отчёте отклонений; успешные пары завершённого
batch остаются пригодны для просмотра.

```bash
python -u -s -m facade_change mine-transitions \
  --dataset "$FC_DATASET_RUN" --alignment-run "$FC_ALIGNMENT_RUN" \
  --splits val --window-sizes 50 100 \
  --out "runs/$(date -u +%Y%m%dT%H%M%S%N)-real-transition-review"
```

По умолчанию используются все категории текущего COCO и три типа кандидатов:

- `replacement`: в одном выровненном пикселе исчезает A и появляется B, для всех
  направленных пар разных классов; например WATER_STAIN → REPAIRS или REPAIRS → SPALLING;
- `appearance`: класс появляется, даже если остальные классы в пикселе сохраняются;
- `disappearance`: класс исчезает, даже если новый класс не появился.

Пересекающиеся классы сохраняются как multilabel. Например, WATER_STAIN может
добавиться поверх сохраняющегося ORNAMENT_INTACT без замены орнамента. Обе даты
должны иметь непрозрачную, геометрически сопоставимую и размеченную поддержку.
Неразмеченная стена на раннем снимке не становится подтверждённым отрицательным
примером WATER_STAIN. Crowd-пиксели исключаются; маски переносятся nearest-neighbor,
RGB — отдельно готовой геометрией. Появление класса в аннотации не доказывает
физическое появление объекта и не оценивает направление деградации автоматически.

Защита от мелких расхождений разметки:

1. `--boundary-tolerance-pixels 2`: появившийся пиксель класса игнорируется,
   если тот же класс уже был в радиусе двух пикселей на ранней маске; исчезновение
   проверяется симметрично по поздней маске. Радиус задаётся на исходной решётке
   опорного снимка, с квадратной окрестностью. Это подавляет небольшое смещение
   контура. Новая тонкая трещина, отсутствовавшая рядом раньше, не эродируется.
2. `--min-component-pixels 25`: минимальная площадь связного компонента и его
   части внутри экспортируемого окна. Разрозненные точки не суммируются в событие.
3. `--min-transition-fraction 0.02`: не менее 2% полной площади окна принадлежит
   этому компоненту после фильтрации: 50 пикселей для 50×50 и 200 для 100×100.
4. `--min-support-fraction 0.5`: минимум половина окна имеет общую допустимую
   размеченную поддержку.

Сохраняются исходная и отфильтрованная маски кандидата, число игнорированных
пограничных пикселей и фактическая доля изменения. Кандидат не означает, что всё
окно изменилось. Порог площади отсекает также реальные очень маленькие события;
это явный компромисс для списка ручного просмотра, а не новое правило benchmark.
Допуск двух пикселей не устраняет крупные локальные ошибки alignment.

Сохраняется до 20 окон на пару, с чередованием типов событий и классов, чтобы
крупный класс не занял весь список. Число подходящих и неэкспортированных окон
фиксируется отдельно. Один физический участок может дать замену, появление,
исчезновение и несколько размеров окна; число кандидатов не равно числу событий.
Все параметры записываются в конфигурации. `--event-types` ограничивает виды событий.
Для воспроизведения старого отбора двух замен используйте
`--no-all-class-pairs --event-types replacement --boundary-tolerance-pixels 0 --min-component-pixels 16`.

При изменении правил майнинга повторять подготовку датасета и alignment не нужно:
запустите только `mine-transitions` с прежними `--dataset` и `--alignment-run`,
сохранив результат в новом каталоге.

Галерея, CSV/JSON кандидатов, RGB, маски и отчёт покрытия серий позволяют проверить
каждый участок. **Все результаты имеют `needs_review` и не являются временной
ground truth.** Ошибка выравнивания, неполнота аннотаций или окклюзия могут имитировать
переход. Отсутствие кандидата не доказывает отсутствие изменения. Отбор по маскам
также не позволяет считать unbiased Precision/Recall только на найденных окнах.
TEST не читается. Пары остаются first-anchor; полноценная история реальных
состояний требует последующей проверки этих кандидатов.

### Одна страница для всех готовых историй

Повторять подготовку данных, SIFT или inference не требуется:

```bash
python -u -s -m facade_change review-transitions \
  --synthetic-run /absolute/path/to/synthetic-histories \
  --candidate-runs /absolute/path/to/val-real-transition-review \
                   /absolute/path/to/train-real-transition-review \
  --out "runs/$(date -u +%Y%m%dT%H%M%S%N)-history-gallery"
```

В `gallery.html` все истории идут на одной статической странице, без выборки,
фильтров и формы вердиктов. Изображения можно увеличивать; легенда объясняет
накладки. Для каждого синтетического кропа показаны обе полные пятикадровые ветви
H0/H1 и известные процедурные состояния/события. Скрытые маски могут заходить под
процедурную окклюзию; они подписаны как скрытая истина, а не видимая GT.

Реальные наблюдения сгруппированы по зданию, виду и ранней опоре, затем упорядочены
по годам. Основная лента содержит исходные полные фотографии всех концов
подготовленных пар, включая кадры с отклонённым или отсутствующим выравниванием.
Статус выравнивания подписан у кадра; он не скрывается из истории. Пути, SHA-256,
годы, размеры и принадлежность проверяются по сохранённому манифесту датасета.
Если оригинал недоступен или изменён, команда останавливается с конкретной ошибкой,
а не создаёт незаметно неполную историю. COCO при этом не открывается.

Отдельная полоса показывает опору и поздний снимок каждой принятой пары на одном
полном холсте выравнивания с объединёнными кандидатными масками, в том числе пары
без кандидатов. Холсты разных пар могут различаться; они не объявляются общей
зарегистрированной последовательностью. Типы событий и классы перечислены в подписи; сотни похожих
окон отдельно не дублируются. Отсутствие кандидатов не доказывает отсутствие
изменения, а кандидатные маски не становятся временной ground truth.

Страница использует общую визуализацию проекта. Её JPEG-копии по умолчанию имеют
исходные размеры; `--preview-max-side 1600` ограничивает только картинки для
просмотра, если нужно уменьшить размер галереи. Научные входы и метрики не меняются.
`histories.json`, `summary.json` и `run.json` сохраняют состав, исходные пути и
хеши; оригинальные запуски остаются без изменений. Входы обязаны иметь совпадающие
хеши датасета и принадлежность TRAIN/VAL; TEST, COCO и модели не загружаются.

## A. Окупается ли оплаченная RGB-аппроксимация обновления

Один готовый кодер `zlib` (level9) используется для обоих mod256 остатков.
H0 выбирает identity либо RGB-affine prediction; все оценённые по текущему RGB
параметры передаются в потоке. H1 имеет ту же nuisance family и дополнительно
платит за битовую маску C, флаг операции и три RGB-байта V. V задаёт fill цветом
либо modular shift внутри C. Остаток восстанавливает каждый поддержанный
RGB-байт точно. H0/H1 независимо выбирают минимальную полную стоимость
из фиксированных режимов. GT и synthetic nuisance parameters в кодер не входят.

Первый рабочий кандидат C — RGB-DIFF >0.08; этот фиксированный proposal
полностью оплачивается. `proposal_coverage.csv` показывает его собственный Recall
и FPR: итоговый Recall не может превысить покрытие C. Отдельно кодируется
`oracle_visible_GT_paid` (файлы с суффиксом `oracle_paid`): C = labels==1.
Это GT-диагностика оплаченного представления, не работающий детектор и не
математическая верхняя граница. Oracle не участвует в калибровке и сравнении
качества. Следующий этап — другие GT-free кандидаты из замороженных моделей;
они не подменяются GT в этом первом прототипе.

Для каждого перекрывающегося тайла вычисляется реальное ΔL=L0−L1.
Карта хранит max ΔL/support_pixel среди тайлов, предложивших этот пиксель в C.
Пиксели вне C не могут стать изменением; τ>=0 не допускает отрицательной
экономии H1. Декодер получает только A, shared reference support и поток.
Проверяются точные round trips обоих потоков и oracle на каждом тайле.
Заголовки, sha256, индексы режимов, длины секций, nuisance, C, V, residual
входят в полную длину. Их сумма совпадает с `len(stream)*8`.

Lossless scope — RGB на заранее общей геометрической поддержке опоры.
Целевые RGB вне неё не кодируются; декодер оставляет там A. Это не whole-image
compression rate: тайлы перекрываются и имеют самостоятельные потоки.
Поддержка кодирования не сокращается с помощью GT visibility/occlusion.

Этот прототип намеренно ограничен: RGB fill/shift не представляет онтологические
переходы или историю S→C,V. Identity/affine не объясняют произвольные тени,
blur и окклюзии. Отрицательный результат относится к этой family/update format,
а не автоматически ко всей диссертационной гипотезе.

## B. Помогает ли прошлый контекст и добавляет ли что-то спектральная ветка

Три режима используют один frozen оригинальный MSDZip checkpoint, его causal
byte windows, lanes и 256-значный словарь без изменений upstream:

| Режим | Вероятности RGB-остатка |
|---|---|
| baseline | исходные logits MSDZip |
| spatial | исходные logits + обучаемый head по frozen DINO-признакам опоры |
| spectral | исходные logits + head по amplitude/phase этих же признаков |

Spatial/spectral имеют одинаковые две token-attention ветки, число параметров,
initial weights, Adam, seed, число эпох и sampled bytes. Финальная logit-коррекция
инициализируется нулём: исходные вероятности точно сохраняются до обучения.
Обучаются только heads на H0 TRAIN. Каждый checkpoint выбирается по минимуму
H0 VAL NLL; после этого модель замораживается для карт всех трёх состояний.

DINOv2 ViT-S/14 загружается через существующий local-only loader. В features
попадает только опорный RGB, с прежней нормализацией и reflect padding;
неподдержанные пиксели детерминированно обнуляются. Никакие target features,
labels, nuisance parameters, Fourier residual или будущие target bytes
не передаются в head. Native RGB mod256 residual остаётся исходным сигналом.

Spectral head использует полный rFFT spectrum и обе ветви amplitude/phase,
без удаления частот. Это собственная небольшая адаптация идеи SET
(https://arxiv.org/abs/2407.18568), не авторская реализация SET внутри слоёв VFM
и без его attention optimization. Пространственный контроль отделяет эффект
спектрального представления от capacity. Сравнение с baseline также меняет
наличие обучаемого адаптера и само по себе не доказывает эффект именно контекста.

Здесь выводятся **model bits / NLL**, без neural entropy stream и без заявления
о проверенном декодировании. Быстрый эксперимент не требует VTM или
нейросетевого сжатия/разжатия; actual roundtrip сейчас относится к A/zlib.

## Метрики, артефакты и решение о продолжении

Первичная метрика — facade-macro visible-H1 pixel Recall при VAL H0 pixel
FPR <=1% и <=5%. τ выбирается только по VAL: максимум Recall, затем меньший
FPR и более высокий τ. Строгое сравнение float32 `score > threshold`.
GT255 игнорируется. Средние — случаи внутри фасада, затем равные веса фасадов.
TRAIN-качество описательное; VAL используется и для checkpoint selection,
и для калибровки. Это не независимый окончательный тест.

Дополнительная диагностика `inspection_budget.csv` ранжирует неперекрывающиеся
32px тайлы по max score и показывает покрытие видимых H1 при номинальных
5/10/25% тайлов. GT не участвует в ранжировании. Реальная доля выбранной
пиксельной поддержки записывается отдельно из-за округления и крайних тайлов.
Это покрытие областей для осмотра, а не FPR маски изменений.

В `.../paid/` и `.../context/` сохраняются:

- `run.json`, `experiment_contract.json`, `events.jsonl`, `selected_cases.json`,
  `input_artifacts.json`: immutable fresh run, configuration/input/source hashes,
  append-only events и конечный статус;
- `summary.json` / `summary.txt`, `threshold_selection.json`, `case_metrics.csv`,
  `facades.csv`, `classes.csv`, `inspection_budget.csv`;
- paid: `tile_costs.csv`, `proposal_coverage.csv`, `oracle_diagnostics.csv`,
  `streams/*.bin`, `scores/*/*.npy`. Bundle содержит последовательные
  самостоятельные потоки; offsets/sizes и stream SHA записаны в tile_costs;
- context: `sampling.json`, `training_history.csv`, `model_provenance.json`,
  `reference_preparation.json`, `spatial.pt`, `spectral.pt`, `raw_bpb/*/*.npy`
  и `scores/*/*.npy`.

`full_diagnostic_seconds` paid включает oracle и все проверки декодера.
Для operational runtime потребуется отдельный замер без oracle.
Новая попытка — новый каталог; частичные файлы при ошибке сохраняются.

После одного фиксированного малого прогона:

1. Посмотреть, какие потери Recall идут от proposal C, а какие — от ΔL gate;
   отдельно crack/paint и каждый фасад. Проверить окупаемость oracle paid C,V.
2. Сравнить spatial/spectral при том же FPR и inspection budget. Падение H0 NLL
   полезно лишь вместе с сохранённым Recall. После трёх фиксированных эпох
   не начинать перебор гиперпараметров на уже просмотренном TEST.
3. При сохранённом Recall и устойчивом эффекте перейти к другим fixed candidates
   и настоящему причинному контексту ≥3 дат после инвентаризации таких серий.
   Неуверенность сегментации остаётся будущим флагом маршрутизации, не veto.
