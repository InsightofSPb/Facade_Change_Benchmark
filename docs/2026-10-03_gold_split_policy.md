# Размеченный набор и сохранение gold разбиения

Подготовка использует только фотографии из `images` актуального COCO JSON.
Каталоги изображений служат для поиска этих файлов; остальные фотографии в них
не включаются в манифест, split, временные пары и кропы. Число полигонов не
определяет состав: аннотации можно обновлять отдельно, а отсутствие полигонов
не считается подтверждением отсутствия повреждений.

## Первоначальный набор

Первый reviewed-запуск с `previous_split=null` создаёт исходный gold-состав
и назначения зданий. Целевые доли train/val/test — 70/10/20 по числу исходных
пригодных изображений. Все виды и даты одного физического здания находятся
в одной части. Для назначения требуется подтверждённый `building_id`, `view_id`
и год; непригодные наблюдения сохраняются с причинами исключения.

Gold здесь означает фиксированный исходный состав данных. Это название не
подтверждает качество полигонов и не создаёт истинные метки временных изменений.
Проценты приблизительные, поскольку здания неделимы.

## Расширение после обновления разметки

В той же конфигурации укажи новый `coco_json`, оставь `manifest_path=null` для
свежего инвентаря и задай `previous_split` путём к **последнему** reviewed
`prepared/split.json`. Передай CSV метаданных для актуальных COCO image IDs.
Все относительные пути считаются от каталога конфигурации.

1. Прежние назначения зданий сохраняются, включая временно отсутствующие здания.
2. Новый снимок известного здания наследует его train/val/test.
3. Новые здания распределяются с учётом всех текущих пригодных изображений.
   Оптимизируются только назначения новых зданий; старые не перемещаются.
4. Исходный gold-состав остаётся неизменным. Расширенный состав сохраняется отдельно.
5. Отсутствующие в актуальном COCO фотографии не обрабатываются. Отсутствующие
   gold-изображения перечисляются в `summary.missing_gold_sha256`; унифицированный
   запуск отмечает это статусом `completed_with_issues` и выводит список в отчёте.

Повторный запуск всегда использует новый выходной каталог. Один и тот же seed
без `previous_split` воспроизводит лишь разбиение неизменного набора, поэтому
он не заменяет сохранённые назначения. При продолжении проверяется совпадение
seed и целевых долей.

Унифицированный скрипт остаётся тем же:

```bash
python -B scripts/2026-10-03_prepare_dataset.py \
  --config configs/local-2026-10-03-dataset.json \
  --out runs/2026-10-03-dataset-002
```

Для подготовки только метаданных добавь `--prepare-only`. Отдельная команда
`python -B -m facade_change prepare` принимает аналогичный `--previous-split`.
Если метаданные ещё не подтверждены, унифицированный скрипт сохраняет таблицы
проверки со статусом `needs_metadata_review`; reviewed-разбиение не продолжается.

## Идентичность и выходы

COCO может перенумеровать image IDs при следующем экспорте. Идентичность снимка
сохраняется по SHA-256 исходного файла, а прежний image ID служит происхождением
записи. Хеш-префиксы имён используются только при поиске файлов. Смена здания,
вида, года или исходных байтов под прежним именем вызывает явный отказ; это
требует проверки и отдельной исправленной версии исходного gold, а не скрытого
переназначения. Между частями проверяются здания, виды и одинаковые байты.

`split.json` сохраняет:

| Поле | Содержание |
| --- | --- |
| `building_assignments` | Все назначения зданий, включая временно отсутствующие |
| `gold_cohort` | Исходный фиксированный состав с хешами и подтверждёнными метаданными |
| `extended_cohort` | Текущий пригодный состав и флаг `gold_member` |
| `historical_cohort` | Идентичности всех ранее включённых снимков для проверки утечек |
| `balance` | Фактические количества и отклонения от целевых долей |
| `provenance` | Источники, их хеши и ссылка на предыдущий split |

Gold-флаг также есть в prepared-манифесте и для обоих оригиналов каждого кропа
в общем индексе. Старый split без снимка gold-состава нельзя использовать как
продолжение: исходное разбиение нужно создать из прежнего reviewed-манифеста.

Аннотации и временные пары имеют собственные версии. При добавлении дат набор
соседних пар может измениться. Для сопоставимых временных метрик сохраняются
также исходный список пар и версия разметки; одного gold-флага снимка недостаточно.
RGB, геометрия и кропы формируются существующим конвейером из оригиналов.

## Проверки кода

2026-10-03 выполнена команда `python -B -m unittest discover -s tests -v`
в существующей CPU-среде: 67 тестов прошли. Синтетическая сквозная проверка
расширила набор с 20 до 30 снимков, сохранила старые назначения и исходный
gold-состав, получила 21/3/6 изображений и экспортировала выровненные кропы.
Отдельно проверены исключение файлов вне COCO, подмена состава повторно
используемого манифеста, смена COCO IDs и хеш-префиксов, отсутствующие gold-снимки,
исторические утечки и отказ при смене исходных байтов или подтверждённых метаданных.
`git diff --check` прошёл. Это проверки кода; реальные фотографии владельца
в этих проверках не использовались и фактическое gold-разбиение ещё не создано.
