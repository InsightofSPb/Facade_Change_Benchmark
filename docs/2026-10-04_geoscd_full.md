# Полный GeoSCD на фасадных парах

Команда `geoscd-full` запускает геометрию VGGT, признаки и proposals SAM1 ViT-H,
отбор изменений GeSCF и объединение результатов двух направлений. Она использует
[официальный GeoSCD](https://github.com/ZilingLiu/GeoSCD/tree/dd31369654e96d6843cc4bbcebce854a8bc2159b),
commit `dd31369654e96d6843cc4bbcebce854a8bc2159b`. Обучение не требуется.
Команда `geoscd` остаётся отдельным экспериментом только с геометрией.

## Установка и исправление частичного setup

В первом локальном логе setup остановился на `pip check`: новая среда увидела
пакеты из `~/.local/lib/python3.10/site-packages`. До скачивания VGGT и inference
выполнение не дошло. Исправленный setup исключает user site при каждом вызове
Python и сохраняет `PYTHONNOUSERSITE=1` в настройках `facade-geoscd`. Повторный
запуск дополняет существующую среду; удалять её или исправлять все посторонние
зависимости из того лога не требуется.

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
bash scripts/setup_geoscd.sh --full --download-weights
conda deactivate
conda activate facade-geoscd
```

В `models` появятся `vggt_1b.pt` и `sam_vit_h_4b8939.pth`. Существующие файлы
с этими именами переиспользуются. Если VGGT уже скачан в
`../GeoSCD-facade/src/pretrained/model.pt`, setup оставляет его там и печатает
путь: подставь этот путь в `--checkpoint`, вместо `models/vggt_1b.pt`.
Без `--download-weights` скачивания нет; inference принимает только локальные веса.

`models/sam3.pt` сохраняется. Он не совместим с используемым SAM1 ViT-H:
GeoSCD извлекает QKV и embeddings из своего модифицированного SAM1 encoder.
Подстановка SAM3 требует отдельной адаптации метода и не воспроизводит эту версию.
Setup устанавливает pinned официальный `segment-anything` для импорта predictor,
а модель строится из bundled `segment_anything_model` GeoSCD. Оба checkpoint
загружаются через `torch.load(weights_only=True)` со строгой проверкой state dict.

## Проверка полного метода на GPU

Начни с одной обычной пары и двух сложных пар из прежнего прогона:

```bash
python -s -B -m facade_change geoscd-full \
  --manifest runs/2026-10-03-first-anchor/manifest.json \
  --geoscd-root ../GeoSCD-facade \
  --checkpoint models/vggt_1b.pt \
  --sam-checkpoint models/sam_vit_h_4b8939.pth \
  --device cuda:0 \
  --pair 73:74 --pair 151:150 --pair 235:236 --limit 0 \
  --out runs/2026-10-04-geoscd-full-smoke
```

Это настоящий полный inference, без подмены результатов CPU-фикстурой. На каждой
паре VGGT вызывается дважды, с обоими порядками снимков; затем SAM/GeSCF
вычисляет две маски, которые объединяются на опоре. Модели перемещаются между
GPU и CPU по этапам, чтобы сократить одновременный расход VRAM. Объём памяти и
время фиксируются в артефактах запуска. Если возникнет ошибка или OOM, она
сохраняется рядом с именами обоих снимков; пара остаётся в общем знаменателе.
После запуска проверь:

```bash
cat runs/2026-10-04-geoscd-full-smoke/summary.txt
```

В `comparison.html` находятся галереи с именами файлов. Для каждой вычисленной
пары сохраняются `final_change_mask_reference_native.png`, маски обоих
направлений, `full_predictions_model_grid.npz`, native score `.npy`,
геометрическая поддержка, окклюзии и `diagnostics.json` со временем/памятью.
`run.json` фиксирует версии, конфигурацию, хеши исходников, весов и артефактов.

После просмотра smoke-галереи запуск всех 210 подготовленных пар:

```bash
python -s -B -m facade_change geoscd-full \
  --manifest runs/2026-10-03-first-anchor/manifest.json \
  --geoscd-root ../GeoSCD-facade \
  --checkpoint models/vggt_1b.pt \
  --sam-checkpoint models/sam_vit_h_4b8939.pth \
  --device cuda:0 --limit 0 \
  --out runs/2026-10-04-geoscd-full
```

Каждый `--out` — новый каталог. Разбиение, состав gold и пары берутся из готового
манифеста. Повторного аудита COCO, назначения split или запуска SIFT/LoFTR нет.
Остальные детекторы этими командами не запускаются.

## Что воспроизводится и что экспортируется

Вычислительная ветвь повторяет `src/demo.py` / `GeSCF` на квадратной сетке 512:
SAM proposals — 32 точки на сторону, proposal IoU и stability 0.7; признаки
`key`, слой 17, embeddings слоя 32; динамический порог по skewness/MAD,
морфология и отбор proposals с IoU 0.65. Режим по умолчанию `occupy`,
`sem_filter=None`. Изменение этих параметров фиксируется в конфигурации запуска.

В полном baseline сохраняются решения геометрии авторов, включая изменение
intrinsics до сетки 512 и предположение о первой камере. Это отличается от
нашей отдельной ветки `geoscd`, где сетка 518 и относительный camera transform
исправлены явно. Поэтому результаты двух команд нужно подписывать раздельно.
Настройка размещения моделей в памяти не меняет веса или формулы метода.
В bundled SAM обычный `Block.forward` также вычисляет и отбрасывает лишний
полный attention перед рабочей веткой. Адаптер убирает только этот неиспользуемый
вызов во время inference, проверяя точный префикс pinned исходника. Ветка QKV,
рабочий attention, residual и MLP сохраняются. Изменение записывается в
provenance; checkout авторов не редактируется.

Сохраняются маски двух направлений и итоговая бинарная маска изменений, а также
диагностика на исходной решётке reference. Native экспорт не добавляет точности
вычислениям на сетке 512. Полные оригиналы остаются источниками RGB; семантические
маски не подставляются вместо изображений. Геометрическая поддержка и
предсказанные окклюзии сохраняются раздельно. Окклюзия — выход модели, не GT.

Итоговый GeoSCD возвращает бинарную маску. Внутренняя косинусная разность
признаков, если сохранена, является диагностическим score, не вероятностью
повреждения. Изменения включают ремонт, условия съёмки и ошибки геометрии;
ранний кадр не считается автоматически «здоровым».

Число вычисленных пар не означает число качественно совмещённых пар. Сравнение
с 180 LoFTR-парами требует общего набора контрольных точек и ручной проверки.
COCO содержит разметку отдельных наблюдений, поэтому без temporal GT этот
прогон не сообщает F1/IoU истинных изменений. Локальные GPU-результаты и качество
на фасадах ещё не проверены в Cloud; тесты кода этого не заменяют.

Экспорт кропов из готовой геометрии LoFTR и сохранённого split выполняется
[отдельной готовой командой](2026-10-04_geoscd_and_crop_preparation.md#2-кропы-из-уже-готового-siftloftr-прогона).

## Проверки реализации

2026-10-04: полный набор `python -B -m unittest discover -s tests -v` —
136 тестов прошли за 37.7 с; `bash -n scripts/setup_geoscd.sh` прошёл.
Новые проверки охватывают сохранение active/QKV выходов при удалении лишнего
SAM attention, направления объединения масок, native координаты, исходные RGB,
разделение окклюзий/поддержки, provenance, отказы и прерывание. Setup проверен
через подставной conda без установки CUDA-пакетов и скачивания весов.
Предобученные VGGT/SAM и реальная GPU inference в этих CPU-тестах не запускались.
