стабильным фоном. Области вне общей разметки и неоднозначные границы исключаются.

## Сравнения и память

Семь методов: `rgb_diff`, `ssim`, `lpips`, `dinov2`, `semantic_dino`, `anychange`,
`msdzip_abs`. Для каждого обязательны три режима. GeoSCD и MSDZip MOD256 исключены.

Для последовательности 2010 → 2014 → 2018 → 2022 на целевом 2022:

| Режим | RGB-опоры | Целевая разметка |
|---|---|---|
| PREVIOUS | 2018 и 2022 | Изменение 2018 → 2022 |
| EARLIEST | 2010 и 2022 | То же изменение 2018 → 2022 |
| HISTORY | 2022 и сохранившиеся прошлые наблюдения текущего локального состояния | То же изменение 2018 → 2022 |

EARLIEST здесь — базовый способ обнаруживать последний шаг через старую опору.
Это не отдельная оценка накопленных изменений 2010 → 2022. Общие целевые шаги
начинаются с третьего наблюдавшегося года, в примере с 2018.

HISTORY использует существующую `TemporalMemory`, максимум три опоры на пиксель.
Опора — целое реальное RGB-наблюдение с локальной маской допустимости; RGB-мозаики
не синтезируются. Сначала вычисляется минимум оценок по допустимым прошлым опорам,
затем память обновляется. Принятое изменение удаляет старые опоры в этих пикселях.
Так возврат к прежнему виду после повреждения остаётся отдельным изменением.
Первое наблюдение инициализирует память, второе прогревает её; оба не являются
оцениваемыми шагами. Будущее и целевые маски в scorer/память не передаются.

AnyChange возвращает пространственную бинарную маску, а не один бит на кроп.
Минимум бинарных масок равен AND по доступным опорам в каждом пикселе. Это наша
временная адаптация готового парного метода. Веса и исходное бинарное решение
парного AnyChange не переобучаются и не калибруются заново.

Все режимы оцениваются на заранее определённой общей геометрии:
`support(first) & support(previous) & support(current)`. Внутри неё метрики
используют только известную разметку. Более ранние/будущие целевые маски и успешность
конкретной модели не определяют этот набор пикселей. Если метод не выдаёт оценку
на общей поддержке, запуск завершается ошибкой; метод не получает более лёгкий набор.

## Пороги, метрики и простые сочетания

Полный запуск подбирает выходные пороги непрерывных методов **на всём VAL**:
максимальный средний F1 по зданиям; при равенстве меньший FPR, затем больший порог.
Сетка — 2049 значений от 0 до 1, решение строго `score > threshold`.
Нет калибровки на случайных кропах, отдельных классах или TEST. Если на VAL нет
известных положительных и отрицательных пикселей, произвольный порог не подставляется.

Порядок для каждого метода:

1. PREVIOUS: парные карты → порог по полному VAL.
2. EARLIEST: карты → собственный порог по полному VAL.
3. Зафиксировать порог обновления памяти равным порогу PREVIOUS.
4. Один причинный проход HISTORY, включая прогрев → отдельный выходной порог HISTORY по VAL.
5. Отчёт по TRAIN, VAL, TEST с этими порогами. Гистограммы TEST собираются только после выбора порога режима.

Порог памяти равный PREVIOUS — явно зафиксированная эвристика, не доказанный оптимум.
Состояния памяти не перебираются для каждой выходной границы. Для AnyChange оба
порога 0.5 служат интерпретацией уже бинарного ответа. Пилот использует диагностические
0.5 для всех методов и не создаёт производственные пороги. Полный запуск калибруется
самостоятельно, используя из пилота только совместимые парные карты.

Пересекающиеся кропы объединяются по `building/view/previous_year/current_year`:
непрерывные оценки усредняются, бинарные маски объединяются OR. Каждый пространственный
пиксель этого перехода учитывается один раз. Затем TP/FP/FN/TN суммируются внутри здания,
из них считаются метрики здания, и здания получают одинаковый вес. Для каждой метрики
сохраняется число зданий с определённым знаменателем; неопределённые значения не становятся нулями.
Если перекрывающиеся участки выбрали разные снимки одного года и известные цели
противоречат друг другу, спорный пиксель исключается для всех методов, а не получает
метку по большинству. Такие пиксели отдельно считаются в `conflicting_overlap_pixels`.

Сохраняются F1, IoU, precision, recall, FPR, TP/FP/FN/TN, число зданий, покрытие разметкой
и приближённый `ap_binned` для непрерывных методов. Бинарный AnyChange и сочетания не получают
фиктивный AP. Гистограммы дают точные TP/FP/FN/TN на используемой сетке порогов; AP приблизителен
из-за квантования, исходные float32-карты также сохраняются.

Срезы: общий ANY_CHANGE, исходные классы и пять групп из `configs/semantic_class_groups.json`.
Положительные пиксели класса/группы — изменение членства хотя бы одного класса;
отрицательные — глобально стабильные размеченные пиксели в области этого класса/группы
на одном из концов перехода. Это локализация изменения в размеченных классах, не предсказание
названия класса методом и не семантический mIoU. Цели автоматически получены из разметки
двух изображений; это не независимо проверенные события повреждения.

Из готовых карт автоматически считаются три заранее заданных варианта:
AnyChange AND Semantic DINO; AnyChange AND MSDZip ABS; AND всех трёх.
Сначала для каждого компонента объединяются пересечения кропов, затем применяются
его уже выбранный порог и AND. Нового inference и подбора коэффициентов нет.
Снижение FPR возможно ценой recall; улучшение F1 не предполагается заранее.
Эти строки сохраняются отдельно в `summary.json/fusion_results` и рядом с базовыми
методами в `metrics.csv`. TEST не выбирает лучший вариант.

Старые checkpoint могли видеть нынешние VAL/TEST. Их доступный аудит сохраняется
в `checkpoint_exposure`: названия split не делают знакомые моделям здания независимым
тестом. VAL здесь калибровочный, его качество не является оценкой на нетронутой выборке.

## Подготовка и пилот на компьютере владельца

Используйте уже рабочую среду проекта и существующий
`configs/2026-11-04-models.local.json`. В нём остаются пути и настройки готовых весов;
недостающие модели не скачиваются автоматически этой командой.

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only origin codex/2026-10-24-main-workflow

python -s -u -m facade_change workflow prepare real \
  --histories /home/sasha/Facade_Change_Benchmark/data/2026-11-04-histories-s192-001/manifest.json \
  --expected-sha256 dec521ea95cdb1447cd707ec31cc78c230864986a34c21c18c70f959415e3134 \
  --expected-candidates 2089 \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-11-04-s192-prepared-001

python -s -u -m facade_change workflow benchmark pilot \
  --prepared /home/sasha/Facade_Change_Benchmark/runs/2026-11-04-s192-prepared-001 \
  --methods rgb_diff ssim lpips dinov2 semantic_dino anychange msdzip_abs \
  --methods-config /home/sasha/Facade_Change_Benchmark/configs/2026-11-04-models.local.json \
  --pilot-tracks 3 --device cuda:0 --trust-checkpoint \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-11-04-s192-pilot-001
```

Подготовка берёт точный reviewed annotation manifest из сохранённого alignment session.
Если журнал с путём к нему отсутствует, команда выдаст ошибку с требованием
`--annotation-manifest`: нужен исходный reviewed manifest с `source.coco_json`, не bare COCO.
Завершённую подготовку повторять не надо. Незавершённую продолжают той же командой с `--resume`.

Пилот выбирает до трёх полных историй TRAIN и до трёх VAL, чередуя короткие и длинные
и отдавая предпочтение разным зданиям. Отбор только по метаданным. TEST в качестве
пилотной выборки не используется; целостность всего набора проверяется при подготовке.
Модели загружаются последовательно, одновременно один активный worker.

Проверить перед полным запуском:

- `run.json`: `status=completed`; все семь методов, три режима, TRAIN/VAL.
- `summary.json`: 42 базовых результата и 18 результатов сочетаний, известные пиксели,
  положительные/отрицательные пиксели, число зданий и диагностические пороги.
- `gallery.html`: RGB EARLIEST/PREVIOUS/CURRENT, GT последнего шага, карты трёх режимов;
  общий правильный масштаб, сохранённая локализация, отсутствие явного сдвига масок.
- `timing.json`: измерения uncached-вызовов, интервал полного времени для каждого
  метода/режима, объём артефактов и приблизительная оценка диска полного запуска.
- `resources.json`: время загрузки и доступный пик Torch allocator в worker.
  Это не полный расход GPU других библиотек; снимок процессов/памяти сохраняется отдельно в ledger.
- `thresholds.json`, `selection.json`, `method_contracts/`, `events.jsonl`, `worker_logs/`:
  пороги, конкретные истории, веса/настройки, журнал и ошибки библиотек.

Время оценивается по реальным вызовам пилота, без предположения о пользе кэша.
Для всего набора PREVIOUS и EARLIEST имеют по 2089 целевых сравнений;
HISTORY — от 2701 до 8882 вызовов с учётом прогрева. Верхняя граница допускает больше
трёх сохранённых целых RGB при разной видимости, хотя на пиксель допустимы лишь три опоры.
Вычисления, совпавшие по RGB **и поддержке**, не повторяются. Замер scorer включает
обмен с worker, но не загрузку модели, сохранение конечных карт и CPU-метрики.
Экстраполяция — ориентир, не обещание завершения за ночь.

## Проверка реализации в Cloud

```bash
python -m unittest discover -s tests -v
python -m unittest 'tests/test_2026-11-04_history_benchmark.py' -v
```

Новый датированный файл включён также в стандартный discovery через `test_workflow.load_tests`.
Сквозные проверки используют настоящие RGB-DIFF/SSIM на процедурных 224 px изображениях;
маршруты семи методов проверяются тестовыми scorer-ами. Проверяются одинаковые шаги/пиксели,
выбор года, неизвестная разметка, пересечения кропов, строгие пороги, VAL до TEST,
ремонт/возврат состояния, бинарная история, AND после слияния, resume и hash-sensitive cache.
Такая проверка не заменяет локальный пилот настоящих LPIPS/DINO/SAM/MSDZip и не подтверждает
их скорость, качество или совместимость локальных весов.

Проверено в Cloud 2026-11-04: общий discovery — 1162 теста, 119 пропущены по условиям
необязательных зависимостей, ошибок нет; отдельно последняя версия нового файла —
15 тестов, все прошли. Основной процесс и `python -s` worker проверялись с одинаковыми
NumPy 2.2.6, OpenCV 4.12.0, tqdm 4.67.1, SciPy 1.13.1 в изолированной CPU-среде.
Отдельный CLI-пример завершил `prepare real` и `benchmark real` с настоящими
RGB-DIFF/SSIM: шесть процедурных историй, 24 наблюдения, 12 целевых шагов,
18 результатов по методам/режимам/split. Это проверка реализации, не результат на фасадах.
