# Реальные пары: просмотр и тест устойчивости к освещению

Три отдельные команды: `prepare` готовит все доступные реальные VAL-кандидаты
на CPU, `run` обрабатывает только вручную выбранные пары, `report` считает метрики
по сохранённым картам без запуска моделей. Команда:

```bash
/home/sasha/miniconda3/envs/scd_bench/bin/python -u scripts/real_eval/real_robustness.py --help
```

Этот эксперимент использует **PREVIOUS**. EARLIEST и HISTORY здесь не имитируются
готовыми парными картами; для возмущённой истории потребуется отдельное причинное
прохождение последовательности с самого начала.

## 1. Отдельный checkout, пока исходный GeoSCD работает

Новый worktree позволяет подготовить галерею, не заменяя файлы в каталоге,
из которого выполняется текущий GeoSCD. `git fetch` обновляет ссылки Git;
`git pull`, переключение ветки или сброс исходного checkout для этого не нужны.

```bash
cd /home/sasha/Facade_Change_Benchmark &&
git fetch origin &&
git worktree add --detach /home/sasha/Facade_Change_Benchmark_robustness origin/main
```

Путь worktree должен быть новым. Если он уже создан этим способом, используйте
его, не повторяя `worktree add`. Новый checkout хранит только код; данные и
результаты продолжают использовать абсолютные пути исходного проекта. Среды,
веса и работающие процессы не меняются.

## 2. Подготовить всех кандидатов и открыть галерею

```bash
cd /home/sasha/Facade_Change_Benchmark_robustness

nice -n 10 /home/sasha/miniconda3/envs/scd_bench/bin/python -u scripts/real_eval/real_robustness.py prepare \
  --run /home/sasha/Facade_Change_Benchmark/runs/2026-10-14-temporal-experiment-002 \
  --snapshot /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-temporal-val-snapshot-001 \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-prepared-001

cd /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-prepared-001
explorer.exe .
```

В открывшейся папке откройте `gallery.html`. Подготовка:

- берёт все доступные реальные VAL / RGB-DIFF / PREVIOUS пары из фиксированного
  snapshot, а не только 12; TEST не читает;
- восстанавливает GT на прежней геометрии, проверяет исходные RGB и support;
- сохраняет исходные кропы, классы обоих наблюдений, GT-переход, варианты
  экспозиции и тени;
- сохраняет неподготовленные/отказавшие пары с причиной исключения;
- предлагает до 12 положительных пар, по возможности до двух на фасад;
  дополнительные пары выбираются теми же флажками без повторной подготовки.

Нажмите «Выбрать рекомендованные», проверьте пары глазами и измените выбор.
Особенно проверьте геометрию, соответствие размеченных изменений RGB и
сохранность мелких повреждений после возмущения. Нажмите
**«Скачать reviewed_selection.json»** и перенесите скачанный файл в папку
подготовки рядом с `gallery.html` и `manifest.json`. Это можно сделать через
открытый Проводник; Windows-папка загрузок у разных пользователей отличается.

Проверьте, что файл оказался на нужном месте:

```bash
ls -l /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-prepared-001/reviewed_selection.json
```

В JSON сохраняются выбранные `pair_ids`, `reviewed: true` и SHA-256 точного
манифеста. Runner не принимает неподтверждённый выбор, дубликаты, исключённые
пары или выбор от другой галереи. Галерея ничего не запускает на GPU.

## 3. Объём и условия эксперимента

Возмущения фиксированы для всех методов: экспозиция в линейном RGB с множителем
0,75 и мягкая диагональная тень с уменьшением линейной яркости максимум на 35%.
Они меняют позднее RGB,
сохраняя геометрию, support и исходную GT-разметку. Точные параметры записаны
в `manifest.json`; при оценке они заново не подбираются.

| Задача на выбранную пару | Опора | Текущий снимок | Разметка |
|---|---|---|---|
| Исходная реальная пара | Ранний RGB | Поздний RGB | Подготовленный GT-переход |
| Реальная пара + экспозиция | Ранний RGB | Поздний RGB с экспозицией | Тот же GT-переход |
| Реальная пара + тень | Ранний RGB | Поздний RGB с тенью | Тот же GT-переход |
| H0 экспозиция | Поздний RGB | Его вариант с экспозицией | Изменения состояния нет |
| H0 тень | Поздний RGB | Его вариант с тенью | Изменения состояния нет |

В записях реальная ветвь называется `H1`, но выбранная пара может не иметь
положительного GT. Наличие изменений определяется разметкой, а не именем ветви.
Для H0 оценивается вся общая геометрическая поддержка пары: она не сужается
по маскам классов. Участки вне support игнорируются.

По умолчанию запускаются восемь методов: **RGB-DIFF, SSIM, LPIPS, DINOv2,
Semantic DINO, AnyChange, GeoSCD и MSDZip ABS**. Каждый получает все выбранные
пары и оба возмущения. MSDZip MOD256 доступен при явном перечислении в
`--methods`, но не включён в основной набор.

**12 пар = 48 новых сравнений на метод + 12 исходных сравнений.** Исходные
карты переиспользуются при совпадении входов, настроек и происхождения модели;
при отсутствии карты выполняется inference. Для восьми методов это 384 новых
возмущённых сравнения и до 96 исходных, большинство которых уже может быть в
кэше. При увеличении числа пар объём растёт пропорционально. Время CPU-подготовки
и GPU-прогона заранее не обещается; прогресс и фактическое время сохраняются.

## 4. После завершения исходного GeoSCD запустить выбранные пары

Дождитесь завершения `/runs/2026-10-17-geoscd-real-all-001`. Его готовые PREVIOUS
карты подключаются как дополнительный кэш; отказы остаются отказами, а не
нулевыми масками. Проверить последние строки текущего прогона:

```bash
tail -n 30 /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-geoscd-real-all-001.log
```

Затем:

```bash
cd /home/sasha/Facade_Change_Benchmark_robustness
set -o pipefail

/home/sasha/miniconda3/envs/scd_bench/bin/python -u scripts/real_eval/real_robustness.py run \
  --prepared /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-prepared-001 \
  --selection /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-prepared-001/reviewed_selection.json \
  --geoscd-run /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-geoscd-real-all-001 \
  --device cuda:0 \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-run-001 \
  2>&1 | tee -a /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-run-001.log
```

Веса, настройки и происхождение берутся из исходного temporal-run. Для ABS
обязательны записанные путь и SHA-256 обученного checkpoint. Новое обучение,
автоматический поиск других весов и скачивание не запускаются. Проверяются
источники модели, веса, выбранные RGB и записи кэша; несоответствие останавливает
соответствующую обработку и сохраняется явно.

Модели загружаются **последовательно**; модель одного метода остаётся загруженной
между его парами. В консоль передаётся worker-log, а при долгой операции каждые
15 секунд печатается время и PID worker. Снимок `nvidia-smi` сохраняется в
`logs/`; чужие процессы не изменяются. Низкая загрузка GPU сама по себе не
означает зависание: сведения о текущем этапе есть в консольном и worker-логах.

```bash
tail -f /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-run-001.log
```

## 5. Продолжение, повтор отказов и сохранение результатов

Для каждого задания сначала атомарно сохраняется `maps/*.npz`, затем запись
`units/*.json`. Все попытки сохраняются в `attempts/`, события — в
`events.jsonl`. `progress.json`, `run.json` и `summary.json` содержат счётчики и
статус. Ошибочная пара не получает искусственную нулевую карту.

Только известная ошибка GeoSCD
`No finite valid SAM correspondence similarities` разрешает продолжить
следующую пару с сохранением исправного worker. Иные ошибки инициализации или
inference прекращают текущий метод; остальные методы обрабатываются отдельно.

Ctrl+C сохраняет готовые карты. Продолжение с теми же входами:

```bash
cd /home/sasha/Facade_Change_Benchmark_robustness
set -o pipefail

/home/sasha/miniconda3/envs/scd_bench/bin/python -u scripts/real_eval/real_robustness.py run \
  --prepared /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-prepared-001 \
  --selection /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-prepared-001/reviewed_selection.json \
  --geoscd-run /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-geoscd-real-all-001 \
  --device cuda:0 \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-run-001 \
  --resume \
  2>&1 | tee -a /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-run-001.log
```

Добавление `--retry-failed` к этой команде повторяет также сохранённые отказы.
Обычный `--resume` пропускает и готовые задания, и уже записанные отказы.
Незавершённые задания без готового маркера выполняются заново. Повтор не меняет
предыдущие записи попыток.

Resume проверяет хеши выбора, манифеста, подготовленных данных, исходного кэша,
весов и относящегося к inference кода. Изменённый выбор, новые условия, иной
checkpoint или изменённый код требуют нового output-каталога. Не обновляйте
worktree во время прогона. Оставьте исходный GeoSCD-кэш неизменным после старта.

## 6. Посчитать таблицы без новых inference и калибровки

```bash
cd /home/sasha/Facade_Change_Benchmark_robustness

/home/sasha/miniconda3/envs/scd_bench/bin/python -u scripts/real_eval/real_robustness.py report \
  --run /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-run-001 \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-report-001
```

По умолчанию используются ранее сохранённые пороги **synthetic VAL H0 1% и 5%**
для PREVIOUS. Это целевые FPR на исходной калибровке, а не обещание FPR 1%/5%
на возмущённых реальных снимках. AnyChange и GeoSCD сохраняют авторские бинарные
маски. Новые пороги по выбранным 12 парам или их возмущениям не подбираются.

Можно построить отдельный отчёт с **уже существующими** real-LOFO порогами,
полученными на невозмущённых данных тем же протоколом GT. Для отчёта из
[инструкции реальных метрик](2026-10-17_real_eval_tools.md):

```bash
/home/sasha/miniconda3/envs/scd_bench/bin/python -u scripts/real_eval/real_robustness.py report \
  --run /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-run-001 \
  --calibration-run /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-calibration-all-003 \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-real-robustness-report-lofo-001
```

Эта команда требует, чтобы указанный calibration-run уже существовал; она не
создаёт его и не обучает пороги заново. Для каждого оцениваемого фасада берётся
сохранённый порог, подобранный без этого фасада. Отчёты с synthetic и real-LOFO
калибровкой сохраняются отдельно.

Смотрите `summary.json`, `aggregate.csv`, `deltas.csv`, `class_aggregate.csv`,
`coverage.csv` и `report.html`. CSV содержат доли; HTML показывает проценты.
Есть исходные/возмущённые результаты, H0 FPR, P/R/F1/IoU, TP/FP/FN/TN,
отмеченная площадь, классовые срезы и доступные сочетания с ABS. Сравнения с
добавкой пересчитывают исходный метод на том же покрытии. Пропуски карт,
отказы и отсутствие подходящего порога видны в покрытии.

## Интерпретация

- Научная единица — фасад. Кадры усредняются внутри фасада, затем фасады имеют
  равный вес. Пиксельные счётчики приводятся отдельно от макрометрик.
- Все аннотированные классы сохраняются; нет скрытого исключения неба или
  конкретного повреждения. Неаннотированный пиксель не превращается в здоровый
  фон. GT реальной ветви — изменение набора аннотированных классов на общей
  известной поддержке после совмещения, с указанным допуском границ.
- Визуальный выбор помогает отсеять очевидные проблемы совмещения, но не
  превращает разность двух семантических масок в независимую экспертную разметку
  всех визуальных изменений. Классовые срезы оценивают локализацию изменения
  в областях класса, а не умение change-метода назвать этот класс.
- Выбор по видимым изменениям и GT обогащает диагностическую выборку. Это
  **exploratory VAL robustness**, не независимый TEST и не оценка частоты
  повреждений на всех фасадах. H0 с искусственным освещением проверяет заданное
  возмущение, а не все реальные изменения погоды, ракурса или окклюзий.
- RGB остаётся uint8 на прежней сетке. GT, выбор пользователя и маски условий
  не передаются модели; scorer получает только reference RGB, source RGB и
  геометрическую поддержку.

CPU-проверки: `python -m unittest tests.test_real_robustness_prepare
tests.test_real_robustness_run tests.test_real_robustness_report -v`. Тесты runner включают настоящий RGB-worker
без GPU и подмены тяжёлых моделей для проверки оркестрации. Качество нейросетей
на реальных данных подтверждается только запуском владельца.
