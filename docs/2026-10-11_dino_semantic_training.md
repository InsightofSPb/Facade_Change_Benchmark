# Первая обучаемая семантическая модель

Этот запуск — исходный supervised-результат перед экспериментами с адаптером,
устойчивостью к условиям съёмки и историей фасада. Он относится к семантической
ветке мастер-карты: строит классы состояния на одном изображении. Он не реализует
H0/H1, временные изменения, Fourier-токены или новую компрессионную модель.
AnyChange, GeoSCD и прежняя DINO-разность остаются конкурентами временной ветки;
их F1 нельзя непосредственно сравнивать с семантическим mIoU этого запуска.

## Модель и обучение

- Оригинальный локальный DINOv2 ViT-S/14 и уже скачанный checkpoint, без загрузок
  из сети и без изменения авторского кода. Повторно используется существующий
  проверяемый загрузчик `methods/dinov2.py`.
- Backbone заморожен. Последние четыре нормализованные карты признаков
  объединяются в 1536 каналов. Обучается стандартная голова
  `BatchNorm2d → Conv2d(1×1)`; logits интерполируются на исходный размер кропа.
- Это собственный supervised baseline на стандартных компонентах PyTorch,
  а не заявленная репродукция полного авторского протокола. Паттерн головы
  соответствует [линейной голове DINOv2](https://github.com/facebookresearch/dinov2/blob/main/dinov2/eval/segmentation/models/decode_heads/linear_head.py).
  Вместо legacy mmseg/SyncBN используется однопроцессный BatchNorm и наш контракт
  пересекающихся COCO-классов.
- Loss: `0.5 BCE + 0.5 soft Dice`. BCE усредняется по всем каналам на допустимых
  пикселях; Dice — по классам с положительными размеченными пикселями в batch.
  AdamW, LR 0.001, weight decay 0.01, cosine schedule, clip norm 1.
- По умолчанию 20 эпох, batch 4, четыре случайных размеченных кропа каждого TRAIN
  фото за эпоху. Фото перемешиваются; если кропов меньше четырёх, допускаются
  повторы с независимыми аугментациями. Это баланс по изображениям при обучении,
  а не равный вес всех геометрических кропов и не баланс классов/фасадов.
- Подготовленные кропы сохраняют 512×512 и шаг 448. Внутри модели RGB дополняется
  справа/снизу до кратности 14, затем padding удаляется с карты logits.

## Разметка и границы метрики

Каналы выводятся из категорий текущего COCO, по возрастанию ID; их соответствие
сохраняется в checkpoint и `config.json`. Для нынешнего набора это 11 классов.
Полигоны и COCO RLE растрируются готовой библиотекой pycocotools. Пересечения
сохраняются как multi-label: один пиксель может принадлежать нескольким классам.
Решение для каждого канала — sigmoid ≥ 0.5, без подбора порога на VAL.

**Неразмеченные пиксели неизвестны, а не являются здоровым фоном.** Учебная и
оценочная поддержка — объединение аннотаций, пересечённое с непрозрачными пикселями
исходного изображения. Crowd, padding и закрытые CutOut пиксели игнорируются.
Внутри этой поддержки отсутствие аннотации класса трактуется как отрицательная
метка этого класса. Это явное допущение о полноте категорий на размеченном участке.

Поэтому результат называется **multi-label mIoU на размеченной поддержке**.
Он не измеряет ложные срабатывания на неразмеченной стене и не сопоставим напрямую
со старым LPOSS mIoU без проверки одинаковых масок, классов и правил агрегации.
Ни 30%, ни 60–70% качества заранее не гарантируются.

## Аугментации TRAIN

RGB и маски проходят одинаковую геометрию. Маски и их поддержка преобразуются
nearest-neighbor, RGB — bilinear; это не должно искусственно стирать тонкие
классы консервативным размыванием маски. Дополнение за границей не участвует в loss.

| Преобразование | Параметры по умолчанию |
|---|---|
| Отражение | Горизонтальное, вероятность 0.5 |
| Умеренная геометрия | Вероятность 0.5; ±5°, масштаб 0.95–1.05, сдвиг до 3% |
| Экспозиция | ±0.5 ступени, в linear-light RGB |
| Контраст | 0.85–1.15 относительно 0.18 в linear-light RGB |
| Баланс белого | Коэффициенты каналов 0.9–1.1 |
| Мягкая тень | Вероятность 0.5; ослабление 15–45% |
| CutMix | Вероятность 0.5; Beta(1,1), прямоугольник из другого TRAIN фото |
| CutOut | Вероятность 0.25; стороны прямоугольника 15–30% кропа, заполнение средним RGB |

Размытия нет. Это ограниченный набор преобразований, а не доказательство
устойчивости ко всем ракурсам и уличным условиям. CutMix копирует RGB, все каналы
разметки и поддержку одним прямоугольником; классификационное смешивание вектора
меток здесь неприменимо. CutOut моделирует закрытие: покрытые пиксели исключаются
из loss, а не превращаются в отрицательные примеры повреждения. Эти две операции
реализованы прямым переносом/закрытием массива для нашего multi-label контракта.

CutMix donor всегда другой TRAIN снимок; один donor crop может использоваться
для нескольких кропов фото. VAL не получает ни одну из перечисленных аугментаций.

## Данные, VAL и воспроизводимость

Используется готовый `dataset.json` и полный `semantic_manifest.json`, поэтому
одиночные фотографии и снимки без адреса остаются в TRAIN. Split не пересоздаётся.
Проверяются SHA COCO/артефактов, SHA открываемых RGB и известные пересечения
building_id, view_id, SHA между всеми split. Неизвестная принадлежность части
TRAIN не даёт объявить полную физическую независимость от holdout.

Общий COCO JSON читается для индексации; TEST аннотации не растрируются,
TEST RGB не открывается и TEST метрики не вычисляются. Выбор checkpoint — только
по VAL. RGB не подвергается EXIF-повороту.

На VAL каждый исходный пиксель учитывается один раз: перекрытия кропов разделяются
посередине, с фиксированным назначением пикселя одному кропу. Это протокол центральной
части кропа, не усреднение logits. TP/FP/FN суммируются внутри фасада; затем mIoU
фасадов усредняется с равным весом. Дополнительно выводится объединённая пиксельная
метрика. Пустое объединение класса даёт `null`, но ложный прогноз отсутствующего
класса даёт IoU 0. Кропы не являются независимыми статистическими наблюдениями.

Seed, параметры, входные хеши, дерево исходников DINO и веса фиксируются.
Одинаковые seed не обещают битовое совпадение разных GPU/версий PyTorch.
Перед CUDA проверяются свободная память и список процессов; чужие процессы
не останавливаются. Результаты создаются в новом каталоге. После каждой эпохи
сохраняются `last.pth` и, при улучшении VAL, `best.pth` (голова, optimizer,
контракт и ссылка с хешем на замороженный backbone). Автоматического resume пока нет.
Растровые маски кешируются сжатыми в `mask-cache/` текущего запуска: большие
полигоны не требуется заново декодировать каждую эпоху. Проверяются хеши входов,
размеры, тип и соответствие категорий; кеш не меняет исходные аннотации.

## Запуск на компьютере владельца

Используется среда, в которой уже работает DINOv2. Единственная новая зависимость
для масок — pycocotools; переустанавливать Torch/CUDA не нужно.

```bash
cd /home/sasha/Facade_Change_Benchmark &&
git -c http.version=HTTP/1.1 pull --ff-only &&
conda activate scd_bench &&
python -s -m pip install --no-deps pycocotools==2.0.11 &&
python -u -s -m facade_change.segmentation \
  --dataset runs/20261011T164728148457Z-dataset-preparation \
  --methods-config configs/benchmark.local.json \
  --device cuda:0 \
  --epochs 20 --batch-size 4 --crops-per-image 4 \
  --cutmix-prob 0.5 --cutout-prob 0.25
```

`--methods-config` читает секцию `dinov2` и ссылку `methods_config` из существующей
конфигурации benchmark. Не используйте `arib-check.local.json`: он может содержать
только новые методы, без путей ранее кешированного DINO. Можно явно передать
`--source-root` и `--checkpoint` вместо конфигурации. Для короткой проверки
реальной CUDA/весов добавьте `--smoke`: одна эпоха на двух фото TRAIN/VAL,
не более четырёх размеченных VAL кропов на изображение. Это проверка запуска,
не результат качества. Каждый вызов автоматически создаёт новый каталог.

Выход `runs/<UTC>-dino-seg/`:

- `summary.json`, `metrics.json`: лучший VAL, числа и границы оценки;
- `per_class.csv`, `per_building.csv`: IoU/Recall/Precision и фасады;
- `best.pth`, `last.pth`: состояния обучаемой головы;
- `history.json`, `val-epoch-*.json`: история и полные метрики эпох;
- `gallery.html`, `previews/`: один фиксированный размеченный кроп каждого
  VAL фасада, GT и прогноз отдельно по классам, без схлопывания пересечений;
- `config.json`, `run.json`: параметры, происхождение, хеши и конечный статус.

CPU-проверки используют настоящий PyTorch и маленький тестовый backbone:
проверяют обучение/заморозку/сохранение, но не качество настоящего DINOv2 или CUDA.
Первый реальный запуск даст исходное качество для следующего сравнения с адаптером.
