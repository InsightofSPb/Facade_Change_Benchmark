# Детерминированные варианты для H₀/H₁

Этот шаг готовит изображения и известную процедурную разметку для проверки
устойчивости к условиям съёмки. Детекторы и расчёт метрик здесь не запускаются.
Используется уже завершённый экспорт LoFTR-кропов; совмещение не пересчитывается.

## Запуск

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
conda activate lposs

python -B -m facade_change h0h1 \
  --crop-run runs/2026-10-04-crops \
  --config configs/2026-10-04_h0h1_controls.json \
  --out runs/2026-10-04-h0h1

cat runs/2026-10-04-h0h1/summary.txt
```

Выходной каталог должен быть новым. Исходные 4918 кропов сохраняются.
Родительский `completed_with_issues` допустим: 31 исключённая пара остаётся в
журнале. Пара 207–206 без кропов не возвращается в набор.

По умолчанию выбираются **до двух кропов на здание** с геометрическим
пересечением не ниже 0.95. Повторные копии одного опорного RGB-кропа исключаются;
предпочтение отдаётся разным видам и опорным снимкам. Отбор использует стабильное
SHA-ранжирование без случайных чисел и записывается в `selection.json`.
Все варианты наследуют существующий split здания. Добавление новых исходных
кропов может изменить отбор следующего запуска: сравнение методов использует
один зафиксированный экспорт.

## Что сравниваем

Во всех случаях reference — один исходный кроп. Synthetic source создаётся
из **этого же кропа**, а не из фотографии следующего года.

| Состояние | Гипотеза | Содержание |
| --- | --- | --- |
| `unchanged` | H₀ | Исходное состояние, включая уже существующие повреждения |
| `crack` | H₁ | Фиксированная тонкая тёмная ломаная — процедурный аналог трещины |
| `paint_patch` | H₁ | Фиксированная локальная цветовая правка — аналог покраски/ремонта |
| `self_paste` | H₀, контроль | Точная вставка тех же пикселей в ту же область |

Каждое состояние независимо комбинируется с 18 сценариями:

| Условия | Фиксированные параметры | Число |
| --- | --- | ---: |
| Без преобразований | Точная копия | 1 |
| Локальная тень | Диагональная граница / полоса; ослабление света 15%, 35%, 55% | 6 |
| Экспозиция | Коэффициент 0.75 / 1.25 | 2 |
| Контраст | Коэффициент 0.8 / 1.2 относительно линейного уровня 0.18 | 2 |
| Баланс белого | RGB-множители `[1.12, 1, 0.88]` / `[0.88, 1, 1.12]` | 2 |
| Размытие | Gaussian σ = 0.8 / 1.6 пикселя | 2 |
| JPEG | Кодирование/декодирование, quality 70 / 40, 4:2:0 | 2 |
| Перекрытие | Непрозрачный прямоугольник, частично закрывающий правку | 1 |

Итого **72 варианта на выбранный кроп**. Это независимые проверки отдельных
факторов: тень не накладывается поверх JPEG, затем поверх размытия.
Положение тени одинаково при всех трёх уровнях; меняется только сила.
Тени, экспозиция, контраст, баланс белого и размытие рассчитываются в линейном
RGB с преобразованием обратно в uint8 sRGB. Выход JPEG сохраняется в PNG,
чтобы чтение не добавляло ещё один цикл сжатия.

Сначала вносится изменение состояния, затем условия съёмки. Геометрия остаётся
фиксированной, преобразование reference↔synthetic source — единичное.
Повторного LoFTR и геометрических аугментаций в этом наборе нет.

## Файлы и маски

`gallery.html` содержит ссылки на четыре страницы состояний. На них показаны
reference, изменённое изображение и полная маска внесённой правки.

| Путь | Содержание |
| --- | --- |
| `bases/…/reference_rgb.png` | Общий опорный RGB для вариантов одного кропа |
| `bases/…/states/…/true_edit_mask_reference.png` | Полная маска фактически изменённых RGB-пикселей до условий съёмки |
| `cases/…/source_rgb.png` | Готовый вариант для подачи методу |
| `cases/…/nuisance_mask.png` | Известная область применения условия съёмки |
| `cases/…/true_visibility.png`, `source_occlusion.png` | Видимость и известное процедурное перекрытие |
| `cases/…/visible_edit_mask_reference.png` | Правка, остающаяся видимой после перекрытия |
| `cases/…/labels_reference.png` | 0 — нет внесённой правки; 1 — правка; 255 — исключённый пиксель |
| `index.json`, `index.csv` | Случаи, исходные имена/годы, split, параметры, пути и хеши |
| `selection.json`, `split.json`, `config.json`, `run.json` | Зафиксированный отбор, split и происхождение |

Тени и изменения экспозиции **не являются положительными метками H₁**.
Они остаются видимыми пикселями и могут вызвать ложное срабатывание детектора.
При известном перекрытии скрытая правка сохраняется в полной маске, но её
пиксели получают метку 255. Индекс содержит долю оставшейся видимой правки.
Полностью скрытый H₁ остаётся H₁ и отмечается `exclude_from_visible_recall`.
Известная видимость относится только к добавленному прямоугольнику:
реальные окклюзии в исходном кропе автоматически не размечаются.

## Дальнейшая оценка

Набор соответствует контролируемой части мастер-карты: неизменное состояние
с мешающими факторами против известного изменения с теми же факторами.
Он проверяет ложные срабатывания H₀ и сохранение чувствительности H₁.
Полная H₀/H₁ модель с учётом реальной длины кода — отдельный следующий эксперимент.

Все методы получают одинаковые RGB и один общий протокол оценки.
Пороги выбираются на train/val и фиксируются до test. Истинные маски правок,
условий и видимости используются для оценки; передача их детектору возможна
только как явно обозначенная отдельная oracle-абляция. В том числе
`source_support` в семействе перекрытий содержит известную процедурную
видимость; это не результат обнаружения реальных окклюзий.

Статистическая единица — здание; варианты одного кропа не являются независимыми
наблюдениями. `self_paste` совпадает с `unchanged` при тех же условиях и служит
проверкой пути вставки, а не дополнительным независимым H₀. Он не проверяет
реалистичность швов при переносе чужого патча.

Это процедурные аналоги, не физическая симуляция трещин, ремонта или теней.
Выводы относятся к выбранным кропам принятых LoFTR-совмещений.
В отчёте сохраняется цепочка 210 пар → 179 экспортированных пар → 4918 кропов →
выбранные базы. Высокий порог пересечения дополнительно ограничивает область
выводов. Семантическая COCO-разметка не превращается в реальную временную
разметку; синтетические метрики не подменяют оценку реальных изменений.

После подготовки и короткого просмотра галереи можно подключать детекторы,
включая GeoSCD в последующем сравнении. Здесь они ещё не запускаются.
