# S192: OR, среднее и обучаемое объединение

Дата: 2026-11-06. Вход — завершённый canonical-history benchmark с семью методами
и PREVIOUS/EARLIEST/HISTORY. Старые карты, пороги, разметка и RGB не изменяются.

## Запуск

Из уже используемой среды benchmark:

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only origin codex/2026-10-24-main-workflow

python -s -u -m data_analysis history-fusion \
  --run /home/sasha/Facade_Change_Benchmark/runs/2026-11-04-s192-full-001 \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-11-06-s192-fusion-001 \
  --all-pairs --resume

```

Та же команда продолжает прерванный запуск. Завершённый вывод не перезаписывается.
Изменение входов, параметров или кода при resume требует нового --out.
Для новой даты запуска выбирайте новый датированный каталог.

Используются NumPy, SciPy и прежний semantic worker из конфигурации исходного run.
Никакой установки пакетов, скачивания весов или обучения базовых моделей нет.
При необходимости --semantic-device cpu или cuda:0 меняет только устройство
дополнительного семантического прохода.

## Что сравнивается

Все одиночные методы сохраняются как контроль. Для каждого из трёх режимов:

- AND и OR бинарных решений с исходными замороженными порогами;
- среднее исходных оценок [0, 1];
- среднее оценок, нормализованных по TRAIN-процентилям 1 и 99;
- logistic stacking по семи оценкам;
- тот же stacking с взаимодействиями оценок и предсказанных семантических групп;
- тот же stacking с взаимодействиями оценок и всех предсказанных классов.

Три обучаемых варианта также получают совместно 14 оценок PREVIOUS + HISTORY.
Это отдельная абляция дополнительной истории; новое состояние памяти не обучается.
EARLIEST оценивает тот же последний целевой переход, как в исходном прогоне.

Без --all-pairs рассматриваются шесть наборов компонентов: три прежних сочетания
AnyChange/Semantic DINO/MSDZip, LPIPS+DINOv2, LPIPS+DINOv2+Semantic DINO и все семь.
Это 105 вариантов. --all-pairs добавляет все 21 неупорядоченную пару: всего
24 набора компонентов, четыре правила, три режима, 21 одиночный контроль
и 12 обучаемых вариантов = 321 вариант.

При 11 классах и 5 группах полный отчёт содержит
321 × 3 split × (1 overall + 11 classes + 5 groups) = 16371 строку.
Это не полный перебор всех подмножеств семи методов.

## Семантический контекст

В прежних canonical-history pair maps не сохранялись вероятности классов.
Один дополнительный проход существующим замороженным Semantic DINO сохраняет
каждое RGB-наблюдение один раз, без истинных масок в inference.

Адаптер для одинаковых reference/source вычисляет вероятности один раз.
Проверяются прежние SHA-256 головы, backbone, дерево исходников backbone и
отображение category_id → channel. Категории переставляются в порядок текущего
датасета по ID, а не по случайной позиции канала.

Вероятности независимых sigmoid хранятся float16; это зафиксированная точность
нового контекста, исходные карты изменений не квантуются заново.
Контекст класса — максимум его предсказаний на концах пары:

- PREVIOUS: previous/current;
- EARLIEST: first/current;
- HISTORY и PREVIOUS+HISTORY: previous/current.

Поэтому EARLIEST не получает предыдущий снимок через семантическую боковую ветвь.
Для группы берётся максимум классов группы. Это мягкий признак присутствия,
не калиброванная вероятность объединения классов и не выбор по GT.

Семантические варианты добавляют признаки q и произведения score × q к общим
оценкам. Модель может изменять вес метода в зависимости от контекста; при слабом
контексте сохраняется общий линейный член. Итог остаётся бинарной картой изменения,
а не предсказанием имени класса.

Все вероятности, модели и гистограммы пишутся атомарными units через существующий
RunStore с SHA-256 и append-only events.jsonl. Для указанного исходного набора
потребуется 3313 семантических наблюдений; время не равно времени повторного
запуска семи методов. CPU-оценка всех сочетаний тоже занимает время.
Кэш вероятностей потребует дополнительного места; исходные файлы сохраняются.

## Обучение и оценка

Используется текущий фиксированный TRAIN/VAL/TEST. Нормализация и логистические
веса получают только TRAIN. До 4000 уникальных размеченных пикселей на здание
выбираются детерминированным равномерным reservoir sampling после объединения
пересекающихся кропов. Общий вес каждого здания одинаков; баланс классов искусственно
не меняется. --sample-per-building управляет объёмом.

Регуляризация L2 фиксирована до запуска: --l2 0.01, seed=13.
Это простой exploratory stacking на существующем split, не nested CV и не
out-of-fold переобучение исходного Semantic DINO.
TRAIN-метрики обучаемого fusion являются обучающей диагностикой.

VAL выбирает выходной порог каждого непрерывного варианта по среднему F1 зданий;
при равенстве — меньше FPR, затем выше порог. Одиночные методы и компоненты
OR/AND сохраняют исходные пороги. До оценки TEST записывается выбранный по VAL
вариант fusion. Все варианты на всех split всё равно выводятся.

Дополнительно сохраняются рабочие точки, выбранные по максимальному VAL recall
при среднем VAL FPR ≤ 5%. В отчёте показан фактический TRAIN/TEST FPR:
ограничение не навязывается через TEST-разметку. Бинарные методы не получают
фиктивную настройку — их единственная точка помечается как некалибруемая и
может превышать бюджет.

Флаги test_previously_inspected=true, происхождение checkpoint и
annotation-derived targets сохраняются как описание эксперимента, не блокируют
запуск. Независимость старых checkpoint автоматически не утверждается.

## Единая пространственная оценка

Все компоненты сначала объединяются по view/year transition на той же общей
поддержке, что раньше. Непрерывные пересечения усредняются, native AnyChange
объединяется OR. Только после этого применяются AND, OR, среднее или логистическая
модель. Противоречивые цели исключаются одинаково. Маска известной разметки не
используется как семантический признак.

TP/FP/FN/TN суммируются внутри здания. F1, IoU, precision, recall, FPR и AP затем
усредняются по зданиям; неопределённые знаменатели остаются NA. AP — прежняя
2049-биновая оценка; для бинарных AND/OR/AnyChange AP отсутствует.
Классы/группы означают локализацию изменений в размеченных областях этих классов.

Перед завершением проверяется точное совпадение TP/FP/FN/TN исходных методов
и трёх прежних AND-комбинаций; macro-метрики сравниваются с допуском 1e-10.
Несовпадение завершает анализ ошибкой вместо публикации несопоставимой таблицы.

Парный bootstrap повторно выбирает здания, а не кропы: 2000 повторов.
В comparisons есть сравнения с одиночным методом, выбранным на VAL,
семантические абляции и PREVIOUS+HISTORY против PREVIOUS.
Интервалы описательные: не исправляют многократные сравнения или выбор на VAL.
