# 2026-10-11 — единый анализ сохранённых карт и потерь Recall

## Решение

Пользователь задал приоритет Recall над F1/Precision и запросил общий анализ
MSDZip mod256, AnyChange, DINOv2, GeoSCD, RGB-DIFF и LPIPS на VAL и TEST,
по каждому фасаду и классу процедурного изменения. Код включён в пакет
`data_analysis`; отдельные архивы скриптов для следующих запусков не нужны.
Команда и описание выходных файлов: [data_analysis/README.md](../data_analysis/README.md).

Прежние решения не пересматриваются: исходные пороги и авторские бинарные
маски сохраняются. Единственное ранее выбранное объединение на TEST —
GeoSCD AND MSDZip. Другие OR/AND остаются диагностикой VAL, без поиска
новых TEST-правил. На TEST допустимо разобрать уже полученные ошибки всех
исходных методов, но такой разбор не превращает TEST в независимый финальный
набор для новых решений.

## Вопрос исследования

По представленному владельцем frozen-отчёту пересечение снизило TEST Recall
GeoSCD с 86.19% до 67.68%, при росте F1 с 71.41% до 77.26%.
Это потеря 18.51 процентного пункта Recall, поэтому выигрыш F1 сам по себе
не удовлетворяет новому приоритету. На marata_44 потеря Recall составляла
31.31 п.п. Эти числа взяты из предоставленного отчёта; здесь не выполнялся
повторный анализ реальных локальных карт.

Анализ отдельно считает сохранённые TP, отброшенные TP, удалённые FP и
прежние пропуски GeoSCD. Для всех пяти визуальных методов строятся четыре
группы GT-положительных и четыре группы GT-отрицательных пикселей относительно
MSDZip. Потеря Recall имеет знаменатель «все видимые GT-положительные
пиксели», доля отброшенных TP — «все TP исходного метода».

Причина порогового отбрасывания проверяется по сохранённому MSDZip score;
сопоставляются raw bpb, расстояние до порога, исходная RGB-разность, класс,
условие и граница GT-правки. Эти признаки характеризуют ошибки, а не доказывают
физическую или модельную причину. GT используется только после scoring.

## Воспроизводимость

- Повторный inference, кодирование и обучение не выполняются.
- Проверяются исходная выборка, хеши карт/данных, пороги, счётчики TP/FP/FN/TN
  и, при `--fusion-run`, точное совпадение прежнего frozen-результата.
- GT=255 исключается; uint8 RGB переводится в int16 перед вычитанием.
- Агрегация: средние случаев внутри физического фасада, затем равные веса фасадов.
- Галерея выбирает случаи по максимальной потере Recall для разбора ошибок;
  этот выбор не влияет на численные метрики или предсказания.
- Полные численные срезы включают оба split, каждый фасад, состояния,
  семейства условий и конкретные сценарии, независимо от лимита галереи.

Для будущего правила с приоритетом Recall критерий выбора следует фиксировать
на TRAIN/VAL: например, Recall при допустимом H0 FPR или бюджете инспекции.
Новые решения после изучения этих ошибок требуют свежей независимой проверки.
Текущий процедурный набор не оценивает реальные повреждения; доверительные
интервалы и научная новизна пересечения не заявляются.

## Проверки кода

Восемь самостоятельных CPU-тестов проходят, включая полный запуск на
независимо запечатанном наборе с шестью исходными методами и прежним
пятиметодным frozen-отчётом. Проверены потеря Recall 0.75 → 0.25, разные
знаменатели, GT=255, равные веса фасадов, строгий порог `>`, авторские маски,
неизменность входов и отказ при изменённых картах/контрактах/счётчиках.

Отдельный запуск настоящего CLI на 12 синтетических случаях завершён:
получены все CSV/JSON и 156 PNG, галерея осмотрена. Wheel собирается и
содержит весь пакет `data_analysis`. Реальные карты `/home/sasha/...`
проверяются указанной локальной командой; их модельные причины здесь
не установлены.

Общая проверка `python -s -B -m unittest discover -s tests -v`: 341 тест,
294 успешных, 46 пропущенных из-за необязательных зависимостей, один ERROR
в прежнем `test_benchmark_results`: `patch("torch.load")` требует PyTorch,
которого нет в этой CPU-среде. Эта ошибка окружения не выдана за зелёный suite.
OpenCV для существующих проверок установлен в отдельный временный каталог;
локальные conda-среды владельца не менялись.
