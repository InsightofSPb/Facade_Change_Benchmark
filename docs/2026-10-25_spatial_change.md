# Пространственные карты изменений и обучаемая история

Согласованный первый PR реализует pair, mean, ConvGRU и ConvGRU-last на готовых
пространственных DINOv2-признаках. Общий декодер выдаёт независимую карту для каждого
выбранного целевого класса. Сравнение включает бинарную DINO-разность и существующий
AnyChange. RGB, геометрия и аннотационные цели переиспользуются.

Это обнаружение изменения между последней парой при доступном текущем изображении.
Цели получены из различий аннотаций; они объединяют появление и исчезновение класса.
Это не прогноз будущего, не регрессия площади, не направленные C,V и не проверка H0/H1
через полную длину описания. Независимая разметка физических событий этим PR не создаётся.

## Модели и входы

| Режим | История | Назначение |
|---|---|---|
| pair | Последняя пара | Основной обучаемый baseline |
| mean | Пространственное среднее прошлых дат, с маской геометрической доступности | Простой контроль истории |
| convgru | Один ConvGRU по всем прошлым датам | Обучаемая пространственная память |
| convgru-last | Тот же ConvGRU только на предыдущей дате | Контроль числа параметров без ранних наблюдений |

Для всех режимов одинаковые замороженные DINO-токены, проекция в 32 канала по
умолчанию и общий двухслойный свёрточный декодер. Он получает предыдущую и текущую
карты, их знаковую разность, память, маски геометрической доступности и log1p
интервала последней пары. ConvGRU дополнительно получает log1p интервала обновления
и возраста наблюдения относительно текущего года. Текущий снимок в память не входит.
Геометрически недоступная позиция не обновляет память. Неизвестность GT не поступает
на вход модели. Геометрическая доступность не является видимостью за лесами/деревьями.

Единица выборки — префикс истории с минимум тремя разными годами. История привязана
к существующей канонической геометрии. Если в одном году несколько наблюдений,
выбирается лексикографически первое observation_id; это один и тот же снимок для
всех обучаемых моделей и RGB-baselines. Исходные альтернативы и консенсус целей
сохраняются. Другие наблюдения этого года в этом эксперименте не объединяются.

Берутся все экспортированные переходы выбранных split, для которых есть хотя бы
один известный пиксель выбранного класса внутри геометрии выбранной пары.
Старые бинарные label/review_status кропа не служат фильтром: полностью стабильные
кропы не обязательны, отрицательные пиксели берутся из class_targets == 0.
Полностью неизвестные переходы пропускаются и учитываются в coverage.json.
Выбранный класс без известных TRAIN-пикселей вызывает ошибку; используйте явный
--categories с поддержанными именами. Классы без положительных TRAIN-примеров
остаются видны в покрытии: их качество не доказывает обучение обнаружению.

--smoke-buildings N выбирает первые N building_id в лексикографическом порядке
отдельно в каждом split, сохраняя все их подходящие префиксы. По умолчанию 0:
ограничения нет. Это диагностический поднабор, не отбор лучших случаев. Числа
положительных/отрицательных/неизвестных пикселей по классам и split сохраняются в
coverage.json; эти предварительные числа включают перекрытие кропов.

## Получить пространственные токены

Если существующий кэш уже содержит patch_tokens, используйте его напрямую.
Если сохранены только pooled-векторы, создайте отдельный кэш:

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare history-features \
  --methods-config configs/history_features.local.json \
  --histories /home/sasha/Facade_Change_Benchmark/data/histories \
  --out /home/sasha/Facade_Change_Benchmark/data/2026-10-25-history-patches \
  --save-patch-tokens --device cuda:0 --batch-size 32 --trust-checkpoint
```

Не повторяются alignment, RGB-нарезка и перенос масок. Для нового кэша проверяются
тот же хеш канонического манифеста, тот же encoder contract (кроме save_patch_tokens)
и полный fingerprint каждого префикса с исходным encoder contract. Исходный индекс
признаков находится по хешу из history-targets; при переносе файлов его можно явно
задать через --target-features. Различия весов, preprocessing, устройства/точности
или исходного кода не обходятся автоматически. Старый кэш и targets сохраняются.

## Короткая проверка

Команды ниже выполняются из /home/sasha/Facade_Change_Benchmark. Если используете
другой сохранённый кэш, замените только --features. Имена выходных каталогов новые;
завершённый запуск не перезаписывается.

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow train spatial-change \
  --features data/2026-10-25-history-patches/index.json \
  --targets runs/2026-10-25-history-targets-001/index.json \
  --models pair mean convgru convgru-last \
  --smoke-buildings 1 --epochs 2 --batch-size 4 --hidden 32 --device cpu \
  --out runs/2026-10-25-spatial-smoke-train-001

conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow benchmark spatial-change \
  --features data/2026-10-25-history-patches/index.json \
  --targets runs/2026-10-25-history-targets-001/index.json \
  --training-run runs/2026-10-25-spatial-smoke-train-001 \
  --smoke-buildings 1 --splits val --baselines dino-difference rgb_diff \
  --device cpu --bootstrap 0 --gallery-limit 8 \
  --out runs/2026-10-25-spatial-smoke-val-001
```

Ожидаются models.json, checkpoints и metrics.json после обучения; maps/*.npz,
metrics-val.json, calibration.json и gallery.html после оценки. CPU-фикстура
проверяет обучение, resume, метрики и галерею, но не является результатом на фасадах.
AnyChange проверяется отдельно с реальными локальными SAM-весами.

GitHub CPU CI запускает весь набор через `scripts/audit_environment.py --run-tests`.
Лимит полного набора — 900 секунд (`--test-timeout` меняет его явно); прежних
60 секунд уже недостаточно. Необязательные Torch/codec-тесты в минимальной среде
могут быть пропущены: число и причины остаются в отчёте и tests.log. Ошибки,
таймаут, пустой или полностью пропущенный набор завершают аудит с ошибкой.
При таймауте сохраняется частичный вывод. Успех минимального CI не подтверждает
работу пропущенных моделей; пространственный CPU smoke выполняется отдельно
в существующей среде с Torch.
CPU requirements включают `tqdm` для подготовки кропов, `pycocotools` для
проверки COCO RLE и SciPy для экспорта атласа: установка проекта в CI использует
`--no-deps`. Проверка
переиспользования сохранённых карт запрещает импорт необязательного Torch.

## Основное сравнение

Прогресс показывается с начала проверки данных: метаданные историй, загрузка
последовательностей, проверка пространственных признаков и целевых масок.
При обучении вложенные tqdm показывают методы, эпохи текущего метода и текущую
фазу: TRAIN по обработанным примерам, VAL по переходам вида между двумя годами
после объединения перекрывающихся кропов. Видны прошедшее время, ETA и текущий
средний TRAIN loss; после VAL обновляются F1 и номер лучшей эпохи.
Ранняя остановка выводится явно, без фиктивного заполнения оставшихся эпох.
При resume счётчик эпох начинается с сохранённого checkpoint. Итоговая строка
каждой эпохи и журнал events.jsonl сохраняются. Обновление предназначено для
следующего запуска; текущий процесс продолжает выполнять загруженную версию.

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow train spatial-change \
  --features data/2026-10-25-history-patches/index.json \
  --targets runs/2026-10-25-history-targets-001/index.json \
  --models pair mean convgru convgru-last --device cuda:0 \
  --epochs 40 --patience 8 --batch-size 8 --hidden 32 --seed 42 \
  --out runs/2026-10-25-spatial-train-001

conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow benchmark spatial-change \
  --features data/2026-10-25-history-patches/index.json \
  --targets runs/2026-10-25-history-targets-001/index.json \
  --training-run runs/2026-10-25-spatial-train-001 \
  --splits val --baselines dino-difference anychange \
  --methods-config configs/methods.local.json --trust-checkpoint --device cuda:0 \
  --bootstrap 500 --out runs/2026-10-25-spatial-val-001
```

Обучение использует masked multilabel BCE + positive-class soft Dice; 255 исключён.
Вес кропа обратно пропорционален числу подходящих кропов здания, чтобы здания
имели одинаковый суммарный вес. Это баланс обучения, не отмена корреляции кропов.
Checkpoint выбирается по VAL macro-building F1 при фиксированном пороге 0.5.
После выбора отдельно калибруются пороги каждого класса и бинарного max-class score.
Если на VAL у класса нет известных положительных или отрицательных пикселей,
оставляется 0.5 с явной причиной. Ни checkpoint, ни пороги на TEST не выбираются.

Прерванный запуск продолжается той же командой с --resume: проверяются конфигурация,
исходники и входные хеши. Завершённый запуск неизменяем. Модели, карты и пороги
сохраняются; повторный benchmark с --resume переиспользует завершённые карты.
Изменение параметров или данных требует нового --out.

## Метрики и границы интерпретации

Предсказания перекрывающихся кропов сначала объединяются в общей системе координат
для каждого (building_id, view_id, previous_year, current_year), затем каждый пиксель
этого перехода учитывается один раз. Непрерывные оценки усредняются без обращения
к GT; native binary masks объединяются OR. Разногласие известных GT в перекрытии
останавливает оценку. Обработка блоками 256×256 не требует полного холста в памяти.

TP/FP/FN суммируются по переходам здания; метрики зданий усредняются с равными
весами. Выдаются F1, IoU, precision, recall по классам и зданиям, macro-значения,
покрытие и парный bootstrap разности с pair. Bootstrap пересэмплирует здания;
он не учитывает неопределённость от обучения с разными seeds. При нулевом
знаменателе метрика null, а не автоматически 1.

AUPRC сохраняется как auprc_binned: step average precision после равномерной
квантизации score в 1024 уровня, без усреднения AP отдельных кропов. Это явно
приближённая метрика, рассчитанная отдельно по зданиям; без положительных пикселей
она неопределена. Порог выбирается на той же сетке. Полные float32 карты сохраняются
и позволяют позже пересчитать точную AP. AnyChange native mask получает F1/IoU/
precision/recall при собственном решении, а auprc_binned=null.

Бинарная цель положительна, если хотя бы один выбранный класс достоверно изменился.
Отрицательна, только если все выбранные классы известны и неизменны. Остальное
неизвестно. AnyChange и DINO-разность сравниваются на этом бинарном результате;
поклассовые числа им не приписываются. Бинарный выход обучаемых моделей —
отдельно калиброванный максимум вероятностей классов.

На TEST нужны отдельно экспортированные TEST targets и --splits test.
Для непрерывных baseline обязательно --calibration-run runs/2026-10-25-spatial-val-001.
Метод, версия/веса и словари должны совпадать с VAL. Метаданные всех split могут
проверяться на leakage, но TRAIN/VAL не декодируют TEST изображения, токены и маски.

Галерея использует одинаковые примеры для всех методов, выбранные по кругу из
зданий и переходов. Показывает всю доступную историю, поклассовые цели и прогнозы,
а также общий бинарный результат. Серым отмечен unknown. Повторная галерея без
инференса: workflow gallery spatial-change --evaluation-run RUN --out NEW_DIRECTORY.

Ограничения: текущие признаки имеют шаг 14 пикселей; увеличение карты не восстанавливает
тонкие контуры. Неизвестная область не является здоровым фоном. Полная история
может переносить устаревшее состояние через ремонт; автоматического reset нет.
Изменённые history_start_year без отдельно валидированного экспорта не принимаются.
Качество на производных целях не доказывает полноту всех физических изменений.

## Дополнительные карты и OVS

--auxiliary принимает JSON schema 1 с kind=spatial_auxiliary_maps,
history_manifest_sha256, source_kind=prediction или rgb_derived,
source={id,revision,...}, channels и observations.
Каждый channel содержит уникальные id/name и kind=context или signal.
Порядок каналов и source фиксируются в checkpoint независимо от target_categories.

observations сопоставляет observation_id с {path,sha256,rgb_sha256,support_sha256,
bbox_xywh,grid}. grid равен patch или rgb. NPZ содержит values[C,H,W] и
available[C,H,W] типа bool. Native RGB-карты должны иметь точную геометрию кропа:
значения усредняются по патчу, availability требует доступности всего патча.
Отсутствующая запись даёт available=False, а не предсказание отсутствия объекта.
GT-карты не являются допустимым источником контекста.

Контекст хранится плотными каналами, без uint16 bitset и лимита 16 категорий.
В тесте 20 контекстных каналов не меняют два целевых канала. Новый словарь не
подключается молча к старому checkpoint: нужен совместимый адаптер/новое обучение.
OVS-инференс этим PR не добавлен; поддержан проверяемый вход предсказанных карт.

## Следующие независимые изменения

Гессиан/Frangi: отдельные многомасштабные пространственные признаки через signal-вход.
Гипотеза — рост полноты изменений трещин без роста FP на швах, проводах и границах.
Проверить ту же модель с сигналом и без него на фиксированном VAL; при отсутствии
устойчивой пользы не развивать ветку. RGB для alignment и MSDZip остаётся исходным.

SET: Learning Spectral-Decomposed Tokens for Domain Generalized Semantic Segmentation,
ACM MM 2024, https://arxiv.org/abs/2407.18568 и https://doi.org/10.1145/3664647.3680906.
В оригинале FFT применяется к промежуточным VFM-признакам; амплитуда и фаза
обрабатываются раздельными обучаемыми токенами, затем IFFT возвращает признаки
в пространственную область для следующего слоя. Это не Fourier positional encoding
и не простое добавление RGB-FFT. Амплитуда/фаза не тождественны низким/высоким частотам.

Для следующего PR: начать с отключаемого spectral feature adapter перед общей
проекцией/модулем истории (сейчас feature_adapter=Identity). Вариант поверх конечного
кэша DINO явно называть SET-inspired, не воспроизведением SET: полноценные вставки
между слоями требуют повторного forward backbone, даже при замороженных его весах.
Сравнить базу, обычный адаптер сопоставимой ёмкости и spectral adapter при одинаковом
декодере/истории. Гипотеза — меньше nuisance FP при сохранении recall реальных
изменений. Риски: потеря важных цветовых/текстурных изменений, чувствительность фазы
к сдвигам и краям кропа. Не удалять амплитуду целиком и не смешивать этот тест с
одновременной заменой OVS/детектора. Стоп: нет воспроизводимой пользы на VAL либо
подавляются реальные повреждения ради меньшего числа срабатываний.

Следом отдельно подключаются один реальный OVS-источник, дополнительные детекторы
через существующий methods registry, MSDZip как карта evidence, Transformer /
recursive block и MoE-декодер. Каждый меняет один компонент при общей подготовке
и оценке. Это не обещание выигрыша и не обязательство запускать все комбинации.
