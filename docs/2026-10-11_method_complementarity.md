# Дополнение MSDZip к AnyChange, DINOv2 и GeoSCD

> Историческая инструкция, сохранённая из локального архива 2026-10-24.
> Упомянутый самостоятельный скрипт заменён [пакетом data_analysis](../data_analysis/README.md)
> и командой `python -m facade_change workflow gallery comparison`.
> Команды и числа ниже относятся к прежнему исследовательскому запуску;
> они не являются результатом повторного benchmark при переносе кода.

Скрипт `scripts/analyze_method_complementarity.py` анализирует сохранённые
карты `msdzip_mod256` вместе с `anychange`, `dinov2` и `geoscd`. Повторного
инференса, обучения, GPU-работы и загрузки весов нет. Все четыре метода должны
присутствовать в полном завершённом локальном H0/H1 benchmark.

Для текущего прогона доступны 18 VAL-случаев / 3 фасада. TRAIN отсутствует;
TEST не заменяет TRAIN и не участвует в численном анализе. Проверка целостности
всего исходного запуска хеширует также TEST-артефакты и читает их метаданные.

## Запуск

Архив содержит только три новых файла: скрипт, его тесты и эту инструкцию.
Распакуйте его в существующий корень `Facade_Change_Benchmark`. Совместимость
проверена по исходникам commit `9509ea713245695403a4bb974cec033d7b2d89dd`.
Зависимости — имеющиеся NumPy и Pillow, новые пакеты не требуются.

```bash
cd /home/sasha/Facade_Change_Benchmark
conda activate scd_bench
FC_ERROR_TAG="$(date -u +%Y%m%dT%H%M%SZ)"
python -u -s scripts/analyze_method_complementarity.py \
  --run "$PWD/runs/20261010T131625089776Z-neural-codecs-comparison" \
  --out "$PWD/runs/${FC_ERROR_TAG}-msdzip-complementarity"
```

По умолчанию запрашиваются TRAIN и VAL. Недоступные части явно записываются
в отчёт; для этого прогона анализируется только VAL. `--splits val` позволяет
запросить только VAL. TEST не разрешён. `--gallery-limit 12` задаёт максимум
показанных диагностических случаев, не уменьшает численную выборку.

## Что измеряется

Порог каждого метода берётся из исходного `threshold_selection.json`.
Применяется прежнее строгое `score > np.float32(threshold)`. Штатные маски
AnyChange и GeoSCD сохраняют авторские решения. Нет новой нормализации карт.
Числа TP/FP/FN/TN воспроизводятся и сверяются с исходным benchmark.

Для каждой пары методов положительные и отрицательные пиксели отдельно
делятся на четыре группы: оба, только MSDZip, только визуальный метод, никто.
Пиксели GT=255 игнорируются только оценивателем.

- `added_recall`: MSDZip-only TP / все видимые положительные пиксели H1.
- `rescued_baseline_misses`: MSDZip-only TP / пропуски визуального метода H1.
- `added_precision_h1`: MSDZip-only TP / все добавляемые пиксели H1.
- `extra_h0_fpr`: MSDZip-only FP / отрицательные пиксели H0.
- `extra_h1_fpr`: MSDZip-only FP / отрицательные пиксели внутри H1-случая.
- `and_lost_recall`: baseline-only TP / все видимые положительные пиксели H1.
- `and_removed_h0_fpr`: baseline-only FP / отрицательные пиксели H0.

При нулевом знаменателе доля неопределена (`null`), а не ноль. Число фасадов,
входящих в каждое среднее, отражено в `metric_building_counts`. Precision добавок
и доля спасённых пропусков поэтому могут быть условными средними.
Абсолютные пиксельные числа — диагностика, не независимые наблюдения.
Основные доли усредняются сначала по случаям внутри фасада, затем поровну
между фасадами. TRAIN и VAL не смешиваются. Есть срезы по фасаду, состоянию,
семейству условий и конкретному сценарию.

Дополнительно оцениваются фиксированные OR и AND от исходных решений.
OR автоматически не уменьшает Recall/FPR, AND автоматически не повышает их.
Сами эти изменения не доказывают полезность объединения. Веса, правила
обучаемой комбинации и новые пороги здесь не подбираются. VAL уже участвовал
в калибровке исходных порогов: это скрининг гипотезы, не независимый fusion test.

## Выходы

- `summary.txt`, `summary.json`: исходные методы, OR/AND и дополнение по фасадам.
- `pairs.csv`: восемь групп ошибок и диагностические доли для каждой пары методов.
- `metrics.csv`: прежние основные метрики каждого исходного/объединённого решения.
- `gallery.html`: автономная галерея RGB, истинных масок и верных/ложных добавок.
- `selected_cases.json`, `input_artifacts.json`, `run.json`: выборка, прежние пороги,
  хеши исходных артефактов, скрипта, среды и конечный статус.

Исходные benchmark/dataset не изменяются. Выходной каталог должен быть новым.
Проверки используют существующие `ReuseResults`, `_parent`, `_case_inputs`,
`replay_selection`, `_metrics_from_counts` и `_building_macro` проекта.

## Проверка реализации

```bash
python -s -B -m unittest discover -s tests -p test_method_complementarity.py -v
```

10 CPU-тестов прошли на синтетическом завершённом dataset/benchmark с двумя
непересекающимися VAL/TEST-фасадами. Проверены ручные расчёты, GT=255, штатные
маски, строгое сравнение с порогом, веса фасадов, неизменность исходных файлов,
отказ при изменении score/hash, несогласованных исходных counts, утечке split,
запросе TEST и повторном использовании выходного каталога. TEST-карты и GT
не входят в численные расчёты. Это проверка кода, не результат на реальных данных.
