# Независимое сравнение совмещений, 2026-10-03

На компьютере владельца завершён аудит COCO из 361 изображения: все файлы готовы,
282 наблюдения имеют подтверждённые метаданные, 79 исключены из временных пар
из-за отсутствия вида/года. Подготовлены 210 соседних временных пар. Две аннотации
с сохранённым area <= 0 исключены в рабочей копии; осталось 17596 аннотаций.

Первый gold-запуск создал reviewed-разбиение, затем был прерван во время кропов.
SIFT прошёл геометрические пороги на первых трёх парах. На Antonenko8 каскад
отклонил SIFT из-за пересечения проективного горизонта с изображением, а LoFTR
завершился ошибкой запроса памяти с неиндексированным устройством cuda.
Это частичный запуск, а не законченная проверка качества на всех фасадах.

После уточнения владельца политика по умолчанию изменена на first-anchor:
каждый поздний снимок совмещается напрямую с самым ранним пригодным снимком
того же view_id. Ранний снимок выбирается среди изображений текущего COCO.
При нескольких снимках самого раннего года опора выбирается стабильно по
очищенному имени, затем SHA-256; числовой COCO ID на выбор не влияет.
Все наблюдения сохраняются в манифесте и разбиении, одногодичные временные
пары не создаются. Старый adjacent остаётся доступным явно.

Для следующего запуска пересобираются только пары из уже созданного
prepared/manifest.json с previous-split на текущий gold split.json.
Назначения зданий и исходный gold-состав сохраняются, RGB не декодируются.
SIFT и LoFTR запускаются независимо на одинаковых новых парах с одинаковыми
порогами и пределом grayscale-прокси. Полноразмерные RGB получаются из оригиналов.
Папки методов разделены: sift/pair-*/ и loftr/pair-*/. Галерея и таблица общие.
Дополнительные кропы и контролируемые варианты на этом этапе не создаются.

LoFTR разрешает cuda в текущий cuda:N до запроса памяти и переноса модели.
Явный индекс не меняется, автоматического перехода на CPU нет. Регрессия
проверяется без GPU с имитацией старого CUDA API; реальный повторный CUDA-прогон
предстоит выполнить владельцу. Веса и среда не обновляются.

В отчёте сохраняется число прошедших геометрические пороги, отклонённых,
ошибочных и не начатых пар по методу, с общим знаменателем выбранных пар.
Дополнительно считаются пары, где пороги прошли оба метода, только SIFT,
только LoFTR или ни один. Пары с незавершённой попыткой выделяются отдельно.
Число соответствий и inliers каждой попытки остаётся в results.csv.
Отчёт обновляется во время расчёта; итоговое плотное совмещение требует
визуальной проверки. Эти количества не измеряют качество обнаружения изменений.

Третий самостоятельный подход из плана — GeoSCD. В проекте есть описание его
назначения, но нет адаптера или результатов пробного запуска. Он не включён
в текущую команду. После двух независимых прогонов сравниваем результаты и
выбираем геометрию для кропов, сохраняя ранее созданное разбиение.

Если поздний кадр шире раннего, объединённый холст сохраняет дополнительную
область в source_rgb.png и отмечает её в source_only.png. В опорном RGB на
этом месте нет наблюдения: нулевое заполнение помечено reference_support.png.
Временные оценки рассчитываются только на overlap.png; вне него residual
равен нулю, а числовая RGB-разность — NaN. В overlay дополнительные области
показаны серым; checkerboard сохраняет видимую часть позднего кадра.
Кропы для парного сравнения требуют не менее 80% общего поддержанного поля;
полностью source-only кропы пока не экспортируются. Сохранённый холст и
reference_to_canvas рассчитываются для каждой пары отдельно; общий атлас
всей последовательности не создаётся.
