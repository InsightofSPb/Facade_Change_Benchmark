# Уточнение совместимости по локальному аудиту lposs

Отчёт владельца от 2026-09-27 показал Python 3.9.23, NumPy 1.26.4, Pillow 11.1.0,
импорт cv2 4.12.0 при метаданных opencv-python 4.7.0, Torch 1.12.1 и Kornia 0.8.1.
NumPy/Pillow/OpenCV и класс LoFTR импортировались. Проверка Torch прошла импорт и
обмен с NumPy, но завершилась на assert о наличии weights_only до опроса CUDA.
Следовательно, прошлый отчёт не проверял CUDA через PyTorch. Вывод nvidia-smi сам
по себе не доказывает выполнение GPU-операций этим Torch.

Порог Python >=3.10 был ограничением начального проекта, а не наблюдаемой ошибкой
его CPU-кода. В отдельной среде сборки воспроизведены Python 3.9.23, NumPy 1.26.4,
Pillow 11.1.0 и cv2 4.12.0 (wheel opencv-python-headless 4.12.0.88). Все 18 тестов
прошли без пропусков, включая синтетическое выравнивание SIFT. Это не полная копия
lposs: PyTorch/Kornia/GPU и сборка OpenCV владельца в этой проверке отсутствовали.
Пакеты локальной среды владельца не менялись.

Изменения: minimum Python снижен до 3.9; аудит проверяет импорт самого проекта,
разделяет работоспособность Torch и поддержку загрузчика checkpoint; отсутствие
weights_only не скрывает сведения о CUDA. Сам LoFTR-загрузчик продолжает требовать
weights_only=True и теперь выдаёт понятную ошибку до чтения checkpoint.
Добавлены две регрессионные проверки с имитацией старого API Torch; это тесты
отчётности, а не запуск реального Torch 1.12.1 или LoFTR.

OpenCV в выравнивании теперь фиксируется также по cv2.__version__, поскольку
метаданные установленного дистрибутива могут расходиться с импортированным модулем.
Причина расхождения в lposs пока не установлена; автоматическая переустановка не выполняется.

Следующий локальный шаг: обновить код, повторить аудит в env-lposs-002, затем строить
манифест COCO при успешных CPU-тестах. Для LoFTR отдельно проверить scd_bench и совместимость весов.
