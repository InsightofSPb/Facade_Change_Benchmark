# Первый CPU-прогон RGB-diff и SSIM на H₀/H₁

Этот запуск проверяет весь путь от готовых вариантов до карт, порогов и метрик.
Он относится к процедурным правкам; реальные изменения между годами и полная
модель условной длины описания здесь не оцениваются.

## Команда

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
conda activate lposs

python -B -m facade_change h0h1-benchmark \
  --dataset-run runs/2026-10-04-h0h1 \
  --methods rgb_diff ssim \
  --max-bases-per-split 1 \
  --out runs/2026-10-04-h0h1-smoke

cat runs/2026-10-04-h0h1-smoke/summary.txt
```

Выходной каталог должен быть новым. На текущем наборе выбирается по одному
опорному кропу из train, val и test — 3 базы × 72 варианта = 216 случаев,
каждый проверяется двумя методами. Отбор фиксируется по SHA-ранжированию до
расчёта карт и просмотра GT. Оба метода получают одинаковые случаи.
Существующие кропы, аугментации и split не меняются; LoFTR не запускается.
Модели, новые веса и GPU для этих двух методов не нужны.

## Два метода

`rgb_diff` — среднее по каналам абсолютное RGB-различие, делённое на 255.
Вход — сохранённый uint8 RGB на исходной решётке; цветовое пространство —
encoded sRGB. Карта лежит в диапазоне [0, 1].

`ssim` — локальный SSIM по каждому RGB-каналу с последующим средним.
Используются Gaussian-окно 11×11, σ=1.5, нормированные population moments,
C₁=0.01² и C₂=0.03² для RGB/255. Карта изменения равна `(1 − SSIM) / 2`
и ограничивается диапазоном [0, 1]. Основная формула и параметры приведены
в [Wang et al., 2004](https://ece.uwaterloo.ca/~z70wang/publications/ssim.pdf).
RGB-усреднение, карта исходного размера и перенормирование весов по
геометрической поддержке — явно заданная адаптация для наших кропов.

Оба scorers получают только два RGB и геометрическую поддержку опорного кропа.
Истинные маски изменений, nuisance, source occlusion и известная видимость
им не передаются. Вне опорной поддержки float32-карта содержит NaN.
Маски `labels_reference` используются отдельно в оценке: 0 — нет правки,
1 — внесённая правка, 255 — пиксель исключается. Таким образом, известная
процедурная окклюзия ограничивает оценку видимых изменений, а не помогает
самому методу определить область перекрытия.

## Порог и метрики

Для каждого метода выбирается один порог из фиксированной сетки 0…1
с шагом 0.01; положительный пиксель — `score > threshold`.
Кандидаты хранятся в float32; точные значения фиксируются в отчёте,
а подбор порога и сохранение предсказаний используют одинаковое сравнение.
Выбор выполняется **только на val** по максимальному building-macro F1
для видимых H₁. При равном F1 предпочтение получает меньший H₀ pixel FPR,
затем больший порог. Один выбранный порог применяется ко всем частям,
типам правок и условиям. Test не участвует в подборе.
Это F1-optimal порог: фиксированный допустимый FPR таким подбором не
обеспечивается, поэтому ложные срабатывания H₀ всегда показываются отдельно.

- Для H₁ показываются F1, IoU, precision и recall локализации правки.
- Для H₀ показывается доля ложноположительных пикселей (pixel FPR).
- `self_paste` сохраняется в отдельном контрольном отчёте; дубли unchanged
  не входят в подбор порога и основные H₀-метрики.
- Полностью скрытая H₁ исключается из оценки recall видимых правок и
  остаётся в учёте покрытия. Пиксели 255 не превращаются в отрицательные метки.
- Сначала усредняются метрики случаев внутри здания, затем поровну по зданиям.
  Приводятся срезы по состоянию, nuisance и конкретному сценарию.

Один test-кроп из одного здания проверяет работоспособность и позволяет
найти явные ошибки. Это не достаточный объём для уверенного сравнения методов;
доверительные интервалы для такого smoke-прогона не объявляются.

## Результаты

`summary.txt` и `summary.json` содержат выбранные пороги, размеры выборки
и сводные метрики. `metrics.json`/`metrics.csv` сохраняют результаты отдельных
случаев, `threshold_selection.json` — подбор на val, `selection.json` —
использованные базы и случаи. `gallery.html` показывает ограниченный набор
карт и масок предсказаний. Float32-карты сохраняются в NPY; PNG используются
для просмотра. Индекс и `run.json` связывают результаты с хешами входов,
конфигурацией и реализацией метода.

Для просмотра через WSL:

```bash
cd /home/sasha/Facade_Change_Benchmark/runs/2026-10-04-h0h1-smoke
python -m http.server 8766 --bind 127.0.0.1
```

В Windows-браузере открой `http://localhost:8766/gallery.html`.
Сначала посмотри чистую правку, H₀ с сильной тенью и правку с перекрытием.

После проверки smoke-прогона полный запуск на уже созданных 5328 вариантах
задаётся `--max-bases-per-split 0` с новым `--out`. Его можно использовать для
первого сравнения этих двух baselines по зданиям; результаты всё ещё относятся
к выбранной процедурной постановке. Другие методы и компрессионный scorer
подключаются следующим отдельным шагом.
