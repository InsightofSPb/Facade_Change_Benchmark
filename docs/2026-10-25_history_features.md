# Канонические истории кропов и frozen DINOv2

Следующий этап после сравнения выравниваний: получить последовательности
`(z_t, year_t, delta_years_t, support_t)` одного участка фасада. Здесь `z_t` —
384-мерный frozen DINOv2-признак снимка. Обучаемый эмбеддинг всей истории `h`
будет следующим экспериментом; этот модуль его не обучает и не создаёт GT событий.

## Почему нужен отдельный индекс историй

Папка `data/crops/pairs` содержит кропы пар. Холст и начало координат могут
различаться между парами: одинаковый номер кропа ещё не обозначает одно место.
`facade_change.history_features` читает сохранённые гомографии из сессии
`dataset_statistics.py`, переносит оригинальные RGB непосредственно в координаты
самого раннего снимка каждого `(building_id, view_id)` и нарезает общую сетку.
Повторный запуск SIFT/LoFTR/GeoSCD не нужен. Проверку сессии и H выполняют
существующие `alignment_session.load_session` и `saved_geometry.frame_geometry`;
новый этап доступен через основной `workflow prepare`. Прямой вход
`python -m facade_change.history_features prepare/embed` также сохранён.

Договорённости:

- Основной метод выравнивания — LoFTR + RANSAC. Сборщик уважает сохранённый
  `selected_method` каждой пары; автоматически сравнивать/перевыбирать методы он
  не будет. Прямые сохранённые SIFT/LoFTR-гомографии совместимы.
- GeoSCD с плотным полем требует отдельного адаптера общего атласа. Такая выбранная
  пара явно исключается с причиной, а не подменяется другим методом.
- Опора — самый ранний **год** вида; при нескольких снимках этого года сначала
  выбирается минимальный строковый `image_id`. Ранее выбранная опора сохраняется,
  пока она присутствует среди снимков самого раннего года. Опора не считается здоровой.
- Каждый последующий снимок идёт прямо в опору. Отсутствующий прямой H не заменяется
  композицией цепочки. Canny/cycle/drift остаются диагностикой выравнивания; ссылка
  на каталог исходных quality-отчётов сохраняется в манифесте.
- Сетка 224×224 с шагом 112, исходный масштаб опорного снимка, без resize и EXIF.
  Начало сетки закреплено в `(0, 0)` опоры; отрицательные координаты допустимы.
  Новые доступные области расширяют атлас, не перемещая старые кропы.
- Кроп сохраняется при геометрической поддержке ≥80% отдельно для каждого снимка.
  Пересечение поддержки **всех** дат не требуется. Однолетние участки также остаются
  в RGB-манифесте; `embed` по умолчанию выбирает истории минимум с двумя годами.
- Поддержка учитывает геометрию, alpha и интерполяцию. Чёрный RGB может быть валиден;
  деревья/леса/машины этой маской не распознаются.
- Снимки одного года сохраняются как альтернативы. Другие снимки самого раннего
  года пока помечаются как невыравненные: межгодовой манифест не содержит нужных
  внутригодовых пар. Новые даты и пропуски не выдумываются.
- Идентичные исходные байты внутри одной истории не дублируются. Конфликт года или
  принадлежности для одинакового SHA-256 останавливает подготовку.
- Split берётся из существующего манифеста. Проверяются building/view/SHA-пересечения
  представленных временных изображений. Дополнительные неизвестные семантические
  TRAIN-снимки сюда не входят и этим аудитом не проверяются.

## Локальный запуск

Из корня рабочей ветки, после завершения ранее запущенных процессов:

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
```

Сначала короткая проверка на двух видах:

```bash
cd /home/sasha/Facade_Change_Benchmark
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare crop-histories \
  --alignment-session data/aligned/sessions/report-1 \
  --quality-report data/aligned/sessions/report-1/quality/report-2 \
  --out data/histories_smoke \
  --limit-views 2
```

Проверить `data/histories_smoke/summary.json` и `gallery.html`: один участок должен
оставаться на месте во все годы. Диагностика не требует новой разметки; будущая
оценка событий потребует проверенных меток изменения.

Извлечение признаков для этого же небольшого набора:

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare history-features \
  --histories data/histories_smoke \
  --device cuda:0 \
  --batch-size 32 \
  --trust-checkpoint
```

Используется секция `methods.dinov2` из `configs/methods.local.json`, если файл есть,
иначе из `configs/methods.example.json`. Обязательные пути: `source_root` и
`checkpoint_path`; `worker_python` задаёт отдельный интерпретатор DINOv2. Поэтому
активация окружения верхнего скрипта не меняет среду модели. Для другого конфига
есть `--methods-config /absolute/path/config.json`, для другого интерпретатора —
`--worker-python /absolute/path/bin/python`. Относительные пути в конфиге относятся
к его каталогу. Веса и исходники должны уже находиться локально. `--trust-checkpoint`
разрешает существующему загрузчику legacy-загрузку доверенного checkpoint; без
этого флага используется только ограниченная загрузка.

После проверки малого набора — полный набор в постоянном каталоге данных:

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare crop-histories \
  --alignment-session data/aligned/sessions/report-1 \
  --quality-report data/aligned/sessions/report-1/quality/report-2 \
  --out data/histories

conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare history-features \
  --histories data/histories \
  --device cuda:0 \
  --batch-size 32 \
  --trust-checkpoint
```

`workflow prepare crop-histories --plan-only` проверяет сохранённые геометрии и метаданные, не создавая RGB.
`--device cpu` подходит для проверки без GPU. На GPU перед загрузкой показываются
процессы и свободная память; процесс не останавливает другие задачи. При OOM
повторить с меньшим `--batch-size`: завершённые признаки останутся в кэше.

Для сессии с конечным `failed` после ошибки quality worker нужен явный
`--quality-report` с завершённым повторным отчётом. Общий загрузчик проекта проверяет
блокировку остановленного preparation, SHA манифеста, review, дочерних run.json и
геометрии, а также соответствие quality-снимку. Исходный статус сессии сохраняется.
Активная сессия, plan-only или несовместимые данные не принимаются. Противоречие
между CSV review и сохранённой выборкой требует сначала применить review через
существующий `dataset_statistics.py`.

## Что сохраняется

| Путь относительно `data/histories` | Содержимое |
|---|---|
| `manifest.json` | Текущий индекс видов, опор, кроп-историй, наблюдений и геометрии |
| `summary.json` | Покрытие ≥2/3/4 лет, здания/виды, причины исключений, reuse |
| `gallery.html` | Галерея до 60 историй с распределением по зданиям |
| `observations/<content-key>/` | Неизменяемые RGB PNG, support PNG и маркер наблюдения |
| `reports/prepare-N/` | Неизменяемая попытка: run.json, config, plan, leakage_check, manifest, events.jsonl |
| `features/index.json` | Текущий индекс frozen-признаков и последовательностей |
| `features/summary.json` | Сколько признаков создано/переиспользовано, длины историй |
| `features/observations/<content-key>/` | Кэш признака отдельного кропа и support |
| `features/reports/embed-N/` | Конфиг, fingerprint модели, журнал, последовательности, снимок индекса |

Верхние индексы заменяются после успешной подготовки; предыдущие снимки индексов,
изображения и признаки остаются в неизменяемых каталогах. Новый запуск создаёт новую
попытку в `reports`, а не переименовывает результат старой. Прерывание сохраняет
завершённые единицы кэша; повтор той же команды их проверяет и переиспользует.
Повреждённый кэш не затирается.

Ключ RGB зависит от SHA оригинала и опоры, H, параметров сетки, реализации и версий
рендеринга. Новый год с той же опорой не меняет старые ключи. Новый более ранний
снимок требует другой опоры и новых кропов. Изменение реализации/параметров также
создаёт новую ревизию кэша. Если поступили новые фотографии, сначала обновить
входной manifest/сессию выравниваний, затем повторить эти команды.

## Представление DINOv2

Используется существующий загрузчик оригинальной ViT-S/14: `pretrained=False`,
строгая загрузка локального checkpoint, `eval()`, замороженные веса и
`inference_mode()`. Вход — нативный RGB-кроп, без resize и аугментации, с ImageNet
нормализацией. Недоступные пиксели заполняются средним ImageNet только на входе
модели; сохранённые RGB не меняются.

Основной `z` — среднее `x_norm_patchtokens` по полностью поддержанным блокам 14×14
с последующей L2-нормализацией. CLS сохраняется отдельно для диагностики.
`--save-patch-tokens` дополнительно сохраняет исходные токены float16; это увеличит
объём кэша. Сами эмбеддинги и inference — float32, TF32 отключён.

Mask применяется при заполнении входа и pooling, но не является attention mask
внутри DINOv2: поддержанные токены всё равно могут зависеть от контекста недоступных
участков. Это ограничение надо учитывать при сравнении кропов с разным покрытием.

В NPZ каждой истории:

- `z_observations [N,384]`, `observation_ids [N]`, `observation_years [N]` — все снимки;
- `z_years [T,384]`, `years [T]`, `year_counts [T]` — L2-нормированное среднее
  альтернатив каждого года;
- `delta_years [T]` — `[0, year_1-year_0, ...]`;
- `elapsed_years [T]` — годы от начала наблюдаемой истории данного участка.

Для 2009, 2013, 2020 получатся интервалы `[0,4,7]` и возраст `[0,4,11]`.
`0` у первого элемента означает начало наблюдений, а не фиктивный прошлый кадр.
Пропущенные годы не интерполируются. Все исходные альтернативы сохраняются:
усреднение по году можно заменить в будущем без повторной работы backbone.
Это офлайн-каталог всех дат. Для оценки в момент `t` следующие этапы должны строить
префикс только из доступных к `t` наблюдений; pooling всей истории для прошлого
целевого момента создаст утечку будущего. Условия покрытия также проверяются
по этому префиксу.

## Проверка и следующий эксперимент

```bash
python -s -m unittest discover -s tests -p test_history_features.py -v
python -s -B -m unittest discover -s tests -v
```

Синтетические тесты проверяют известные сдвиги, отрицательные координаты,
расширение атласа, alpha/чёрный RGB, пропуски, альтернативы одного года, split/hash
проверки и восстановление после прерывания. CPU-тест с небольшим локальным toy hub
проходит через реальный offline-загрузчик и извлечение признаков. Он проверяет
интерфейс, формы, нормализацию и кэш, **не качество pretrained DINOv2**.

Следом: аудит реального числа пригодных историй и имеющихся event-меток; фиксируем
единый набор и building split. Затем сравниваем последнюю пару, pooling истории и
обучаемое представление порядка/времени. Начальные небольшие кандидаты — GRU
с hidden=128 и двухслойный Transformer с width=128, 4 heads, FF=256. Истории ≥3 лет
дают сравнение с последней парой; ≥4 лет — перестановку прошлого с сохранением
последней пары. До этого frozen `z` нельзя называть обученным эмбеддингом динамики,
а качество alignment или различие семантических масок — GT временного события.
