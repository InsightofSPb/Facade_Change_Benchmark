# Подготовка нового COCO с двумя путями

## Запуск

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
conda activate scd_bench
python -s scripts/prepare_dataset.py \
  /home/sasha/Facade_Change_Benchmark/data/result_coco_401.json \
  /home/sasha/Facade_Change_Benchmark/data/images_516
```

Число снимков не зашито в код: скрипт считает реальные
записи `images` актуального COCO. Не включает остальные фотографии из каталога.
Запуск использует CPU и существующие `build_manifest`, `preprocess_coco`,
`prepare_dataset`; окружение, веса и сторонние модели не меняются.

## Сопоставление и проверка

Порядок разрешения пути: явный путь внутри каталога → точное имя → подтверждённый
rename-map → имя без 8-символьного hex-префикса → сравнение регистра.
Автоматически читаются `*image_rename_map.csv` непосредственно в каталоге фото;
столбцы `old_name,new_name`. Другие расположения задаются повторяемым
`--rename-map /path/map.csv`. CSV не является командой переименования.
Конфликтующие соответствия и неоднозначные файлы не выбираются наугад.

Исходные COCO ID/имена, категории, сегментации и изображения сохраняются.
Только аннотации с явно записанным `area <= 0` исключаются из рабочей копии,
как в прежней подготовке. Журнал находится в `preprocessed/removed_annotations.json`.
Неразмеченные области не объявляются здоровыми или фоном. Проверка инвентаря
не доказывает качество и полноту полигональной разметки.

Для неизменённых снимков старые метаданные используются после сверки SHA-256
и размеров; новая нумерация COCO сама по себе не переносит принадлежность.
Новые/изменённые фото декодируются на исходной решётке без EXIF-поворота.
Проблемы печатаются по исходному `file_name` и текущему `image_id`:

- `missing_images.csv`: COCO-записи без файла;
- `image_issues.csv`: также неоднозначные пути, дубликаты, ошибки формата и размеров;
- `metadata_review_with_names.csv`: все записи, принадлежность и причины исключения.

## Действующая политика facades-v4 (уточнение владельца 2026-10-11, 19:38 МСК)

Та же команда с двумя путями теперь по умолчанию:

1. Включает одиночные снимки и все пригодные снимки без установленного адреса в
   семантический TRAIN. Заполнять metadata CSV для этого не нужно.
2. Формирует VAL/TEST из целых подтверждённых зданий. Основная единица баланса —
   здание, а не кроп. Цель — 70/10/20: TEST `round(0.20*N)` зданий, VAL
   `round(0.10*N)`, TRAIN — остальные. Например, 55 зданий дают 38/6/11.
   Прежний предел TEST 7–10 не применяется. Ограничения серий сохраняются:
   короткие 1–2 года и длинные 8+ в TRAIN; средние 3–7 — кандидаты VAL/TEST.
   При недостатке кандидатов это явно указано в отчёте; целевые доли не выдаются
   за фактические. Точные проценты ограничены неделимостью зданий и правилами серий.
3. Экспортирует для компрессионной ветки только временные пары из подтверждённых
   видов/лет. Одиночные семантические снимки не становятся временными примерами.

Переход со старой политики создаёт новую версию назначений, без изменения старых
run-каталогов. Числа кропов сохраняются как диагностика; полная семантическая
сводка включает TRAIN без адресов, поэтому доли фотографий и кропов могут заметно
отличаться от 70/10/20 по подтверждённым зданиям.
Неизвестные адреса не считаются отдельными подтверждёнными фасадами в статистике зданий.

`dataset.json` указывает на полный `semantic_manifest.json` и `semantic_crops.jsonl`.
`prepared/manifest.json`, `prepared/split.json`, `prepared/pairs.csv` содержат подтверждённую
часть и временные кандидаты. `auxiliary_training.json` перечисляет добавленные TRAIN-снимки,
исключённые явные совпадения с VAL/TEST и точные дубли TRAIN. Проверки учитывают и
исторические holdout-наблюдения. Неизвестные поля остаются неизвестными; статус metadata
не подменяется на reviewed.

Если добавлены снимки без адреса, записывается `physical_disjointness_verified=false`
и статус `completed_exploratory_train_only` (код 0). Это позволяет обучать сегментацию
сейчас, но не утверждать доказанное отсутствие пересечения физических зданий с holdout.
Известные совпадения не включаются в TRAIN; неизвестные совпадения по одному имени
IMG/PXL исключить невозможно. Информация о пропущенных файлах и классах сохраняется
независимо от общего статуса.

В явные правила добавлены `Kamennoostrovskii_57`, `Sablinskaya_16` и
`Kamenoostrovskii_prospect_25_2`. Два снимка Sablinskaya за 2026 год сохраняются
отдельно в том же виде, как существующее правило Voskova; их источник не выдумывается.
26 снимков этих трёх серий дают 23 first-anchor пары. Это кандидаты для alignment,
а не доказанная геометрическая сопоставимость. У всех трёх серий 8+ лет: TRAIN.

Также добавлены подтверждённые именные правила для Pushkinskaya_5, Marata_8,
Poltavskaya_14, Chkalovskii_prospect_58, Chkalovskii_prospect_54,
Bolshaya_Monetnay_11 и Kamenoostrovskii_prospect_26_28. Хеш-префиксы COCO
не мешают их распознаванию. Семь дат Poltavskaya_14 (2009–2025) дают шесть
first-anchor кандидатов; у Marata_8 без года сохраняется неизвестная дата,
поэтому временная пара не создаётся. Все ранее использованные неизвестные
TRAIN-снимки после уточнения адреса остаются в TRAIN.

Уточнение метаданных оформляется новым запуском подготовки с прежним split.
Уже готовящиеся аугментации и текущее обучение продолжают использовать свой
неизменяемый снимок. Новые истории можно готовить из нового запуска независимо
от обучения. Для последующего обучения на новом снимке понадобится подготовить
соответствующий кеш аугментаций; `--reuse-augmentations` переиспользует только
проверенные неизменившиеся примеры.

`leakage_check.json` проверяет полный семантический состав после добавления TRAIN:
здания, виды, SHA-256 и оба конца каждой временной пары, с учётом владельцев и
истории текущей версии. Известное пересечение сохраняется в отчёте и завершает
подготовку с ошибкой до экспорта учебного индекса. Неизвестные TRAIN-адреса
перечисляются отдельно; отсутствие утечки для них по-прежнему не доказано.

Старую политику с целью TEST 7–10 можно воспроизвести через `--split-policy facades-v3`.
Первая миграция в v4 меняет назначения, следующие запуски v4 сохраняют их.

### Дополнение COCO без переноса обучающих снимков в holdout

Для последовательного расширения сохраняется `semantic_history.json`: история
всех семантических TRAIN/VAL/TEST идентичностей, включая TRAIN без адресов.
История не зависит от текущей нумерации COCO и сохраняет временно исчезнувшие фото.
Для прежних подготовок она восстанавливается из проверенного полного
`semantic_manifest.json`, а не только из подтверждённого `prepared/split.json`.

Если ранее неизвестный TRAIN снимок получает адрес, новый фасад закрепляется за
TRAIN. Если адрес уже принадлежит VAL/TEST, подготовка останавливается с описанием
конфликта. Производное назначение и причины записываются в `extension_guard.json`
и при необходимости `extension_input_split.json`; старый запуск не изменяется.
Автоматический выбор предшественника проверяет полноту накопленной истории.
Можно явно передать `--previous-split <последний-run>/prepared/split.json`.
Целевые 70/10/20 не являются основанием переносить уже использованные фасады.

Затем отдельно подготавливаются фиксированные аугментации; неизменённые примеры
можно перенести в новый набор через `--reuse-augmentations`. Команды и проверки
совместимости описаны в [семантическом обучении](2026-10-11_dino_semantic_training.md).

Для прежнего строго подтверждённого режима можно явно выбрать `--split-policy series-v2`.
Следующие разделы описывают прежний протокол и его совместимость.

## Предыдущая политика series-v2

Согласована ранее 2026-10-11; доступна через `--split-policy series-v2`. Цели — **80% TRAIN / 8% VAL / 12% TEST по кропам**.
Научная единица разбиения — целое физическое здание. Все ракурсы, даты и кропы
одного здания остаются вместе. Длина серии — максимальное число различных
подтверждённых лет внутри одного вида; несколько фотографий одного года не
считаются дополнительными временными шагами.

- 1–2 года, 8+ лет или неполные сведения о годе/виде: TRAIN при создании версии.
- 3–7 лет: кандидаты для VAL/TEST; минимум одно такое здание сохраняется в TRAIN.
- VAL/TEST: цель минимум два независимых здания в каждом; по возможности два
  здания с 5–7 годами в каждом, иначе одно. Эти ограничения важнее точных процентов.
- При нехватке подходящих зданий отчёт явно показывает `series_constraints.issues`;
  неподходящие серии не подставляются вместо недостающих. Статус `needs_split_review`.

Цели приблизительные: используются детерминированные перемещения и обмены целых
зданий, без обещания глобально оптимального баланса. Средние серии в holdout
ограничивают выводы этим режимом; перенос на длинные серии отдельно не проверен.
Метки дефектов и показатели моделей не участвуют в выборе split. `class_coverage.csv`
показывает наличие аннотаций каждого класса по изображениям и зданиям; это не
пиксельная площадь и не проверка полноты разметки.

Первый запуск series-v2 со старым legacy-разбиением использует прежний манифест
только для проверенного кеша RGB/метаданных. Создаётся новый split и новый gold-состав,
старые файлы не изменяются. `split_transition.json` связывает обе версии хешами,
перечисляет перемещения зданий и отдельно прежний TRAIN, попавший в новый holdout.
Модели, уже обучавшиеся на новых VAL/TEST, для этой версии нужно переобучить.
Старые экспериментальные таблицы относятся к старому split.

Повторный запуск автоматически выбирает совместимую историю **той же политики**.
После создания series-v2 её владельцы и исходный gold-состав заморожены. Новые
наблюдения существующего здания сохраняют его split; если серия позже выходит
за границы 3–7 лет, это отражается как исключение прежней политики, без тихого
переноса здания. `building_series.csv` показывает серии и назначения по каждому зданию.

Для продолжения прежнего протокола используется `--split-policy legacy`.

## Проверка и выбор предыдущего разбиения

Поиск в `runs/` принимает только завершённые настоящие `dataset_preparation`
с reviewed split и пересечением имён текущего набора. Dev-аудиты, benchmark-копии
и незавершённые подготовки не являются источником назначения.
Проверяются хеши артефактов, исходный gold-состав, provenance, seed и целевые доли.
Выбирается совместимое расширение, содержащее все найденные исторические назначения;
mtime каталогов не определяет выбор. Несовместимые или разветвлённые истории
выдают `needs_split_review`, сохраняя аудит, и требуют явного пути:

```bash
python -s scripts/prepare_dataset.py data/result_coco_392.json data/images_516 \
  --previous-split runs/2026-10-03-first-anchor/split.json
```

Если предшествующего reviewed-запуска нет, создаётся первое разбиение выбранной
политики с seed 42 (80/8/12 для series-v2; 70/10/20 для legacy). Метаданные берутся
из существующих подтверждённых `configs/2026-10-03_metadata_rules.json`, старого
манифеста и, при необходимости, `--metadata-csv` с ID текущего экспорта.
Неизвестные здания не подтверждаются автоматически по названию.

При расширении одной версии новые фото известного здания наследуют его split. Прежние назначения сохраняются,
включая временно отсутствующие здания, исходный gold-состав и всю историю владения.
Только новые подтверждённые здания распределяются по политике и дефициту кропов; все их виды
и даты остаются вместе. Число аннотаций и модельные метрики не участвуют в балансе.
Семантическое обучение допускает одиночные снимки: наличие временной пары не требуется.
В series-v2 семантической ветке достаточно подтверждённого `building_id` и пригодного
файла. `view_id` и `year` в reviewed CSV могут оставаться пустыми; они сохраняются
как неизвестные, а не заполняются догадками из имени. Временная ветка требует оба
поля. Неизвестное здание исключается из обучения; имя IMG/PXL не считается отдельным
зданием. `_YYYY_vN` позволяет предположить год, но не подтверждает здание и не
объединяет разные варианты в один ракурс.

Для заполнения метаданных скопируйте `metadata_review_with_names.csv` из отчёта в
отдельный файл, оставьте ID актуального COCO, укажите подтверждённый `building_id`
и `reviewed=true`. Виды и годы заполняются только когда известны. Затем повторите
те же два пути с `--metadata-csv data/reviewed-current.csv`. Числовые ID нельзя
переносить в другой экспорт COCO без сверки. Будущие запуски переиспользуют эти
подтверждения из манифеста после проверки SHA-256 и размеров.

Пока есть неизвестные здания, доли рассчитаны только для подтверждённой части.
Добавление большого числа TRAIN-only снимков может заметно увеличить TRAIN сверх
80%: уже созданные назначения автоматически не пересматриваются. До первого
обучения желательно закончить проверку метаданных. Если после неё нужна новая
балансировка, явно передайте исходный legacy split через `--previous-split` вместе
с полным актуальным `--metadata-csv`: это создаст ещё одну версию series-v2 без
перезаписи старой. При наличии нескольких независимых версий дальнейшие запуски
потребуют явно выбрать нужный новый `prepared/split.json` через `--previous-split`.
Это осознанная смена протокола; использованные для обучения splits тихо не меняются.

## Кропы и значение пропорций

По умолчанию crop 512, stride 448. Последний кроп прижат к краю, поэтому перекрытие
может превышать 64 пикселя. Малое изображение даёт один частичный кроп с указанным
padding справа/снизу; padding должен иметь игнорируемую поддержку. Размеры можно
изменить через `--crop-size` и `--crop-stride`; геометрия записывается в split и run.

В текущей facades-v4 баланс использует число зданий; число геометрических кропов
служит диагностикой (в прежней series-v2 именно оно было весом баланса). Индекс
`semantic_crops.jsonl` перечисляет те же координаты без создания копий изображений.
Сводка показывает здания, изображения и кропы отдельно. Старые здания не переносятся,
поэтому точные целевые доли не гарантируются. Последующая фильтрация по видимости,
прозрачности или наличию размеченных пикселей может изменить эффективные доли.

Временные пары сохраняют `first-anchor`: поздние наблюдения сопоставляются с самой
ранней датой своего вида. Они только кандидаты; эта команда не запускает alignment,
не создаёт aligned temporal crops и не объявляет разность семантических масок
истинной разметкой временного изменения. Для геометрии остаётся существующая
цепочка `scripts/2026-10-03_prepare_dataset.py` и команда `facade_change batch`.

## Статусы

`completed` означает успешную подготовку индекса, а не завершённый эксперимент.
`completed_with_issues` означает проблемы изображений/аннотаций или отсутствие
части прежнего gold. `needs_metadata_review` означает непроверенные метаданные;
при достаточном числе известных фасадов их индекс всё равно сохранён.
`needs_split_review` при конфликте истории сохраняет аудит без нового split;
при нехватке средних серий сохраняет подготовленную часть и явные ограничения,
которые нужно устранить до сравнительного эксперимента. Последние три статуса
возвращают код 2. Неудачный запуск хранит `run.json` со статусом ошибки.

Каждая попытка создаёт новый каталог, сохраняет конфигурацию и SHA-256 входов и
выходов. Старые COCO, фотографии, CSV и результаты не изменяются.
