# Обучаемые представления истории по готовым DINOv2-признакам

Этап использует `data/histories/features/index.json`. Повторно запускать DINOv2,
выравнивание или нарезку кропов не нужно. Обучаются небольшие классификаторы
событий и временные энкодеры. Frozen-векторы отдельных наблюдений остаются входом.

## Что сравнивается

| Вариант | Вход и результат |
|---|---|
| `previous` | Косинусное расстояние до предыдущего наблюдения |
| `earliest` | Косинусное расстояние до первого наблюдения текущего эпизода |
| `history_mean` | Косинусное расстояние до нормированного среднего прошлого |
| `pair` | Обучаемый классификатор последней пары |
| `pooled` | Та же пара плюс среднее представление прошлых наблюдений |
| `gru` | Та же пара плюс последний hidden state однослойной GRU |
| `transformer` | Та же пара плюс последний валидный токен двухслойного Transformer |
| `pooled-gru`, `pooled-transformer` | Дополнительные pooling+MLP контроли с приблизительно соответствующим бюджетом параметров |

По умолчанию запускаются `pair pooled gru transformer`, каждый с `gaps` и `none`:
восемь моделей. `gaps` передаёт разрыв с предыдущим годом и годы от начала эпизода,
делённые на 10. `none` убирает календарные признаки, но сохраняет порядок. Transformer
получает синусоидальные позиции, в том числе в `none`. Пропуски не интерполируются.

Общая визуальная проекция: 384 → 128. GRU: hidden=128, один слой. Transformer:
width=128, 4 головы, 2 слоя, FF=256. Голове передаются проекции предыдущего и текущего
кадров, их направленная и абсолютная разности, интервал пары и, кроме `pair`, вектор
истории. Для оценки 2018 → 2026 энкодер истории видит только годы до 2018 включительно.
Текущий 2026 год доступен классификатору пары, но не входит в вектор прошлого.

Увеличенная pooling-голова сама по себе может дать выигрыш. Для проверки механизма
добавьте `pooled-gru pooled-transformer`; точное число параметров сохраняется для
каждой модели. Это приблизительные контроли ёмкости, а не гарантия равной сложности
или оптимальности настройки всех архитектур.

## 1. Оценки, галереи и таблица разметки

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only

conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow benchmark history-scores \
  --features data/histories/features/index.json \
  --out runs/2026-10-25-history-scores-001
```

Результаты: `scores.csv`, `review.csv`, `gallery.html` (расхождение методов),
`largest_changes.html` (наибольшие оценки), `summary.json`, `run.json`,
`experiment_contract.json`, `events.jsonl`. Галереи содержат до 60 событий каждая;
`--gallery-limit 200` увеличит число. Таблицы содержат все подходящие события.
Снимки одного года показаны как альтернативы, а не как отдельные временные шаги.

По умолчанию только TRAIN и VAL. Минимум — три года **к моменту оцениваемого события**,
а не три года в полной будущей истории. Первый переход длинной серии поэтому
не входит в это сравнение. Для отдельной парной диагностики используйте
`--min-years 2` и новый каталог. При добавлении будущего года идентификатор и
fingerprint уже существующего префикса сохраняются, если его входы не изменились.

Косинусные оценки описывают изменение внешнего вида. Это не вероятность дефекта,
не подтверждение ремонта и не готовые labels. Геометрическая поддержка кропов
не гарантирует отсутствие дерева, лесов или ошибки регистрации. Размеры выборки
читаются из текущего экспорта, а не задаются по числам из переписки.

## 2. Проверенные метки событий

Скопируйте `review.csv` в отдельный локальный файл, например
`data/2026-10-25_history_labels.csv`, и заполните его. Совместимые старые ручные
метки можно перенести только после проверки соответствия `track_id`, лет, участка
и fingerprint префикса. Автоматического предположения о совместимости нет.

| Поле | Что записать |
|---|---|
| `review_status` | `accepted`, `excluded` или оставить `unreviewed` |
| `comparable` | `yes` для пригодной размеченной пары; неоднозначную пару исключить |
| `label` | `1` — подтверждённое событие между двумя последними годами, `0` — подтверждённое отсутствие целевого изменения |
| `event_type` | Например, `crack`, `repair`, `degradation`, `appearance`, `disappearance`, `unchanged` |
| `review_source` | Кто проверил и/или ссылка на исходную ручную разметку, для синтетики — проверяемая программа события |
| `history_start_year` | Первый год эпизода; после известного прошлого ремонта — год ремонта |
| `notes` | Видимость, причина исключения, сомнения и другие замечания |

Идентификаторы, `prefix_sha256`, здания, split и годы не исправляются вручную.
Незаполненные/исключённые строки не превращаются в отрицательные примеры. При
противоречивых метках код останавливается. Несравнимые или закрытые участки не
размечаются как unchanged. Семантическая маска одного кадра не является GT события.

Политика целевого события должна быть одинаковой во всех split: например, включать
повреждение и ремонт, исключать освещение/окклюзию. Для неоднозначных альтернатив
одного года нужен ручной вывод или исключение. `history_start_year` — доступная
на тот момент информация о прошлом, не вывод из будущего события. Если в таблице
есть подтверждённый прошлый ремонт, последующие метки должны начинать новый эпизод.
После такого сброса снова проверяется минимум три года.

Для репрезентативной оценки размечайте заранее выбранную выборку по зданиям,
включая обычные низкие сигналы. Только top-score/disagreement галереи дают смещённую
выборку. Покрытие и доля размеченных событий сохраняются отдельно от метрик.

## 3. Обучение моделей

Нужны положительные и отрицательные проверенные события как в TRAIN, так и в VAL.
Без них код сообщает, чего не хватает, до загрузки GPU. TEST не участвует в обучении,
выборе checkpoint или порога; его NPZ не открываются, значения test labels не читаются
как обучающие/валидационные цели. Разбиение сохраняется из подготовки данных.

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow train history-models \
  --features data/histories/features/index.json \
  --labels data/2026-10-25_history_labels.csv \
  --models pair pooled gru transformer \
  --time-modes gaps none \
  --device cuda:0 --batch-size 64 \
  --epochs 100 --patience 15 --seed 42 \
  --out runs/2026-10-25-history-models-001
```

Для короткой проверки используйте `--epochs 2` и отдельный каталог. CPU также
поддерживается: `--device cpu`. Перед CUDA проверяются свободная память и процессы.
Чужие задачи не останавливаются. Требуется среда с PyTorch, поддерживающим
`torch.load(weights_only=True)` и используемые Transformer API (проверено на CPU 2.5.1).
Новые зависимости для скоринга и метрик не нужны; AP реализован с группировкой ties
и проверяется против scikit-learn, когда тот установлен.

Loss — BCE с одинаковым суммарным весом каждого здания. AdamW, gradient clipping=1,
dropout=0.1; DINO не обучается. Checkpoint выбирается по building-weighted VAL AP.
Порог — минимальный наблюдаемый порог, удовлетворяющий building-weighted VAL FPR ≤5%.
Если ties не позволяют выбрать такой порог, допустим порог выше всех оценок.

Для каждого варианта сохраняются `last.pth` (optimizer, RNG, лучший state),
`best.pth`, `result.json`, `val_predictions.npz`. Последний содержит вероятность
и 128-мерный вектор прошлого для каждого размеченного VAL события. У `pair` это
проекция предыдущего кадра, а не обученный вектор всей истории. Sigmoid-вероятности
не объявляются откалиброванными без отдельной проверки.

Прерванный запуск продолжается той же командой с `--resume`; конфиг, входные хеши
и код должны совпасть. Прогресс восстанавливается с последней завершённой эпохи.
Завершённый запуск не перезаписывается. Изменение данных/labels/параметров означает
новый каталог. Для устойчивого вывода повторите сравнение с заранее выбранными seeds.

## 4. Оценка с фиксированными порогами

После фиксации архитектур и протокола отдельно экспортируйте таблицу TEST.
Разметьте её независимо от настройки моделей.

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow benchmark history-scores \
  --features data/histories/features/index.json --splits test \
  --out runs/2026-10-25-history-test-review-001
```

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow benchmark history-models \
  --features data/histories/features/index.json \
  --training-run runs/2026-10-25-history-models-001 \
  --labels data/2026-10-25_history_test_labels.csv \
  --splits test --device cuda:0 --batch-size 64 \
  --out runs/2026-10-25-history-test-001
```

`metrics.json` содержит AP, recall, **фактический** FPR при VAL-пороге, результаты
по типам события и cluster bootstrap (500 повторов, единица — здание). Основная AP
вычисляется на объединённых событиях с весом `1 / число событий здания`; macro AP
по зданиям с положительными событиями и обычная micro AP — дополнительные показатели.
AP — сумма приростов recall, умноженных на precision в уникальных порогах, а не
трапециевидная площадь. Если положительных событий нет, AP явно не определена.

Разности AP моделей и парного baseline, а также gaps − none получают **парные**
bootstrap-интервалы. Это условная неопределённость для уже обученных моделей;
она не включает вариацию обучения и выбора гиперпараметров. На одной группе
доверительный интервал не строится. TEST FPR не обязан оставаться равным 5%.

На префиксах 4+ лет дополнительно переставляются более ранние векторы при сохранении
последней пары и временных позиций. Нормальная и перемешанная версии оцениваются
на одинаковом поднаборе с прежним порогом. Это inference-проверка зависимости от
прошлого, а не отдельно обученная модель. Разные типы изменений сравниваются
по схеме «этот тип положительных событий + все отрицательные события».

Остальные выходы: `predictions.csv`, `gallery.html`, `<model>_embeddings.npz`,
coverage, конфигурация, хеши и журнал. Число перекрывающихся кропов не трактуется
как число независимых фасадов.

## 5. Векторы для всех доступных историй после обучения

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare temporal-embeddings \
  --features data/histories/features/index.json \
  --training-run runs/2026-10-25-history-models-001 \
  --splits train val --device cuda:0 \
  --out runs/2026-10-25-learned-history-features-001
```

Без `--labels` выдаются оценки и векторы всех подходящих префиксов, но **не метрики**.
`history_through_year` точно указывает последнюю дату, включённую в вектор прошлого.
Без таблицы используется полная доступная прошлая история без сбросов после ремонта.
Для сравнения с известными ремонтами используйте размеченные префиксы с явным
`history_start_year` через `benchmark history-models --labels ...`. Эта ветка пока не
реализует retrieval похожих обучающих случаев или LLM-объяснения. Это следующий
отдельный эксперимент после сравнения B/C/D, а не скрытая часть temporal модели.

## Проверка реализации

```bash
python -s -B -m unittest discover -s tests -p test_history_features.py -v
python -s -B -m unittest discover -s tests -v
```

Тесты включают подготовку и frozen-extraction интерфейс, синтетические feature-файлы,
реальное CPU-обучение всех четырёх вариантов, сравнение AP со scikit-learn,
сохранение/загрузку, продолжение после прерывания, замороженный TEST-порог,
padding, годы, split, hash, отсутствие будущего и explicit repair reset.
ISO-датированный модуль новых тестов включён через стандартный `load_tests`.
Эти проверки не являются результатом на настоящих фасадах.

Опорные API: [PyTorch GRU](https://docs.pytorch.org/docs/stable/generated/torch.nn.GRU.html),
[TransformerEncoderLayer](https://docs.pytorch.org/docs/stable/generated/torch.nn.TransformerEncoderLayer.html),
[определение AP](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html).
