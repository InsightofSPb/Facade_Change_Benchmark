# Общий запуск методов на сохранённом H0/H1-поднаборе

Добавлены пять семейств: LPIPS, DINOv2, RSCD, AnyChange и полный GeoSCD. RSCD
представлен тремя фиксированными checkpoint, поэтому новых строк методов семь:
`lpips`, `dinov2`, `rscd_cmu`, `rscd_diff_cmu`, `rscd_pscd`, `anychange`, `geoscd`.
Обучение на фасадах для этих методов не выполняется. Полный GeoSCD использует
существующую реализацию VGGT + модифицированный SAM1 ViT-H, а не только геометрию.

## Исходные данные и размеры

Вход эксперимента, разметка и решётка оценки остаются **256×256**. Загружается
именно прежний `selection.json`: те же 10 кропов, 3 validation и 7 test-фасадов,
60 пар. Повторной случайной выборки, построения кропов и генерации условий нет.
Проверяются все пять отпечатков родительского датасета, идентичность и порядок
баз и пар. Исходные RGB uint8 и геометрическая поддержка — единственный вход
scorer; разметка, состояния H0/H1 и известная видимость доступны evaluator.

DINOv2 ViT-S/14 разбивает вход на патчи 14×14. Число 256 не кратно 14:
`18×14=252`, `19×14=266`. Для DINOv2 и RSCD адаптер добавляет **внутреннюю
отражённую рамку по 5 пикселей с каждой стороны** до 266×266, не меняя ни одного
исходного пикселя. Выход восстанавливается на дополненную решётку и обрезается
до исходных 256×256. Рамка не участвует в метриках. Это зафиксированная подготовка
нашего входа, а не заявление о буквальном повторении авторского эксперимента.
LPIPS, AnyChange и GeoSCD используют свои штатные внутренние преобразования;
их результаты также возвращаются на исходную решётку. Старые восемь методов
пересчитывать из-за этой подготовки не требуется.

Рабочие команды подготовки данных, выравнивания и отдельного GeoSCD сохраняются.
`scorers.py` остаётся совместимым входом для старого кода. Переданные исходники
конкурентов читаются из внешних каталогов и не копируются целиком в Git.
Распределение старых тестов по подпапкам и переименование датированных команд
не являются условием этого сравнения: существующие точки входа и обнаружение
тестов сохранены. Новый код уже разделён по адаптерам.

## Среды и локальные файлы

Оркестратор можно запускать из `lposs`. LPIPS/DINOv2/RSCD/AnyChange работают в
существующей `scd_bench`, полный GeoSCD — в `facade-geoscd`. Worker выбирается
абсолютным `worker_python`; активация сред внутри benchmark не требуется.
Одновременно остаётся активным только один worker/model. Его логи выводятся
в файлы, чтобы модельные сообщения не ломали таблицы прогресса.

Владелец подтвердил 2026-10-04:

| Среда | Python | Torch / torchvision | CUDA |
|---|---|---|---|
| `scd_bench` | 3.10.21 | 2.6.0+cu118 / 0.21.0+cu118 | Доступна |
| `facade-geoscd` | 3.10.22 | 2.6.0+cu118 / 0.21.0+cu118 | Доступна |

В `scd_bench` уже есть NumPy 1.26.4, Pillow 11.1.0, scikit-image 0.25.2,
einops 0.8.1 и safetensors 0.5.3. `lpips` отсутствует. Transformers, timm и
huggingface-hub не нужны для используемой локальной DINOv2 ViT-S/14 и этих
адаптеров. Setup не меняет Torch/torchvision/NumPy/Pillow, не создаёт среду и
не устанавливает пакеты обучения, xformers или весь старый benchmark.
Перед импортом torchvision проверяется `mpmath` — зависимость SymPy в цепочке
Torch Dynamo. Если она отсутствует, setup устанавливает только `mpmath==1.3.0`
с `--no-deps`; установленные версии основных пакетов сохраняются.

```bash
cd /home/sasha/Facade_Change_Benchmark
bash scripts/setup_competitors.sh --env scd_bench --download-lpips-weights
```

Эта явно выбранная загрузка получает только официальный AlexNet backbone LPIPS
`alexnet-owt-7be5be79.pth` из `download.pytorch.org`, проверяет префикс SHA-256 и
кладёт его в Torch Hub cache этой среды. Калибровочные веса LPIPS входят в пакет
0.1.4. Существующий проверенный backbone переиспользуется. Без флага веса не
скачиваются. Inference никогда автоматически не скачивает модели.
Все DINO/RSCD/SAM checkpoint из прежнего проекта используются на месте.
RSCD загружает NumPy-метаданные checkpoint через ограниченный список scalar/dtype.
Импорт совместим с NumPy 1.26 и 2.x; в Torch 2.6 учитываются оба исторических
имени NumPy scalar. Версии библиотек для этого менять не требуется.

LPIPS проверяет локальный файл по умолчанию в `torch.hub.get_dir()/checkpoints`.
Для другого расположения можно задать `backbone_checkpoint` в конфигурации
метода; необязательный `calibration_checkpoint` переопределяет калибровочный
файл из официального пакета.

Путь VGGT выбирает `configure_competitors.py`: сначала из записи прежнего
`2026-10-04-geoscd-full-smoke`, затем из других GeoSCD full запусков, затем из
`models/vggt_1b.pt` или `/home/sasha/GeoSCD-facade/src/pretrained/model.pt`.
Используется только существующий файл, без копирования и новой загрузки.
`sam_checkpoint` указывает на уже имеющийся SAM1 ViT-H из прежнего benchmark.
SAM3 не подставляется вместо него. Для GeoSCD сохраняется готовая среда;
повторять `setup_geoscd.sh` после успешного прежнего запуска не нужно.

## Настройка и единая команда

```bash
conda activate lposs
python -B scripts/configure_competitors.py \
  --reuse-run runs/2026-10-04-compression-quick-001 \
  --out runs/2026-10-04-all-methods-001
```

Если прежний запуск имеет другое имя, замени значение `--reuse-run`. Helper
проверяет завершённый статус, метрики, selection, сохранённые карты и их SHA-256,
а также существование нужных исходников, checkpoint и Python-файлов. Модели
не загружаются. После проверки создаются `configs/methods.local.json` и
`configs/benchmark.local.json` с абсолютными локальными путями. Для одной проверки
без записи добавь `--dry-run`. Имеющиеся локальные конфигурации сохраняются:
helper сообщает об этом, а новые значения флагов применяет только к создаваемым
файлам. Пути в существующих конфигурациях также проверяются; неправильный путь
вызывает явный отказ, сохраняя файлы владельца. Helper не удаляет файлы и не
скачивает веса.

Настройки остаются редактируемыми: `methods_config` указывает на файл с объектом
`methods`; параметры модели находятся под её точным именем. При ручном
использовании шаблонов все относительные пути JSON считаются от её каталога.
Пути `/home/sasha/...` в примерах относятся к компьютеру владельца.

`methods` перечисляет новые методы для вычисления. Методы прежнего запуска
добавляются для сравнения из `reuse_run` без загрузки их checkpoint или нового
inference. Переиспользуется **полная исходная папка с сохранёнными картами**;
пятифайловый архив метаданных для анализа не является кешем inference.
Проверяются завершённый статус, SHA-256 карт, конфигурация, выборка, исходный
датасет и совпадение пар. Старые validation-пороги и время inference сохраняются.

```bash
conda activate lposs
python -u -B -m facade_change h0h1-benchmark \
  --config configs/benchmark.local.json
```

Методы можно включать и выключать списком в JSON или переопределять через CLI:

```bash
python -u -B -m facade_change h0h1-benchmark \
  --config configs/benchmark.local.json \
  --methods lpips dinov2
```

Это запустит только два новых метода, остальные восемь будут взяты из
`reuse_run`. Для следующего запуска обязательно меняй `out` в конфигурации
либо передавай новый `--out`: старый каталог результатов не перезаписывается.
Ни `--quick-bases`, ни повторный подбор seed при точной `--selection` не нужны.

## Оценка и интерпретация

Для LPIPS/DINOv2 и непрерывной карты RSCD порог выбирается только на трёх
сохранённых validation-фасадах и фиксируется до test. Авторская маска RSCD
сохраняется как дополнительный диагностический результат. AnyChange и GeoSCD
оцениваются по штатным бинарным маскам без нового подбора их внутренних
гиперпараметров на test.

H1 F1/IoU/precision/recall требуют видимых положительных пикселей. H0 оценивается
по pixel FPR. Известное перекрытие используется только в evaluator; игнорируемый
255 не передаётся моделям. Усреднение — сначала случаи внутри фасада, затем
равные веса фасадов. Пиксели и несколько условий одного кропа не являются
независимыми наблюдениями. На 7 test-фасадах не заявляются доверительные интервалы
или доказательство превосходства на настоящих межгодовых повреждениях.

`run.json`, `selection.json`, `threshold_selection.json`, `metrics.json`,
`summary.json`, карты и галерея дают единый результат всех включённых и
переиспользованных методов. `progress.txt` и `live_metrics.json` сохраняют
промежуточное состояние. Время переиспользованных методов — длительность их
первоначального inference, а не скорость чтения карты; оно не прибавляется к
новому расходу вычислений. Происхождение исходников, веса, внутреннее дополнение
и Python-среды фиксируются в метаданных. Прерванные и завершённые результаты
сохраняются; автоматический resume незавершённого benchmark не заявляется.

## Проверки реализации

Проверки без настоящих весов подтверждают интерфейсы, точное чтение выборки,
совпадение метрик из повторно использованных карт и изоляцию worker. Они не
подтверждают локальную CUDA-работу новых моделей или качество на фасадах.
Перед итоговыми численными выводами нужен локальный прогон и его завершённые
артефакты. Общая команда проверки кода сохраняется:

```bash
python -B -m unittest discover -s tests -v
```
