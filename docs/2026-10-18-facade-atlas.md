# Атлас фасадов: локальный запуск

Браузерный прототип с картой Санкт-Петербурга, карточками фасадов, фотографиями по
годам, шторкой сравнения, GT-слоями, журналом кандидатов изменений и предварительными
отчётами. Модели и повторное сопоставление кадров не запускаются. Qwen заменена
детерминированной заглушкой.

## Первый запуск на компьютере владельца

Для запуска нужен уже созданный архив
`runs/2026-10-18-prototype-inputs-001.tar.gz`. Он содержит подготовленные кадры,
числовые маски, сохранённые гомографии и исходные фотографии. В Git находятся
исходники интерфейса и подготовки; реальные фотографии и результаты остаются локально.

Чтобы сохранить текущую рабочую ветку и незакоммиченные изменения, создайте отдельный
worktree. Следующие две команды выполняются один раз:

```bash
git -C /home/sasha/Facade_Change_Benchmark fetch origin
git -C /home/sasha/Facade_Change_Benchmark worktree add --detach /home/sasha/Facade_Atlas_Prototype origin/codex/2026-10-18-facade-atlas
```

Затем подготовьте данные и запустите сервер:

```bash
conda run --no-capture-output -n scd_bench python /home/sasha/Facade_Atlas_Prototype/scripts/2026-10-18-facade-atlas.py \
  --bundle /home/sasha/Facade_Change_Benchmark/runs/2026-10-18-prototype-inputs-001.tar.gz \
  --out /home/sasha/Facade_Atlas_Prototype/runs/2026-10-18-facade-atlas-001
```

После сообщения о запуске сервера откройте **http://127.0.0.1:8765**.
Терминал должен оставаться открытым; остановка — `Ctrl+C`. Сервер слушает только
локальный интерфейс компьютера. Он не использует GPU и не вмешивается в текущие
эксперименты.

Требования для подготовки: **Python 3.9+, NumPy, SciPy, Pillow 9.1+ с поддержкой WebP**.
Используется существующая среда `scd_bench`; рабочие Torch/CUDA не переустанавливаются.
Node.js, npm, Docker, API-ключи и сборщик JavaScript для запуска не нужны.
Если зависимости уже есть, ничего устанавливать не требуется. При ошибке импорта
следует установить только недостающие зависимости в отдельную среду; не обновлять
среду текущего обучения ради просмотрщика.

Архив распаковывается автоматически во временный каталог. Исходные файлы не меняются.
Новый каталог результата создаётся эксклюзивно: существующий `--out` не перезаписывается.
`run.json` фиксирует исходный архив, хеши исходников и статус подготовки. Ошибка оставляет
диагностику в отдельном неуспешном запуске; для новой попытки выберите новый каталог.

## Повторный запуск

Повторная подготовка не нужна. Для уже созданного каталога достаточно стандартного
Python без NumPy/SciPy/Pillow:

```bash
python3 /home/sasha/Facade_Atlas_Prototype/scripts/2026-10-18-facade-atlas.py \
  --serve /home/sasha/Facade_Atlas_Prototype/runs/2026-10-18-facade-atlas-001
```

Если порт занят, добавьте `--port 8766` и откройте http://127.0.0.1:8766.
Для подготовки без запуска сервера добавьте `--prepare-only` к первой команде.
`--serve` обслуживает готовую копию интерфейса из указанного результата. После правок
исходников интерфейса создайте новый каталог результата, чтобы получить новую версию.

Подложка карты загружается из OpenStreetMap и требует сети. Фотографии, маски и
истории после подготовки доступны локально. При недоступной подложке остаются
координаты точек и список объектов. В браузере нужен JavaScript; открытие `index.html`
через `file://` не поддерживается.

## Что должно получиться

Для архива `2026-10-18-prototype-inputs-001.tar.gz` проверено:

- 12 карточек, 74 наблюдения, 62 соседние пары;
- 11 точек зданий; «Мира, 15» остаётся без точки до подтверждения корпуса;
- 11 классов GT и 911 кандидатов изменения меток размером от 64 px;
- 296 изображений для браузера: исходные и совмещённые кадры, RGB-кропы, числовые маски;
- `data/2026-10-18-facades.json`, `data/2026-10-18-locations.json`,
  `data/2026-10-18-validation.json`, `assets/`, `index.html` и `run.json`.

Количество объектов и кандидатов относится к этому архиву, а не ко всему датасету.
Первый экран открывает Каменноостровский проспект, 61. Выберите годы, подвигайте шторку,
включите «GT-разметка» или «Изменения GT», затем нажмите запись журнала.

## Смысл слоёв и записей

Рамка «Анализируемый участок» обозначает один подготовленный кроп 512 × 512 на всю
историю. В совмещённых координатах она остаётся неподвижной; маски внутри неё
относятся к выбранным годам. Общий кадр даёт контекст, но не расширяет покрытие GT.
Исходные фотографии без преобразования доступны отдельной кнопкой.

`packed == 0` означает неизвестную разметку, а не исправную поверхность. `support`
описывает геометрическую поддержку и не исключает деревья, машины или леса.
Пересекающиеся классы сохраняются. Визуализация смешивает их цвета; нажатие на точку
показывает все её метки.

Журнал содержит добавления/исчезновения отдельных меток на совместно поддержанной
и размеченной области соседних наблюдений. Используются 8-связные компоненты от
64 px, без морфологии. Это кандидаты для проверки, не независимо размеченные
физические события. Исчезновение метки повреждения не доказывает ремонт.
Для произвольной пары лет слой изменений пересчитывается; журнал остаётся журналом
соседних наблюдений. Метрики качества модели не подменяются сходством GT между годами.

Общие фотографии преобразуются сохранёнными `source_to_reference` в координаты
раннего опорного снимка. Согласованность с подготовленными кропами проверяется;
точность совмещения каждой детали фасада этим не подтверждается.

Демонстрационный приоритет предлагает проверить изменения разметки. Последствия
для людей/имущества и исторического материала остаются неоценёнными. ГОСТ 31937-2024,
п. 5.1.10, и ГОСТ Р 56198-2014, п. 7.2.1, приняты как ориентиры структуры материалов.
Нормативная категория технического состояния автоматически не присваивается.

## Отчёт, комментарии и Qwen

Кнопка «Предварительный отчёт» собирает наблюдения, годы, координаты областей и
фотоматериалы. Есть экспорт JSON и печать/PDF. Это шаблон, Qwen не вызывается.
Комментарии сохраняются в `localStorage` текущего браузера с введённым автором и
датой записи; в экспорт они попадают отдельно от профессиональной оценки.
Другой браузер, хост или порт имеет отдельное хранилище. Для переноса комментариев
сохраните отчёт JSON; автоматического общего сервера комментариев нет.

Точка подключения модели:

```javascript
await buildReport({ facade, categories, location, reviewNotes }, provider);
```

Функция находится в `web/facade_atlas/2026-10-18-reporter.js`. Без `provider`
возвращается заглушка. Провайдер получает те же подтверждающие данные; его ошибка
передаётся вызывающему коду и не подменяется фиктивным ответом. Для реального Qwen API
нужен отдельный серверный адаптер; секретные ключи нельзя помещать в браузерный код.

## Если нужно собрать входной архив заново

Скрипт коллектора также включён в репозиторий:

```bash
conda run --no-capture-output -n scd_bench python /home/sasha/Facade_Atlas_Prototype/scripts/2026-10-18-collect-prepared.py \
  --prepared /home/sasha/Facade_Change_Benchmark/runs/2026-10-17-night-prepared-001/manifest.json \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-10-18-prototype-inputs-002.tar.gz \
  --include-originals
```

Коллектор копирует существующие данные и проверяет хеши, не запускает модели.
Для просмотрщика обязательны оригиналы и audit с сохранёнными преобразованиями.
Текущая версия поддерживает один выбранный вид/кроп на здание и не менее двух
наблюдений в истории. Несколько видов одного здания требуют отдельного расширения
интерфейса; они не объединяются молча.

Чтобы расширить GT за пределы кропов, потребуется исходный COCO-файл
`runs/20261011T175248818684449-dataset-402/preprocessed/annotations.json` из основного
репозитория владельца. В текущий архив он не включён; его импорт пока не реализован.

## Проверки разработчика

Из корня репозитория:

```bash
python -m unittest discover -s tests -p 'test_facade_atlas.py' -v
```

Дополнительные проверки браузерной математики и отчёта (Node.js 18+, только для
разработки):

```bash
node scripts/2026-10-18-check-facade-atlas.mjs
node scripts/2026-10-18-check-facade-atlas.mjs --site runs/2026-10-18-facade-atlas-001
```

Выполнены CPU-подготовка на переданном архиве, проверки хешей/масок и HTTP-выдачи
локального результата. Проверки данных не являются браузерной проверкой всех
интерактивных действий; автоматизированный браузер в среде подготовки недоступен.

## Файлы

- `web/facade_atlas/` — статические исходники интерфейса, без данных и привязки к Sites.
- `scripts/2026-10-18-facade-atlas.py` — безопасная распаковка, подготовка и локальный HTTP-сервер.
- `scripts/2026-10-18-facade-atlas-export.py` — RGB/GT-экспорт с переиспользованием геометрии.
- `scripts/2026-10-18-collect-prepared.py` — сбор входного архива.
- `configs/2026-10-18-facade-atlas-locations.json` — публичные адреса/координаты со ссылками на источники.
- `runs/` — локальные результаты, исключённые из Git.
