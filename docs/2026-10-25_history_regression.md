# Регрессия изменений по классам из готовых историй

После экспорта масок от 2026-10-25 владелец получил 2769 автоматических положительных
переходов, 0 стабильных и 2215 неизвестных. Это результат его конкретного запуска,
не универсальные размеры набора. Бинарный классификатор с таким набором не обучается.
Новая постановка использует сохранённые карты каждого класса и предсказывает вектор
долей различий. Полностью неизменившийся кроп для этого не требуется.

## Цель, вход и loss

Для класса `c` и перехода `i`:

```text
y[i,c] = число пикселей class_targets[c] == 1
         / число пикселей class_targets[c] != 255
```

Знаменатель — сравнимая аннотированная область данного класса после ранее заданного
допуска границ. Значения `255` исключены и из числителя, и из знаменателя. Минимум
по умолчанию — 64 известных пикселя и 0.1% площади канонического кропа. При меньшем
покрытии цель класса недоступна: `valid=False`, значение в NPZ — `NaN`, loss отсутствует.
Ноль означает совпадение на этой области. Неразмеченная часть остаётся неизвестной.

Цель — доля изменившихся **аннотаций**. Это не вероятность события, не тяжесть
повреждения, не прирост площади класса и не независимая временная истина. Она
объединяет появление и исчезновение класса, не различает их направление. Пересечения
классов сохраняются: пиксель может участвовать в нескольких целях, сумма долей не
обязана равняться единице. Полнота отсутствующих классов внутри аннотированного
объединения остаётся предположением исходного multilabel-контракта.

Прежние бинарные `label` и `review_status` не определяют доступность новой цели.
Например, старый переход мог быть неизвестным из-за частично закрытого участка,
но иметь достаточно сравнимых пикселей для условной доли конкретного класса.
Также не применяется бинарный порог «не меньше 8 изменившихся пикселей»:
регрессия сохраняет малые доли. Исходный допуск границ из `history-targets` сохранён.

Модель получает frozen DINO-векторы прошлых наблюдений, их интервалы и текущий вектор.
GRU/Transformer формирует представление прошлого; текущий кадр получает голова.
Вектор прошлого не содержит текущего или будущих кадров. Голова выдаёт по одному
числу через sigmoid для каждого класса. RGB, даты и классовые маски не пересчитываются.
Маски и размеры сравнимых областей используются только для целей и оценки;
GT-маски не подаются на вход нейросети. Геометрическая поддержка не является видимостью.

Loss — masked MSE. Вес распределён поровну между классами с доступными целями,
внутри класса — поровну между зданиями, внутри здания — между пригодными переходами.
Полностью неизвестные строки пропускаются. Классы без TRAIN-целей отмечаются
`trained_classes=False`; их предсказания в итоговом inference скрываются как
недоступные и не участвуют в метриках. Константные цели допустимы, но явно отмечены
в покрытии: они не доказывают способность обнаруживать изменения.

Известные ремонты требуют границ эпизодов. Автоматические маски не определяют
достоверный ремонт, поэтому данный режим использует полный доступный прошлый
префикс. Сброс по проверенным событиям в бинарном режиме не переносится сюда
неявно; это отдельное ограничение текущего эксперимента.

## 1. Подготовить векторы целей из уже готового запуска

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only

conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow prepare history-fractions \
  --features data/histories/features/index.json \
  --annotation-run runs/2026-10-25-history-targets-001 \
  --out runs/2026-10-25-history-fractions-001
```

Это CPU-проход по сохранённым `targets/*.npz`. Оригинальные RGB, COCO-растеризация,
выравнивание, DINO и дополнительная ручная разметка не нужны. Проверяются завершение
исходного запуска, хеши, идентичность префикса, здания, split, лет и порядок категорий.
Старый запуск сохраняется. Сводка создаётся заново в новом каталоге; для этого
короткого этапа нет отдельного checkpoint/resume.

Выход: `index.json`, отдельные `train.npz`/`val.npz`, `summary.json`, `run.json`,
`experiment_contract.json`, `events.jsonl`. Для каждой цели сохранены доля, valid,
числитель, знаменатель и площадь кропа. `summary.json` показывает по классам/split
число нулей, ненулевых, неизвестных целей, диапазон значений и число зданий.
TEST только при явном `--splits test` и наличии ранее экспортированных TEST-карт.
Отдельные NPZ гарантируют, что TRAIN/VAL не открывают массив TEST-целей.

## 2. Обучить pair, pooled, GRU и Transformer

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow train history-models \
  --features data/histories/features/index.json \
  --class-targets runs/2026-10-25-history-fractions-001/index.json \
  --models pair pooled gru transformer --time-modes gaps none \
  --device cuda:0 --batch-size 64 \
  --epochs 100 --patience 15 --seed 42 \
  --out runs/2026-10-25-history-regression-001
```

`--class-targets` выбирает регрессию и взаимно исключается с бинарным `--labels`.
Флаг `--allow-derived-labels` для этого режима не нужен: происхождение из масок
задаётся самим типом входного артефакта и записывается в отчёт. FPR-порог регрессии
не применяется. Для короткой проверки используйте `--epochs 2` и другой `--out`.
`--device cpu` поддерживается; CUDA проверяется перед загрузкой моделей.

Сравнение сохраняет восемь вариантов: четыре архитектуры с интервалами лет и без них.
Дополнительные контроли ёмкости `pooled-gru pooled-transformer` доступны как раньше.
Выбор checkpoint — минимальная `macro_building_mae` на VAL. Сначала MAE усредняется
по переходам каждого здания, затем зданиям каждого класса, затем доступным классам.
Например, MAE 0.02 — ошибка 2 процентных пункта доли сравнимой области. Дополнительно
сохраняются RMSE и поклассовые результаты. Постоянные нулевые классы могут упрощать
среднюю метрику; диапазоны целей и результаты каждого класса нужно читать вместе.

Контроли: постоянный ноль; среднее и взвешенная медиана TRAIN по классу; косинусные
previous/earliest/history_mean, преобразованные в доли отдельной линейной регрессией
по каждому классу **на TRAIN** с отсечением в [0,1]. Поэтому эти три контроля здесь
имеют обученную калибровку. Все методы оцениваются на одинаковых доступных целях.

`metrics.json` сразу содержит сравнительные VAL-метрики моделей и контролей;
`models.json` — спецификации, порядок классов, хеши и пути к лучшим checkpoint.
Рядом: `coverage.json`, `summary.json` и каталоги моделей с `last.pth`, `best.pth`,
`result.json`, `val_predictions.npz` (предсказания, цели, valid, покрытие, векторы истории).
Прерывание обучения продолжается той же командой с `--resume`; параметры, код
и входы должны совпадать. Завершённый запуск не перезаписывается.

## 3. Оценить сохранённые модели и экспортировать предсказания

```bash
conda run --no-capture-output -n scd_bench python -s -u \
  -m facade_change workflow benchmark history-models \
  --features data/histories/features/index.json \
  --training-run runs/2026-10-25-history-regression-001 \
  --class-targets runs/2026-10-25-history-fractions-001/index.json \
  --splits val --device cuda:0 --batch-size 64 --bootstrap 500 \
  --out runs/2026-10-25-history-regression-val-001
```

Сохраняются `predictions.csv` (строка событие × класс), `metrics.json`, векторы истории
и доли по моделям в NPZ. Есть парные bootstrap-интервалы разностей MAE относительно
парной модели и для gaps − none; единица пересэмплирования — здание. Отрицательная
разность означает меньшую ошибку первого метода. На префиксах 4+ лет сравниваются
обычный прогноз и прогноз с переставленным более ранним прошлым при фиксированной
последней паре. Это inference-абляция, не переобучение модели.

VAL использовался для выбора checkpoint: его интервал не является независимой
оценкой обобщения и не учитывает вариацию обучения. Для TEST нужны явно подготовленные
TEST-маски/доли; используйте `--splits test` после фиксации протокола. Без
`--class-targets` экспортируются все подходящие префиксы выбранных split без метрик.
Префиксные векторы также доступны через `prepare temporal-embeddings` с этим training run.

## OVS, дополнительные объекты и видимость

Существующие `maskclip_stock`, `lposs_stock`, `sam3` уже принимают словарь в
[semantic-routes](2026-10-18-semantic-routes.md). Дообученные фиксированные головы
от нового словаря не получают новых выходных классов. В LPOSS CLIP/MaskCLIP задаёт
соответствие текста и визуальных признаков, а DINO поддерживает распространение меток.
Сохранённый pooled DINO-вектор кропа не является пространственной OVS-маской.
Patch-токены сохраняются только при соответствующем флаге extraction; даже при
их наличии нужны совместимые backbone, preprocessing и текстовое отображение.

Для отдельной проверки контекста разумный небольшой словарь — дерево/кустарник,
транспорт, человек, строительные леса и защитная сетка. Их модельные маски остаются
псевдопредсказаниями с собственными confidence и происхождением. Они могут предложить
исключить перекрытую область или стать дополнительным входом модели после проверки.
Отсутствие предсказанного автобуса не доказывает видимость фасада. Предсказанная
«стена» не доказывает отсутствия повреждения. Неразмеченные пиксели не становятся
истинным здоровым фоном. Этот коммит не смешивает OVS-предсказания с ручными целями.

Для крупных помех можно проверить SAM3 на уникальных исходных фотографиях и перенести
маски сохранённой геометрией в кропы. Это гипотеза экономии вычислений; потерю мелких
деталей при resize надо проверять. Для дефектов может требоваться обработка окон.
Наш `_SAM3Segmenter` уже вызывает `set_image` один раз на RGB, а последующие запросы
переиспользуют state. Время каждого дополнительного текста/синонима остаётся.
Перед ночным запуском нужны измерение на небольшой выборке и оценка общего времени;
текущий шаг регрессии не запускает SAM3 или LPOSS и не требует новых весов.

Проверенные первоисточники (2026-10-25):

- [LPOSS, официальный код](https://github.com/vladan-stojnic/LPOSS)
- [LPOSS, статья CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/papers/Stojnic_LPOSS_Label_Propagation_Over_Patches_and_Pixels_for_Open-vocabulary_Semantic_CVPR_2025_paper.pdf)
- [DINOv2 / dino.txt](https://github.com/facebookresearch/dinov2)
- [Talk2DINO, обученное текстовое отображение для OVS](https://github.com/lorebianchi98/Talk2DINO)
- [SAM3, повторное использование image embeddings](https://huggingface.co/docs/transformers/model_doc/sam3#efficient-multi-prompt-inference-on-single-image)

## Проверки

```bash
python -s -B -m unittest discover -s tests -p test_history_features.py -v
python -s -B -m unittest discover -s tests -v
```

Проверяются условные знаменатели и unknown, маскирование градиентов, равные веса
зданий/классов, отсутствие чтения TEST, источник без бинарных меток, обучение
непрерывным целям, восемь моделей, checkpoint/resume, inference и парный bootstrap.
CPU-синтетика проверяет реализацию; прирост на реальных фасадах ещё не измерен.

Проверка 2026-10-25: до совмещения с общим переносом масок (`a57143a`) полный набор
содержал 1074 теста, ошибок нет, 3 пропуска внешних ArIB/BCM/VTM компонентов.
После совмещения прошли 89 проверок историй/масок/регрессии и 7 проверок workflow,
включая CLI. Новые модели проверены на PyTorch 2.5.1 CPU.
