# Диагностика истории, нелинейный фьюзинг и память переходов

Дата: 2026-11-08. Это следующий разведочный эксперимент на уже сохранённых
картах и DINO-токенах. Его результаты ещё не получены на реальных фасадах.
Исходные признаки, checkpoint ConvGRU, семь детекторов и прежние отчёты не меняются.
Вариант «история только при обучении» остаётся отдельной гипотезой и здесь не реализован.

## Что считается разметкой

Исходные семантические маски размечены человеком. Метки временного изменения
строятся автоматически из этих масок после переноса в общие координаты.
Это не утверждение, что исходная разметка автоматическая или плохая. Ошибка
совмещения или различие обводки границы могут дать тонкую полосу изменения,
хотя объект не менялся. Уже применённая boundary tolerance не гарантирует
устранение всех таких ошибок. Неразмеченная область остаётся неизвестной.

## 1. Одна ConvGRU, разные входы прошлого

Используется один завершённый VAL-selected checkpoint `convgru`, по умолчанию seed 13.
Обучения ConvGRU нет. Проверяются:

| Имя | Вход |
|---|---|
| `convgru-original` | Исходная история и исходные геометрические маски |
| `convgru-common` | Исходная история; support старых кадров пересечён с support предыдущего кадра |
| `convgru-repeat` | Тот же common support, но старые DINO-признаки заменены признаками предыдущего кадра |

Последняя пара, даты, число шагов, веса и support оцениваемого перехода фиксированы.
Сравнение repeat с common меняет содержание старых изображений при одинаковых
масках памяти. Сравнение common с original отдельно показывает эффект изменения
этих масок. Это вмешательство во вход уже обученной модели; оно не заменяет
сравнение независимо обученных `convgru` и `convgru-last`.

Пороги 5/10/15% выбираются для **original на полном VAL** и без перекалибровки
применяются к common/repeat, TRAIN/TEST и поднаборам. Поэтому у изменённого входа
даже VAL FPR может превысить бюджет; колонки `overall_val_*` описывают исходную
калибровку, а `fpr` — фактическую метрику соответствующего вмешательства.

Сохраняются весь набор и переходы с минимум тремя наблюдениями. В текущем
каноническом протоколе события уже начинаются с третьего наблюдения, поэтому
эти когорты совпадают; повторный forward для одинаковой когорты не выполняется.
Это явно отмечено в summary. Наличие старых кадров не доказывает, что сеть их использует.

## 2. Линейный фьюзинг и MLP

Из сохранённых карт после объединения перекрывающихся кропов берутся **все
известные TRAIN-пиксели**. TRAIN занимает float32 memmap. Вклад каждого здания
в суммарную функцию потерь одинаков; bootstrap также выполняется по зданиям.

- `stack`: исходная замороженная логистическая регрессия, обученная ранее.
- `linear-all`: логистическая регрессия с 7 весами и смещением, переобученная
  на всей новой TRAIN-матрице при L2=0.01 по умолчанию.
- `mlp-16`: `7 → 16 ReLU → 1`, 145 параметров, те же семь признаков и TRAIN-пиксели.
  Квантили нормализации и стандартизация общие с `linear-all`, вычислены только на TRAIN.

MLP инициализируется линейной функцией через ReLU(z)-ReLU(-z)=z, с обычной
погрешностью float32. Начальная эпоха 0 участвует в выборе checkpoint. Затем
по умолчанию 10 эпох AdamW, lr=0.001, weight_decay=0.01, batch=8192; каждый
TRAIN-пиксель используется один раз за эпоху в перемешанном порядке. Это не
одинаковая оптимизация с выпуклой LR: архитектура и оптимизатор различаются.
Выбор: максимальный macro recall при VAL macro FPR≤5%, затем меньший FPR,
затем более ранняя эпоха. Один checkpoint используется для всех трёх бюджетов.

Этот refit изолирует семь PREVIOUS-оценок. Он не заменяет старую полную матрицу
OR/AND, всех пар, семантических взаимодействий и PREVIOUS/EARLIEST/HISTORY.

## 3. Память переходов

Это адаптация принципа банка признаков из PatchCore, **не воспроизведение
опубликованного PatchCore**. Используются замороженные DINOv2-токены и случайная
ограниченная выборка по зданиям; исходный backbone, coreset и image-level
reweighting PatchCore здесь не воспроизводятся.
Источник идеи: https://arxiv.org/abs/2106.08265.

Для каждой поддержанной пары токенов сохраняется знаковая разность:

`delta = normalize(DINO(current)) - normalize(DINO(previous))`.

Саму разность повторно не нормализуем: величина изменения должна сохраниться.
Оценка — минимальное евклидово расстояние от delta до банка, делённое на 4.
Деление ограничивает шкалу [0,1]; оно не превращает расстояние в вероятность.
Карта 16×16 разворачивается в 224×224 ближайшим соседом.

Пример: переход «стена при одном освещении → та же стена с тенью» может быть
близок к накопленным помехам. Переход «надпись → чистая стена» сравнивается с
переходами, а не с чистыми стенами. Совпадение текущего вида со старым не является
автоматическим основанием подавлять изменение. Успех обнаружения всё равно
проверяется, а не гарантируется формулой.

### Общий банк и допуск личной истории

Общий банк строится только на TRAIN. Требуются валидные endpoint-токены,
не менее 50% известных GT-пикселей внутри patch и ни одного известного
положительного пикселя. Остальная часть patch может оставаться неизвестной:
это «нет размеченного изменения при достаточном покрытии», не доказанная
чистота всего patch. Устойчивое существующее повреждение также может быть
неизменным состоянием; `ORNAMENT_INTACT` не является обязательным классом.

По умолчанию берётся до 256 векторов на TRAIN-здание, uniform reservoir.
Сохраняются event/patch/year provenance. При запросе TRAIN исключается **всё
здание запроса**, чтобы обучающий переход не находил себя или соседний кроп
того же здания в общем банке.

Личная память не использует GT. Допуск определяется малой DINO-разностью
`||delta||/2`. Порог равен медиане по зданиям TRAIN-квантилей этой оценки на
кандидатах общего банка; default quantile=0.5. Это эвристика, не гарантия
отсутствия изменения и не калиброванная вероятность. Порог фиксируется до VAL/TEST.

Такой допуск выбран ещё и потому, что исходный canonical run **не сохранял
семь карт для самой первой пары наблюдений**. Её DINO-токены уже существуют:
первый переход можно добавить в прошлую память без повторного запуска детекторов.
Для всех прошлых переходов используется один и тот же DINO-допуск.

Личная память содержит только завершённые переходы того же кропа с конечной
датой строго раньше даты запроса. Ни текущий переход, ни будущие наблюдения
не добавляются до его оценки. Память пересобирается из строгого префикса.

### Сравнения

| Метод | Банк |
|---|---|
| `transition-distance` | Только расстояние до общего банка, без фьюзинга |
| `transition-global` | Общий банк TRAIN |
| `transition-own` | Общий банк плюс прошлые переходы этого участка |
| `transition-foreign` | Общий банк плюс переходы одного другого TRAIN-здания |

Донор исключает здание запроса, не использует VAL/TEST-здания или их GT.
Его переходы также заканчиваются раньше текущей даты. В персональный и
контрольный банки добавляется **одинаковое число векторов**, максимум 128.
Если собственной истории или подходящего донора нет, обе добавки пустые.
Это честное совпадение с общим банком, а не выдуманная личная память.
`transition_coverage.csv` показывает доступный объём, фактический matched size
и донора для каждого события.

Для global/own/foreign обучается **одна общая двухпараметрическая поправка**:

`logit = frozen_stack_logit + a * (b + w * standardized_distance)`, `w >= 0`.

`a` — доля поддержанных feature-кропов после overlap merge. При отсутствии
поддержанных DINO-токенов поправка равна нулю. Нормализация расстояния и b,w
обучаются на TRAIN с исключением здания запроса из банка. Затем параметры
одинаковы у всех трёх вариантов. OR/AND и запрет «знакомого» состояния не вводятся.
Для честного сравнения при заданном бюджете каждый вариант получает свой
порог на полном VAL; он фиксируется для TRAIN/TEST и классов. Это отличается
от ablation ConvGRU, где порог намеренно одинаковый для всех вмешательств.

### Как интерпретировать

Ключевое сравнение истории: own против global **и** foreign с учётом фактического
FPR, числа зданий и return-to-past diagnostics. Global против stack проверяет
дополнительную полезность расстояния, но не персональной истории.
Return-to-past по-прежнему означает совпадение аннотированного состояния с
более ранним, а не отдельную ручную верификацию событий A→B→A.

Риски: загрязнение памяти незамеченными изменениями, неоднозначность DINO,
ошибки совмещения, неполное покрытие аннотациями, малое число независимых
зданий и один seed. Размер памяти выровнен; распределения материалов и
временных интервалов доноров не выровнены. Короткие истории могут не дать
допущенных примеров. Нельзя представлять отсутствие выигрыша при почти
пустой памяти как полноценную проверку полезности всей истории.

Решение о продолжении принимается на VAL: нужен выигрыш own относительно
обоих контролей при сопоставимом FPR, не объясняемый единственным зданием и
не сопровождающийся потерей возвращений состояния. При отсутствии такого
сигнала не увеличивать автоматически банк или глубину модели. TEST уже
просматривался; результаты и bootstrap остаются разведочными.

## Запуск

Остановленный исходный memory run нужен только для чтения. При активном
обучении shared lock не берётся. Новые GPU-веса не скачиваются; DINO, исходные
детекторы и ConvGRU не обучаются заново. На GPU проверяется свободная память;
чужие процессы не останавливаются. Запускать после завершения другой GPU-задачи.

```bash
cd /home/sasha/Facade_Change_Benchmark &&
git pull --ff-only origin codex/2026-10-24-main-workflow &&
conda run --no-capture-output -n scd_bench python -s -u -m data_analysis memory-followups \
  --run /home/sasha/Facade_Change_Benchmark/runs/2026-11-08-s192-memory-001 \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-11-08-s192-followups-001 \
  --seed 13 --epochs 10 --fpr-budgets 0.05 0.10 0.15 --resume
```

Программа переходит в сохранённую worker-среду исходного эксперимента. Все
три этапа имеют progress bars; MLP дополнительно показывает эпохи, батчи и VAL.
Завершённые этапы, histogram units, банки и merged scores сохраняются.
При прерывании внутри обучения MLP оно начинается с эпохи 0; оптимизатор
между эпохами не сохраняется. Исходные runs не изменяются. Изменение кода,
настроек или источников требует новой выходной директории.

Для разбора достаточно прислать из нового output:

- `2026-11-08_followup_report.txt` — краткий текст по общим метрикам;
- `2026-11-08_ablation_comparisons.csv` — интервалы разниц при подмене истории;
- `2026-11-08_followup_comparisons.csv` — разницы фьюзинга и банков;
- `2026-11-08_transition_coverage.csv` — действительно ли использовалась память.

Полные классовые и фасадные таблицы находятся в `*_metrics.csv` и
`*_per_building.csv`; возвраты — в `*_return_to_past.csv`. Большие memmap,
merged-block NPZ и исходные признаки присылать не требуется.

## Проверки реализации

Focused tests проверяют неизменность последней пары и дат при ablation,
одинаковый memory support, точную тождественность коротких историй, линейную
инициализацию MLP с погрешностью float32, направленность переходов,
исключение здания TRAIN, причинность и размер donor-memory. Сквозной
процедурный CPU-прогон запрещает RGB/DINO/detector inference, проверяет
точное совпадение старого stack, неизменность исходного run, отчёты и resume.

```bash
python -m unittest tests.test_2026-11-08_memory_followups -v
python -m unittest tests.test_2026-11-08_memory_evaluate -v
python -m unittest discover -s tests -v
```

Датированные модули тестов запускаются явно: обычный discovery с такими
именами файлов может их не включать. Синтетические проверки не являются
результатами качества на реальных фасадах.
