# Статистика фасадного набора COCO

Команда `workflow prepare statistics` считает записи `images` текущего COCO без
чтения фотографий, сегментации, выравнивания и изменения split. С 2026-10-24 код
находится в `facade_change/dataset_statistics.py`; `data/dataset_statistics.py`
остаётся коротким совместимым launcher-ом. Только этот launcher разрешён в Git
внутри `data/`, исходные данные и отчёты остаются вне Git.

```bash
cd /home/sasha/Facade_Change_Benchmark
conda activate scd_bench
python -m facade_change workflow prepare statistics data/result_coco_402.json
```

Другой COCO можно указать первым аргументом. Без аргумента используется
`data/result_coco_402.json` в checkout. Прежний запуск из `data/` также работает:

```bash
cd /home/sasha/Facade_Change_Benchmark/data
python dataset_statistics.py result_coco_402.json
```

## Что считается

- Единица группировки — существующий `building_id`: все виды и элементы одного
  объекта объединяются, как попросил владелец 2026-10-19. Это количество
  идентифицированных фасадов/зданий в принятой группировке, а не число отдельных
  стен здания.
- История — объект с фотографиями хотя бы двух **различных известных лет**.
  Несколько фотографий одного года, включая balcony, side, left/right и v1/v2,
  остаются отдельными изображениями, но дают один год наблюдения.
- Число лет наблюдений — размер объединения лет **всех видов** объекта.
  Это отличается от длины наиболее длинного отдельного вида в политике split.
- Продолжительность — `max(year) - min(year)`, без прибавления единицы.
  Например, 2010, 2015, 2025 — три года наблюдений и интервал 15 лет.
- Средние и медиана продолжительности рассчитываются только по историям,
  с одинаковым весом каждого объекта. Длина по известным датам может быть
  неполной, если у части изображений дата неизвестна.
- Таблица по числу лет включает все идентифицированные объекты: строка 0
  означает неизвестные даты, строка 1 — один известный год. Таблица по
  продолжительности включает только истории. В обеих таблицах сохраняются
  все изображения соответствующих объектов, включая недатированные.
- Остальные изображения объединены в `other_images`: объекты без установленной
  многолетней истории и неидентифицированные снимки элементов. Для известных
  объектов отдельно указаны количество таких объектов и число объектов с
  ровно одним изображением. Неидентифицированные снимки считаются изображениями,
  а не автоматически уникальными физическими фасадами.

## Имена и подтверждённые метаданные

Повторно используются `configs/2026-10-03_metadata_rules.json` и существующие
правила исключений, включая старые имена `man_7_1.png`, `ryileeva_26_2.png`,
хеш-префиксы и подтверждённые варианты одного года. Неизвестная дата в явном
правиле или проверенном CSV остаётся неизвестной.

Для описательной статистики добавлено объединение суффиксов вида только под
**уже известным** именем объекта или вида: `side`, `balcony`, `ornament`,
`left/right`, `front/back`, `top/bottom`, `roof`, `wall`, `facade`, `closeup`,
`detail`, `repairs`, `v1/v2` и соответствующие нумерованные варианты.
Год может стоять до или после суффикса. Это сопоставление помечается `inferred`
и `known_group_view_suffix`, отдельно подсчитывается и не меняет подтверждения
метаданных в основном pipeline. Неизвестные адреса, произвольные суффиксы,
несколько разных годов в имени и числовые продолжения адресов не объединяются
наугад. Неописанные варианты остаются в CSV для проверки.

Если COCO содержит старые имена, используйте реальный CSV переименований:

```bash
python -m facade_change workflow prepare statistics data/result_coco_402.json \
  --rename-map /path/to/image_rename_map.csv
```

`--rename-map` можно повторить. Карты не ищутся автоматически в соседних
каталогах, чтобы случайно не использовать карту другого набора. Подтверждённые
уточнения из существующей таблицы можно передать через
`--metadata-csv /path/to/metadata_review.csv`; её `image_id` должны относиться
к текущему COCO. `--metadata-rules` позволяет явно выбрать другую версию правил.

## Выходы и проверяемость

Сводка печатается в терминал. Каждый запуск создаёт новый каталог
`data/dataset_statistics/YYYY-MM-DDTHHMMSSffffffZ/` относительно входного COCO.
Внутри сохраняются файлы с датой создания в имени:

- `YYYY-MM-DD_dataset_statistics.txt`: сводка и обе таблицы;
- `YYYY-MM-DD_dataset_statistics.json`: числа, распределения и состав фасадов;
- `YYYY-MM-DD_facades.csv`: годы, число снимков каждого года, интервал и
  количество недатированных снимков по каждому объекту;
- `YYYY-MM-DD_images.csv`: все COCO-записи, исходные и разрешённые имена,
  объект, вид, год и источник метаданных;
- `YYYY-MM-DD_run.json`: конфигурация, хеши COCO/правил/скрипта, версия кода,
  статус и хеши отчётов.

`--out /path/to/new/directory` меняет место сохранения. Существующий каталог
не перезаписывается. Дубликаты COCO ID являются ошибкой. Повторяющиеся `file_name`
отмечаются в JSON и сводке, но записи не удаляются автоматически. Содержимое
изображений не проверяется на дубли; считается число записей COCO.

Если есть неизвестные объекты или даты, точное число всех физических фасадов
или полная длительность их историй из одного COCO не установлены. Это видно
в сводке и CSV. Статистика не утверждает геометрическую сопоставимость видов
или наличие реальных изменений состояния.

Проверка на синтетических метаданных:

```bash
python -m unittest discover -s tests -p 'test_dataset_statistics.py' -v
```
