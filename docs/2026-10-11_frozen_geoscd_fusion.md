# GeoSCD AND MSDZip: проверка переноса на TEST и результаты по фасадам

> Историческая инструкция, сохранённая из локального архива 2026-10-24.
> Упомянутый самостоятельный скрипт заменён [пакетом data_analysis](../data_analysis/README.md)
> и командой `python -m facade_change workflow gallery comparison` с `--fusion-run`.
> Команды и числа ниже относятся к прежнему исследовательскому запуску;
> они не являются результатом повторного benchmark при переносе кода.

После TRAIN/VAL-скрининга пользователь выбрал фиксированное правило
`geoscd+msdzip_and`: пересечение прежней маски GeoSCD с прежней маской
`msdzip_mod256`. На VAL F1 изменился с 56.70% до 75.09%; это ещё не результат
на TEST. Исходные TEST-результаты уже были просмотрены. Новая проверка остаётся
исследовательской проверкой переноса, а не окончательным независимым тестом.

`scripts/evaluate_frozen_geoscd_fusion.py` читает сохранённые карты и исходный
завершённый скрининг. Модели, кодеки, обучение и GPU не запускаются. Новые
пакеты не нужны. Скрипт использует существующие `ReuseResults`, проверку
dataset/support/GT, вычисление метрик и фасадное усреднение проекта, а также
помощники уже установленного `analyze_method_complementarity.py`.

## Запуск

Архив содержит только новый скрипт, тест и эту инструкцию. Распакуйте его в
существующий корень `Facade_Change_Benchmark`, где уже установлен прежний
`scripts/analyze_method_complementarity.py`. Совместимость проверяется по
имеющимся исходникам commit `9509ea713245695403a4bb974cec033d7b2d89dd`.

```bash
cd /home/sasha/Facade_Change_Benchmark
conda activate scd_bench
FC_FUSION_TAG="$(date -u +%Y%m%dT%H%M%S%NZ)"
python -u -s scripts/evaluate_frozen_geoscd_fusion.py \
  --run "$PWD/runs/20261010T131625089776Z-neural-codecs-comparison" \
  --screening-run "$PWD/runs/20261011T110912Z-msdzip-complementarity" \
  --out "$PWD/runs/${FC_FUSION_TAG}-geoscd-msdzip-frozen"
```

Это чтение и проверка существующих файлов, не многочасовой inference.
Предварительная проверка хешей может занять время на большом исходном запуске;
точное время на домашнем диске не измерено. После неё выводится прогресс случаев.

## Что фиксируется

- Только выбранное `GeoSCD AND MSDZip`, без перебора иных TEST-комбинаций.
- Исходные четыре метода: MSDZip mod256, GeoSCD, AnyChange и DINOv2.
- Прежние пороги, строгое `score > np.float32(threshold)` и авторские маски.
- Все исходные non-sham VAL/TEST-случаи, без нового поднабора фасадов/условий.
- Та же поддержка RGB-решётки, GT=255 и правила видимых положительных H1/H0.
- Среднее случаев внутри фасада, затем равные веса фасадов. VAL и TEST отдельно.

До численной оценки TEST-карт/GT записывается `frozen_contract.json` с правилом, порогами,
полной выборкой, происхождением исходного запуска и скрининга. Выбор правила
зафиксирован в новом запуске как решение пользователя после VAL-скрининга;
прежний скрининг содержал оба диагностических кандидата OR/AND и сам по себе
не являлся предварительной регистрацией победителя.
Предварительная проверка целостности читает байты TEST-файлов для хеширования;
это не расчёт масок или TEST-метрик.

Проверяются хеши и завершённые статусы benchmark/скрининга, совпадение parent
fingerprint, исходной выборки и порогов. VAL пересчитывается первым: результаты
всех четырёх исходных методов и AND должны в точности повторить прежние
VAL-средние и строки по фасадам. При расхождении TEST не оценивается.
Исходные TP/FP/FN/TN каждого метода дополнительно сверяются с benchmark.
В конце проверяется неизменность использованных файлов; старые запуски не меняются.

## Выходы

- `summary.txt`: VAL/TEST-средние, все фасады, разница AND − GeoSCD в процентных
  пунктах и количество улучшившихся/ухудшившихся фасадов; текст также в терминале.
- `facades.csv`: каждый фасад × каждый из пяти методов, F1/IoU/Precision/Recall/H0 FPR.
- `facade_deltas.csv`: изменения AND относительно GeoSCD по каждому фасаду.
- `summary.json`: те же числа, происхождение и срезы по состоянию/условию/гипотезе,
  с фасадными строками внутри каждого среза.
- `metrics.csv`: TP/FP/FN/TN и метрики каждого случая/метода.
- `gallery.html`: самодостаточная галерея; до чтения GT/карт выбирается первый
  case_id каждого фасада, максимум `--gallery-limit 12` фасадов по умолчанию.
  Численная оценка включает все случаи независимо от размера галереи.
- `frozen_contract.json`, `selected_cases.json`, `input_artifacts.json`, `run.json`:
  правило, выборка, хеши, среда и конечный статус в новом каталоге.

Низкий H0 FPR и высокий Precision могут сопровождаться потерей Recall.
Отрицательные изменения на отдельных фасадах сохраняются в отчёте.
Процедурные изменения и небольшой набор фасадов не доказывают обнаружение
реальных повреждений. Доверительные интервалы и статистическая значимость
не заявляются. Любая последующая доработка по просмотренным TEST-ошибкам
потребует нового независимого набора для итоговой оценки.

## CPU-проверки

```bash
python -s -B -m unittest discover -s tests -p 'test_*complementarity.py' -v
python -s -B -m unittest discover -s tests -p 'test_frozen_geoscd_fusion.py' -v
```

Тестовые данные — завершённый синтетический cache с непересекающимися VAL/TEST
фасадами. Это проверка вычислений и контрактов кода, не домашние TEST-результаты.
Прошли 9 тестов новой проверки и 10 прежнего анализатора. Проверены точное
повторение VAL, ручные TEST-расчёты, строгое сравнение с порогом, таблицы по
фасадам, неизменность входов, отказы при изменении provenance/порогов и
остановка до TEST при расхождении VAL. Сквозной CPU-пример также прошёл.
