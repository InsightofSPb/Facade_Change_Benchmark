# WWW: выбор архивного действия — 2026-11-16

## Наблюдение и границы диагноза

В переданном владельцем логе `www-tool-probe-3-001` все три вопроса закончились
без поиска: два `completed`, один `abstained`, ноль runtime errors. Вопросы о
наличии ранней архивной фотографии и источнике архивного снимка также не вызвали
`archive_search`. При этом первый ответ утверждал отсутствие ранних записей,
хотя архив не был проверен. Полный текст второго ответа в логе отсутствует;
один `decision=supported` не позволяет проверить его фактическую корректность.

В коде обнаружено, что `archival_qa/supported` допускал ссылки только на локальные
фото. Это конкретный дефект проверки происхождения свидетельств. Повторяемый
шаблон final в начальном запросе и после retrieval мог подталкивать модель
к немедленному ответу; это гипотеза о причине поведения, не доказанный механизм.

## Изменение протокола

Revision: `2026-11-16-explicit-archive-actions-v2`.

- В C сначала идёт отдельный запрос выбора действия: `retrieve`, `answer` или
  `abstain`. До этого выбора шаблон финального ответа не передаётся. После
  поиска агент может выбрать ещё один поиск в пределах прежних лимитов.
- `answer` переключает на формирование final; `abstain` также формирует final,
  но только с `insufficient_data/incomparable`. Без поиска разрешены и локальный
  ответ, и отказ. Автоматического dispatch по типу вопроса нет.
- Для `archival_qa` выбор `answer` без показанных архивных записей отклоняется;
  агент может выбрать поиск либо отказ. В финальном `supported` для всех A/B/C
  обязательна хотя бы одна ссылка на действительно показанную архивную запись.
  Наличие такой ссылки проверяет происхождение, а не истинность всего текста.
- Контекст явно различает `not_searched`, `no_matches`, `records_returned` и
  `unavailable`. Пустая выдача относится к запросу и фильтрам, а не доказывает
  отсутствие свидетельств во всём архиве. Семантическая проверка утверждений
  об отсутствии записей по-прежнему требует factual review.
- Все запросы выбора, повторные попытки и финальная генерация оплачиваются из
  прежних лимитов Qwen, токенов, изображений и времени. Jina учитывается как
  прежде. C теперь требует дополнительного выбора перед final; это изменение
  протокола с дополнительной стоимостью, не бесплатное ускорение.
- В терминале видны этап выбора, выбранное действие и реальный вызов инструмента.
  `calls`, `messages`, `reply-*`, `exposure`, `costs` и `events.jsonl` сохраняются.

Общие инструкции и начальные фото A/B/C одинаковы. Финальный контракт выдаётся
на этапе ответа. Веса, retrieval, фильтры, вопросы, разметка, UI и human approvals
не меняются. Новый execution contract запрещает resume старых запусков.
Для итогового сравнения нужны A/B/C одной новой revision; старые ответы нельзя
смешивать с обновлённым C как с неизменным экспериментом.

## Повтор трёх диагностических вопросов в WSL

Используются уже созданные probe inputs и индекс V3.1. Эти вопросы служат
отладке поведения агента и не добавляются в оценочную когорту. Если выходной
каталог уже существует, выбрать новый номер, не удалять предыдущий результат.

```bash
cd /home/sasha/Facade_Change_Benchmark &&
git pull --ff-only &&
set -o pipefail &&
/home/sasha/miniconda3/envs/change-agentic-rag/bin/python -u -m facade_change.agentic www run \
  --questions /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-tool-probe-inputs-001/questions.json \
  --config /home/sasha/Facade_Change_Benchmark/configs/2026-11-15-www-archive-20mp-001.local.json \
  --archive-index /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-archive-index-v31-001/index.json \
  --conditions bounded_agentic_retrieval \
  --out /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-tool-probe-3-002 \
  2>&1 | tee /home/sasha/Facade_Change_Benchmark/runs/2026-11-16-www-tool-probe-3-002.console.log
```

Для двух архивных вопросов проверяем, выбрал ли настоящий Qwen `retrieve`,
был ли инструмент действительно вызван, какие записи показаны и какие из них
процитированы. Для локального контроля допустим `answer` без поиска. Если агент
снова отказывается без проверки доступного архива, исправление ещё не подтвердило
нужное поведение, даже при нуле runtime errors. Корректность дат, идентичности
здания и содержания ответа проверяется отдельно от частоты вызовов инструмента.

Ожидаемые артефакты: `contract.json`, `results.json`, `events.jsonl`, `gallery.html`
и каталоги `questions/<id>/bounded_agentic_retrieval/` с исходными запросами и
ответами. CPU fixtures проверяют только протокол и обработку ошибок; они не
показывают способность настоящего Qwen выбирать инструменты или качество QA.
