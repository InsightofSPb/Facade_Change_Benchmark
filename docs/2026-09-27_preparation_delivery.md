# Подготовка репозитория и данных: поставка 2026-09-27

Область работы — первые два блока `28_09_plan.docx`: сборка репозитория
(28–30 сентября) и воспроизводимая подготовка данных (1–4 октября).
Код этих блоков реализован. Фактические локальные данные, окончательные группы
зданий и CUDA-результаты не подменяются синтетической проверкой в Cloud.

## Что реализовано

| Задача | Реализация и результат |
| --- | --- |
| Общий вход COCO и фотографии | Существующий манифест со статусами, размерами и SHA-256; `prepare` переиспользует его без повторного декодирования 329 RGB |
| Старые скрипты, конфигурации, логи и веса | `inventory` и `prepare --assets-config`; ограниченный просмотр заданных репозиториев, SHA-256 небольших скриптов/конфигов и группы точных копий |
| Происхождение старых моделей | Явные поля известных обучающих групп и источника сведений; неизвестное остаётся неизвестным, файл весов не считается проверенным методом |
| Временные пары | `adjacent`, `first-anchor`, `all`; исходные и исключённые наблюдения сохранены с причинами |
| Новое разделение | `reviewed`: целевые 70/15/15 по числу пригодных изображений; физические здания неделимы; фактические доли, отклонения и числа зданий записываются |
| Предотвращение утечки | Проверки building_id, view_id и одинаковых байтов между train/val/test; разделение выполняется до производных данных |
| Геометрия | SIFT, LoFTR и последовательный SIFT→LoFTR при ошибке/слабом результате; общий MAGSAC в исходных пикселях |
| Проверка результата | Общая сравнительная галерея, исходные фотографии, совмещение, RGB-разность, детали; все отказы остаются в знаменателе |
| Кропы | Прямое семплирование исходного RGB с композицией преобразований; сохранение исходного масштаба опоры, группы и части |
| Контрольные примеры | Четыре случая «изменение состояния да/нет × условия да/нет» и два matched sham-контроля, истинные процедурные маски и геометрия |
| GeoSCD | Проверено назначение официального кода; интеграция отложена как необязательный эксперимент, см. отдельную записку |

Контрольные примеры используют локальное процедурное изменение цвета и
известные сдвиги/фотометрические изменения. Это проверка входа и артефактов,
а не готовая реалистичная модель разрушения. Поддержка изображения и физическая
окклюзия разделены: текущая геометрическая маска не исключает деревья и машины.

пропусков. Проверены геометрия, происхождение данных, split по изображениям,
утечки, сохранение отказов, переход каскада, кропы и контрольные примеры.

Использован официальный outdoor-checkpoint, SHA-256:

Последняя проверка испытывает маршрутизацию, а не обосновывает порог 1000 для
реальных данных. Рабочий порог по умолчанию — 30. Галерея LoFTR и контрольные
выходы осмотрены. Веса и генерируемые файлы в Git не включены.

Старый Torch загружает доверенные веса только с `--trust-checkpoint`.
Новый Torch использует `weights_only=True`. Автоматического обновления среды,
переключения CUDA→CPU или загрузки весов без `--download-weights` нет.

## Локальное выполнение и оставшиеся сведения

Команды для уже готового `manifest-001` находятся в начале README. Они сравнивают
три известные пары: 55:54, 73:74 и 72:71, формируют кропы и контрольные примеры.
Для подготовки всех пар используется тот же `batch --limit 0` без `--pair`.
Предпочтительный массовый режим — `--methods cascade` после просмотра сравнения.

Инвентаризацию компонентов можно включить в тот же `prepare`:

```bash
cp -n configs/sources.example.json configs/local-sources.json
python -B -m facade_change prepare \
  --manifest runs/manifest-001/manifest.json \
  --assets-config configs/local-sources.json \
  --split-mode dev --pair-policy adjacent \
  --out runs/2026-09-27-prepared-with-assets-001
```

В конфигурации указаны кандидаты на исходные репозитории. Отсутствующие пути
фиксируются как missing; ни файлы, ни скрипты старых проектов не удаляются.
Код/конфиги размером до 2 MiB хешируются в общем лимите 64 MiB. Веса и журналы
не исполняются и не загружаются. Совместимость старых компрессионных моделей
и их обучающие фасады требуют фактических сведений из найденных конфигураций.

Для окончательного train/val/test необходимо подтвердить building_id в таблице
метаданных. Сейчас у владельца 244 записи с гипотезой года/вида и 85 неизвестных;
это не 329 подтверждённых физических групп. Например, адреса 16–18 и 18 нельзя
молча считать независимыми. `dev` позволяет сразу проверить методы и производные
данные, но не выдаётся за готовый научный split. После подтверждения групп
`prepare --split-mode reviewed --val-fraction .15 --test-fraction .15` создаёт
новое разделение; производные данные строятся заново с этими назначениями.

Также остаются локальный запуск CUDA, просмотр реальных пар и временная разметка.
Проверка COCO 8182 по неположительной площади пока не выполнена; полигоны
не удалялись. Эти пункты явно отделены от готовности кода и не требуют нового
аудита исправной среды lposs.
