# Малый сравнительный прогон компрессионных оценок

Этот режим быстро проверяет, как текущие H0-trained MSDZip `abs` и `mod256`
сравниваются с RGB-diff, SSIM, zstd и LZMA на одинаковых процедурных парах.
Это проверка направления дальнейших экспериментов, а не окончательный вывод
о превосходстве метода или его устойчивости к каждому условию съёмки.

## Что выбираем

`--quick-bases 10 --selection-seed 42` выбирает до 10 кропов, по одному из
разных зданий: при достаточном составе исходного набора — 3 здания из val
и 7 из test. Train не оценивается. Наследуем существующие назначения split;
здания между частями не перемещаются. Если разных зданий недостаточно,
используется меньшая выборка; недостающие места не заполняются другими
кропами того же фасада.

Для каждого кропа выбираются два разных семейства помех и по одному
конкретному сценарию каждого семейства. Семейства: тень, экспозиция,
контраст, баланс белого, размытие и перекрытие. Выбранные два сценария
одинаковы для всех трёх состояний:

| Состояние | Гипотеза | Пар на кроп |
|---|---|---:|
| `unchanged` | H0 | 2 |
| `crack` | H1 | 2 |
| `paint_patch` | H1 | 2 |
| **Всего** | | **6** |

`self_paste`, чистый вариант `identity` и JPEG в малый прогон не входят.
Семейства чередуются по порядку, заданному seed; выбор здания и кропа
фиксируется по SHA256 до вычисления оценок и просмотра масок. Уровни
интенсивности также чередуются в воспроизводимом порядке: для теней —
15%, 35%, 55%, затем исходные шаблоны внутри каждого уровня; для других
семейств — исходные варианты сценариев. При 10 кропах и полном исходном
пуле представлены все три силы тени и оба варианта экспозиции, контраста,
баланса белого и размытия. При меньшем бюджете или неполном пуле такое
покрытие не гарантируется. На конкретном кропе используется только один
конкретный вариант каждого из двух семейств: помехи не складываются
друг с другом в одной паре.

Новые RGB, маски и аугментации не создаются. Исходный dataset, split,
модели и checkpoints остаются прежними; повторное обучение не требуется.
Все восемь методов получают одни и те же выбранные пары. `selection.json`
сохраняет здания, кропы, сценарии, case IDs, seed и хеши исходного набора.
Подробное распределение семейств и интенсивностей находится в
`selection.json.quick_selection` и повторяется в `run.json.config.subset`.
Хеши родительского dataset не заменяются хешем подвыборки, поэтому ранее
обученные checkpoints продолжают проходить проверку происхождения данных.

## Команда

Перед запуском останови прежний большой benchmark через `Ctrl+C`.
Каталог результата должен быть новым.

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
conda activate lposs

python -u -B -m facade_change h0h1-benchmark \
  --dataset-run runs/2026-10-04-h0h1 \
  --methods rgb_diff ssim zstd_abs zstd_mod256 lzma_abs lzma_mod256 msdzip_abs msdzip_mod256 \
  --msdzip-abs-checkpoint runs/2026-10-04-msdzip-h0-002/2026-10-04_msdzip_h0_abs.pt \
  --msdzip-mod256-checkpoint runs/2026-10-04-msdzip-h0-002/2026-10-04_msdzip_h0_mod256.pt \
  --trust-checkpoint \
  --quick-bases 10 \
  --selection-seed 42 \
  --compression-tile-size 32 \
  --compression-stride 16 \
  --zstd-level 3 \
  --lzma-preset 3 \
  --device cuda:0 \
  --out runs/2026-10-04-compression-quick-001
```

`--quick-bases` имеет приоритет над `--max-bases-per-split`.
Без `--quick-bases` сохраняется прежний полный протокол: можно указать
`--max-bases-per-split 0` и оценить весь исходный набор в новом каталоге.

## Прогресс и промежуточные результаты

Показываются две полосы tqdm: общая для запуска и для текущего кропа,
объединяющая все методы. Одна единица прогресса — завершённая оценка одной
пары одним методом. Для 10 кропов это 60 пар × 8 методов = 480 оценок;
на кроп приходится 48 оценок. Полоса обновляется после завершения оценки,
поэтому во время одного вызова MSDZip она может некоторое время стоять.

После каждого завершённого кропа выводятся:

- Таблица всех методов с F1, IoU, precision, recall, H0 pixel FPR,
  временем вычисления карт, порогом, долей сравнимых пикселей и долей
  сохранившейся видимой правки.
- Таблица всех шести пар: для H1 показан F1, для H0 — FPR каждого метода.
- После тестового кропа — накопленная таблица TEST с равным весом зданий.

F1/IoU/precision/recall относятся к видимым пикселям H1; H0 оценивается
отдельно по ложным срабатываниям. Полностью закрытая правка не получает
искусственно нулевой или идеальный F1: метрика не определена и выводится
как `—`. Покрытие сохраняется в отчёте. Известные маски правок и видимости
по-прежнему используются только в evaluator, а не передаются scorers.

Сначала рассчитываются val-кропы. Их текущие таблицы используют
**предварительные пороги только по уже обработанному val** и помечаются
соответственно. После всех выбранных val-кропов один порог каждого метода
фиксируется; только затем начинается test. Во всех тестовых таблицах
используются эти фиксированные пороги. Финальные val-метрики также
пересчитываются при итоговых порогах.

После каждого завершённого кропа сохраняются `live_metrics.json` и
`progress.txt`. Они позволяют прочитать промежуточные результаты, в том
числе после остановки. Уже вычисленные карты остаются в `scores/` и
`native_bpb/`. Автоматическое продолжение прерванного запуска этот режим
не реализует. По завершении создаются стандартные `summary.txt`,
`summary.json`, `metrics.json`, `metrics.csv`, `threshold_selection.json`
и `gallery.html`.

## Сколько ждать и как интерпретировать

Оба варианта MSDZip выполняют 60 × 2 = 120 оценок. При наблюдавшихся
44,6 секунды на пару это около **89 минут только для MSDZip**.
Практический ориентир — **1,5–2 часа** с остальной обработкой, но это
не гарантированный срок: он зависит от размеров поддержки, устройства
и фактической скорости. tqdm постепенно уточнит оставшееся время.

Сравнивай методы внутри этого запуска: прежние полные RGB-diff/SSIM
таблицы рассчитаны на другом составе случаев и не являются прямым
контролем для новой подвыборки. На семи тестовых фасадах можно увидеть
крупные проблемы и понять, стоит ли расширять эксперимент. Нельзя
утверждать, что метод лучше вообще или устойчив ко всем помехам.
Остановка после просмотра первых test-результатов остаётся диагностикой;
такой неполный результат не выдаётся за завершённое сравнение на всех
заранее выбранных фасадах. Настоящие изменения между годами здесь
по-прежнему не проверяются.
