# 2026-11-16 — заполненные приватные карточки review

Подготовленные ответы теперь можно проверять как обычные карточки: исходные RGB,
предложенный результат, текст ответа, ограничения и готовые рамки. Рисование мышью
нужно только для исправления области. Состояние сохраняется в браузере и выгружается
отдельным JSON; можно восстановить сохранение только для того же кандидата и пакета
предложений. Нет массового approval или автоматического подтверждения источников.

`2026-11-16-assistant-review.html` — отдельный шаблон. Старый review, scoring,
промпты моделей и исходные 16 человеческих решений не изменены.
`2026-11-16-render-assisted-review.py` принимает подготовленный приватный payload:
он проверяет SHA предложений, уникальность вопросов, исходные координатные решётки,
наличие встроенных изображений и отсутствие approvals. Реальные изображения,
ответы и payload в Git не добавляются.

```bash
python scripts/2026-11-16-render-assisted-review.py \
  --proposals /absolute/path/2026-11-16-www-filled-proposals.private.json \
  --out /absolute/path/2026-11-16-www-filled-review.private.html
```

На странице «Подтвердить ответ и выделенные области» — явное человеческое решение.
Изменение ответа, видимости, ограничений, вопроса или рамок снимает подтверждение.
Непроверенные строки не попадают в decisions. Изображения и черновые пояснения
не включаются в публичный export. Рамки хранятся в `region_crop_pixels`; масштаб
канваса относится только к отображению. Повторные кропы одного предложенного
события могут иметь общий `event_id` и собственные рамки.

Для earliest карточка явно ограничивает вопрос показанными локальными датированными
наблюдениями. Это предложение изменения формулировки, а не сохранение широкой
архивной задачи. Архивный earliest требует отдельной привязки `earliest_archive`;
интерфейс не выдаёт локальную дату за наиболее раннюю во всём V4.1. Фотографии
на уровне здания показаны как контекст без support approvals. Частные пакеты
нельзя добавлять в retrieval.

Экспорт решений совместим с `qa review` на точных исходных candidate bytes.
Если уже существует применённый review для этой же когорты, необходимо сохранить
его revision chain через `--previous`; нельзя применять старые revision=0 поверх
существующих решений. Предложенный пакет этой сессии начинает отдельный review
полного all-candidates manifest; старые 16 остаются на своём исходном manifest.

Проверки: Python renderer tests, Node DOM-контракт (явное подтверждение, снятие
approval при редактировании, native drawing/cancel, earliest precision и restore),
проверка подготовленных меток настоящим `_checked_label` без записи approvals.
Node DOM не заменяет визуальный тест настоящего браузера: запуск Chromium в
текущей среде блокируется политикой сокетов. Настоящие Qwen/Jina не запускались.
