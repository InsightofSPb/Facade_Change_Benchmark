# Facade Change Benchmark

Единый проект для подготовки и исследования изменений исторических фасадов.
Текущий путь: **COCO → манифест → временные пары → SIFT / LoFTR / каскад →
кропы из оригиналов → контролируемые примеры и общая галерея**.

Версия: 2026-09-27. Это рабочая подготовка данных и диагностика геометрии;
сравнительный benchmark детекторов повреждений пока не выполнен.
Источники перенесённой логики описаны в [provenance](docs/2026-09-27_provenance.md).
Состав поставки и фактические проверки — в [отчёте подготовки](docs/2026-09-27_preparation_delivery.md).

## Быстрый запуск в существующей lposs

Среда `lposs` и манифест `runs/manifest-001/manifest.json` уже проверены на машине
владельца: доступны 329 фотографий, SIFT завершил девять запусков на трёх парах.
Повторять аудит среды или декодирование всех фотографий для изменения метаданных
не требуется. Команды выполняются из корня проекта без установки пакета.

```bash
cd /home/sasha/Facade_Change_Benchmark
git pull --ff-only
conda activate lposs

python -B -m facade_change prepare \
  --manifest runs/manifest-001/manifest.json \
  --split-mode dev --pair-policy adjacent \
  --out runs/2026-09-27-prepared-dev-001
```

`prepare` использует уже сохранённые размеры и хеши, не открывает исходные RGB.
Неизвестные наблюдения остаются в манифесте с причинами исключения из пар.
Режим `dev` предназначен для проверки геометрии; это не разделение для обучения
или итогового оценивания.

Следующая команда сравнивает три метода на тех же трёх парах, сохраняет кропы
по геометрии каскада и по шесть контролируемых примеров из одного кропа каждой
пригодной пары:

```bash
python -B -m facade_change batch \
  --manifest runs/2026-09-27-prepared-dev-001/manifest.json \
  --pair 55:54 --pair 73:74 --pair 72:71 \
  --methods sift loftr cascade --limit 3 \
  --max-side 1024 --ransac-threshold 3 \
  --device cuda --checkpoint auto --trust-checkpoint --download-weights \
  --allow-inferred-metadata \
  --crops --crop-method cascade --tile-size 256 --stride 128 --controls 1 \
  --out runs/2026-09-27-methods-and-data-001
```

```bash
cat runs/2026-09-27-methods-and-data-001/summary.txt
explorer.exe "$(wslpath -w /home/sasha/Facade_Change_Benchmark/runs/2026-09-27-methods-and-data-001/comparison.html)"
```

Строки галереи — пары, столбцы — методы. Ссылки `Open details` показывают
оригиналы, наложение, шахматное совмещение и детали в исходном масштабе; ссылки
`crops` и `controls` открывают производные данные. Ошибки и отклонённые результаты
остаются в таблице. Код возврата `2` у `batch` означает завершённый запуск с такими
проблемами; галерею всё равно можно открыть. Для повторного запуска выбери новое
имя выходного каталога: существующие результаты не перезаписываются.

Для всех подготовленных пар убери три аргумента `--pair` и укажи `--limit 0`.
Список реально выбранных пар сохраняется в `selected_pairs.json`.

## LoFTR и текущая среда

LoFTR выполнен с настоящими outdoor-весами на CPU в Python **3.9.23**, PyTorch
**1.12.1+cpu**, Kornia **0.8.1**, NumPy **1.26.4**. Синтетические изображения
имели разные размеры, не кратные восьми: 191×237 и 209×259. Получено 498 inliers
из 498 поддержанных соответствий; максимальная ошибка на проверочных точках с
известной геометрией — 0.357 исходного пикселя. Это проверка совместимости
загрузчика, масок и координат. CUDA и реальные фасады проверяются локальной
командой выше; качество LoFTR на них заранее не утверждается.

`--checkpoint auto` ищет `loftr_outdoor.ckpt` или `outdoor_ds.ckpt` в стандартном
Torch-кеше. `--download-weights` разрешает скачать официальный outdoor-checkpoint,
только если этих файлов нет. Без этого флага скачивания не происходит.
Для весов вне кеша укажи их полный путь через `--checkpoint`.

PyTorch 1.12.1 не имеет `weights_only`; `--trust-checkpoint` явно разрешает
старый загрузчик pickle для доверенных весов. В более новых Torch используется
`weights_only=True`, без скрытого перехода на pickle при ошибке. Ключи весов
проверяются строго, SHA-256 и способ загрузки сохраняются в `run.json`.
Для неизвестного локального checkpoint сначала установи его происхождение.

LoFTR дополняет grayscale-прокси до размера, кратного восьми, и исключает
неподдержанные области из соответствий. Полноразмерные RGB этим не изменяются.
`--device cpu` разрешён явно; автоматического переключения с CUDA на CPU нет.
Модели запускаются последовательно, состояние GPU записывается перед загрузкой.

## Геометрия, каскад и кропы

Все методы оценивают преобразование `source → reference`: reference — раннее,
source — позднее наблюдение. Это не предполагает, что ранний фасад неповреждён.
SIFT и LoFTR используют общий MAGSAC в исходных пикселях опоры. `max-side`
ограничивает только прокси для соответствий; итоговый RGB сохраняет масштаб
исходной опоры. Холст расширяется по объединению кадров.

В `cascade` первым запускается SIFT. При ошибке или непрохождении порогов по
числу/доле inliers, их пространственному покрытию и геометрическому пересечению
запускается LoFTR. Это простое последовательное правило; соответствия двух
методов не объединяются. Пороги служат для выбора ветви и не доказывают точность
совмещения каждого пикселя. Все попытки и выбранный метод сохраняются.

Каждый кроп строится непосредственно из оригинальных RGB: перенос окна
компонуется с исходной гомографией до интерполяции. Уже сохранённые выровненные
PNG повторно не интерполируются. Сохраняются преобразования, хеши оригиналов,
маски поддержки и геометрического пересечения. Отклонённое совмещение не
используется для создания кропов; `batch` берёт только выбранный `crop-method`.

`overlap` учитывает геометрию, alpha и поддержку интерполяции. Он **не исключает
физические окклюзии** деревьями, машинами или лесами. Чёрный RGB может быть
валидным. RGB-разность также отражает освещение и ошибки геометрии; она не
является маской повреждений.

## Разделение train / validation / test

До подготовки данных для обучения требуется подтверждение физических зданий.
`view_id` обозначает конкретный вид, а `building_id` объединяет все виды одного
здания. Имена файлов дают лишь гипотезы; например, виды `9-ya_linia_VO_16-18`
и `9-ya_linia_VO_18` могут пересекаться. Они отмечаются для проверки в
`group_review.csv`, но автоматически разными зданиями не объявляются.

Скопируй таблицу проверки и подтверди `view_id`, `building_id`, `year`, затем
поставь `reviewed=true` у проверенных наблюдений. Исходный завершённый манифест
при этом не меняется:

```bash
cp runs/manifest-001/metadata_review.csv runs/2026-09-27-metadata-review.csv
```

После заполнения таблицы:

```bash
python -B -m facade_change prepare \
  --manifest runs/manifest-001/manifest.json \
  --overrides runs/2026-09-27-metadata-review.csv \
  --split-mode reviewed --pair-policy adjacent \
  --val-fraction 0.15 --test-fraction 0.15 --seed 42 \
  --out runs/2026-09-27-prepared-reviewed-001
```

Целевые доли по умолчанию — **70% / 15% / 15% исходных изображений** для
train / validation / test. Все наблюдения и виды одного подтверждённого здания
попадают целиком в одну часть; из-за размеров групп точные доли могут отличаться.
В отчёте сохраняются фактические количества. Фиксированный seed обеспечивает
воспроизводимость для одного и того же входного набора.

Разделение проверяется по `building_id`, `view_id` и SHA-256 изображений.
Неизвестные записи остаются исключёнными; кропы и контролируемые варианты
наследуют часть исходного здания и не могут переопределить её. Для нового запуска
`batch` используй reviewed-манифест; пары можно отфильтровать через `--split`.
Наличие разделения само по себе не создаёт истинную временную разметку.

## Контролируемые примеры

Для каждого выбранного кропа создаются четыре комбинации «процедурное изменение
есть/нет × изменение условий есть/нет» и два парных контроля самовставки.
Изменение состояния — локальное изменение цвета, условий — известный сдвиг
и фотометрическое преобразование. Сохраняются истинные преобразования,
маски процедурной области, граница вставки и несопоставимые пиксели.

Это контроль корректности обработки и артефактов, а не реалистичная симуляция
разрушения фасада. Метки обозначают только заданное процедурное изменение;
семантическая COCO-разметка отдельных наблюдений тоже не считается истинной
разметкой временного изменения.

## Выходные файлы

| Файл | Содержание |
| --- | --- |
| `manifest.json`, `pairs.csv`, `split.json` | Наблюдения, пары, части и причины исключений |
| `metadata_review.csv`, `group_review.csv` | Подтверждение метаданных и возможных пересечений видов |
| `comparison.html`, `results.csv`, `results.json` | Общая галерея и все успешные/неуспешные попытки |
| `geometry.json` | H source→reference и перенос reference→canvas |
| `reference_rgb.png`, `source_rgb.png` | RGB на общем холсте в масштабе исходной опоры |
| `overlap.png`, `source_only.png`, `reference_only.png` | Геометрическое пересечение и поддержка одного кадра |
| `absolute_residual_rgb.png` | Поканальная абсолютная RGB-разность; вне overlap нули |
| `rgb_mean_absolute_difference.npy` | Средняя RGB-разность; вне overlap NaN |
| `matches.csv`, `diagnostics.json` | Соответствия, inliers, ошибки, пороги и выбранная ветвь |
| `crops.json`, `crop.json` | Происхождение кропов, части, координаты и хеши |
| `examples.json`, `example.json` | Параметры и метки контролируемых примеров |
| `summary.txt`, `run.json` | Короткий отчёт, версии, конфигурация, статусы и хеши |

`completed_needs_review` означает законченный расчёт, требующий просмотра;
`completed_rejected` — сохранённое совмещение, не прошедшее пороги.
`completed_with_issues` сохраняет частично выполненный пакет вместе с ошибками.
Для обсуждения результатов достаточно `summary.txt`, `results.csv` и нужных
изображений. HTML-галерея использует относительные ссылки: при переносе файла
нужно сохранять рядом папки изображений.

## Инвентаризация компонентов и GeoSCD

Команда `inventory --config PATH --out NEW_DIRECTORY` просматривает только
явно заданные каталоги исходного кода, конфигураций, журналов и весов. Результат
содержит кандидаты, пределы просмотра и неизвестные сведения об обучающих
фасадах. Наличие файла не подтверждает совместимость или выполненный эксперимент.
`configs/sources.example.json` задаёт исходные каталоги; `prepare --assets-config`
может выполнить эту инвентаризацию в том же запуске. Небольшие скрипты и
конфигурации хешируются для поиска точных копий; веса и журналы не загружаются.
Большие данные, веса и результаты остаются вне Git.

GeoSCD не включён в текущий запуск. Его возможная роль и требуемый адаптер
описаны в [отдельной записке](docs/2026-09-27_geoscd_scope.md).
Он остаётся дополнительным экспериментом для сложной геометрии и предполагаемых
окклюзий; результатов на наших фасадах пока нет. DINOv2, RSCD, AnyChange,
компрессионные детекторы и их общая научная оценка также не объявляются выполненными.

## Новый набор данных и Codex Cloud

Для нового набора, у которого ещё нет манифеста, скопируй `configs/paths.example.json`,
укажи COCO и узкие каталоги исходных фотографий, затем выполни `manifest` один раз:

```bash
cp -n configs/paths.example.json configs/local.json
python -B -m facade_change manifest --config configs/local.json --out runs/manifest-001
```

Относительные пути считаются от каталога JSON-конфигурации. Проверка COCO сейчас
ограничена метаданными: полигоны не растрируются и не удаляются. Уже завершённый
манифест повторно не создавай; исправления метаданных применяются через `prepare`.

В Cloud установка CPU-зависимостей и тесты выполняются скриптом
`bash scripts/setup_cloud.sh`. Синтетический сквозной пример:

```bash
python -B -m facade_change demo --out runs/2026-09-27-cloud-demo-001
```

Локальный `lposs` этим setup-скриптом обновлять не требуется. Аудит среды нужен
при конкретном новом сбое или изменении окружения, а не перед каждым запуском.
