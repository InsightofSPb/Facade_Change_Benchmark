# Facade Change Benchmark

Основа единого проекта для исследования изменений исторических фасадов.
Сейчас работает путь **COCO → проверяемый манифест → выравнивание пары → диагностическая галерея**.
Разработка в Codex Cloud и запуск на локальном датасете используют один код.

Версия основы: 2026-09-27. Это ещё не законченный benchmark и не результаты статьи.
Переиспользованная логика и ограничения описаны в [provenance](docs/2026-09-27_provenance.md),
проверки — в [отчёте](docs/2026-09-27_verification.md).

## Что уже есть

- Проверка всех записей COCO: поиск файлов, неоднозначности, SHA-256, фактические размеры,
  статусы доступности и отдельные статусы временных метаданных.
- SIFT и адаптер LoFTR с общим переводом координат и MAGSAC в исходных пикселях.
- Расширяемый общий холст; оригиналы RGB интерполируются один раз.
- Маски поддержки и пересечения, RGB-разность, соответствия, геометрия, галерея деталей.
- CLI, CPU-пример с известной геометрией, тесты, инструкции для Cloud, журнал каждого запуска.

SIFT проверен здесь на синтетике. LoFTR реализован, но запуск с весами ещё предстоит.
Фотографии владельца в репозиторий не включены. Детекторы DINOv2, RSCD, AnyChange,
SSIM, GeoSCD и компрессионные модели добавим после проверки общего входа.

## Codex Cloud

1. Подключи этот GitHub-репозиторий к окружению Codex.
2. В поле setup script укажи `bash scripts/setup_cloud.sh`.
3. Первое задание содержится в [docs/2026-09-27_first_cloud_task.md](docs/2026-09-27_first_cloud_task.md).

Скрипт ставит CPU-зависимости и запускает тесты. Для отдельного просмотра галереи:

```bash
python -m facade_change demo --out runs/cloud-demo-001
```

Открой `runs/cloud-demo-001/sift/gallery.html`. Для повторного запуска выбери новое имя каталога.
В Cloud не требуется `/home/sasha`, GPU, COCO владельца или веса моделей.
Настройка окружения описана в [официальной документации](https://developers.openai.com/codex/cloud/environments).

## Первый локальный запуск

Сначала используем имеющуюся среду, например `lposs`. Из корня репозитория выполни:

```bash
conda activate lposs
python -B scripts/audit_environment.py --run-tests --out runs/env-lposs-001
cat runs/env-lposs-001/summary.txt
```

Аудит не устанавливает и не обновляет пакеты. Проверяются реальные импорты, SIFT/MAGSAC,
связка PyTorch–NumPy, наличие LoFTR в Kornia и состояние GPU. Веса не загружаются.
Короткие CPU-тесты выполняются при наличии базовых зависимостей. Результаты аудита сохраняются
в новой директории; подробности неудачного импорта остаются в audit.json, тестов — в tests.log.
Код возврата 2 означает, что текущая среда не прошла все проверки CPU-основы.
Отсутствие Torch/Kornia не мешает отдельной проверке COCO и запуску SIFT.
CPU-основа поддерживает Python 3.9+. Проверена отдельная среда Python 3.9.23,
NumPy 1.26.4, Pillow 11.1.0 и OpenCV 4.12.0: все 18 тестов прошли.
Аудит разделяет импорт PyTorch, обмен с NumPy, доступность CUDA и наличие аргумента
weights_only у torch.load. Отсутствие этого аргумента блокирует текущий загрузчик LoFTR,
но не означает, что PyTorch не импортируется или что SIFT/COCO не работают.
Расхождение версии OpenCV в метаданных и импортированном модуле явно отмечается в отчёте.

При необходимости сравни вторую существующую среду:

```bash
conda activate scd_bench
python -B scripts/audit_environment.py --run-tests --out runs/env-scd-bench-001
```

После выбора рабочей среды команды выполняются прямо из корня, установка проекта не нужна:

```bash
cp -n configs/paths.example.json configs/local.json
python -m facade_change manifest --config configs/local.json --out runs/manifest-001
```

Пины requirements-cpu.txt задают проверенное окружение Cloud/CI; локальная среда может иметь
другие версии. До результатов аудита не запускай setup_cloud.sh и не обновляй её зависимости.
Импорт LoFTR не подтверждает совместимость конкретных весов: это следующий отдельный smoke.

Создание отдельной среды остаётся запасным вариантом, если существующие окажутся непригодны:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-cpu.txt
python -m pip install --no-deps -e .
python -m facade_change doctor
python -m unittest discover -s tests -v
python -m facade_change demo --out runs/local-demo-001
cp -n configs/paths.example.json configs/local.json
python -m facade_change manifest --config configs/local.json --out runs/manifest-001
```

Можно также вызывать `python -m facade_change` из корня без editable-установки.

Конфигурация уже содержит известные пути:

```text
/home/sasha/LPOSS/datasets_mine/data_18_08_329/result_coco_18_08_329.json
/home/sasha/LPOSS/datasets_mine/images_516
```

Это кандидаты из аудита: локальная команда должна подтвердить соответствие всех файлов.
Относительные пути в JSON считаются от каталога этого JSON.
Указывай узкие каталоги исходных изображений, чтобы не смешивать их с масками и результатами.

Манифест сохраняет все наблюдения, включая отсутствующие файлы, неверные размеры и неизвестные годы.
Код возврата 2 означает завершённую инвентаризацию с проблемными изображениями; смотри `summary.txt`
и `manifest.json`. Код 1 — ошибка выполнения, 0 — команда выполнена без таких проблем.
Проверка annotations пока ограничена метаданными: полигоны не растрируются и не удаляются.

## Выбор и подтверждение одной пары

В `runs/manifest-001/metadata_review.csv` проверь только выбранные наблюдения:
`view_id`, `building_id`, `year`; выставь им `reviewed=true`. Остальные строки оставь как есть.
`building_id` объединяет все виды одного физического здания. Не подтверждай его по одному сходству имён.

После визуального просмотра возможный кандидат — `baskov_34`: image_id 55 (2016) и 54 (2019),
если эти номера и даты подтверждаются текущим COCO. Это предварительные сведения из аудита,
а не автоматический выбор подходящей пары.

```bash
python -m facade_change manifest --config configs/local.json \
  --overrides runs/manifest-001/metadata_review.csv --out runs/manifest-002

python -m facade_change align --manifest runs/manifest-002/manifest.json \
  --reference-id 55 --source-id 54 --method sift --max-side 1024 \
  --out runs/baskov-2016-2019-sift-001
```

В команде замени IDs, если выбрана другая пара. Неизвестные записи вне пары не блокируют выравнивание.
Флаг `--allow-inferred-metadata` разрешает диагностический запуск на гипотезах из имён,
фиксируется в run.json и не разрешает отсутствие года/вида или конфликт зданий.

## LoFTR локально

Используй окружение с совместимыми PyTorch/Kornia и локальный доверенный checkpoint
Kornia LoFTR (обычный state_dict или словарь с ключом state_dict). Установка варианта
PyTorch для конкретной CUDA — отдельный шаг после `doctor`. Код не загружает веса из интернета.
Если существующий Torch не поддерживает weights_only, сначала проверь другую уже установленную
среду (например scd_bench). Поддержка CPU на Python 3.9 не означает совместимость любых версий Torch.
В начальной версии проверка совместимости — строгое `load_state_dict`; несовместимые ключи дают отказ.

```bash
python -m facade_change doctor
python -m facade_change align --manifest runs/manifest-002/manifest.json \
  --reference-id 55 --source-id 54 --method loftr --max-side 1024 \
  --checkpoint /absolute/path/to/loftr_outdoor.ckpt --device cuda \
  --out runs/baskov-2016-2019-loftr-001
```

Путь к checkpoint — заполняемый пример. По нему нет предположения о наличии весов.
`--device cpu` допустим явно; скрытого переключения с CUDA нет.
По одной паре нельзя сделать вывод о превосходстве метода.

## Как читать результат

| Файл | Значение |
| --- | --- |
| `manifest.json` | Все наблюдения, статусы, пути, размеры и хеши |
| `metadata_review.csv` | Таблица подтверждения вида, здания и года |
| `geometry.json` | H source→reference и отдельный перенос reference→canvas |
| `reference_rgb.png`, `source_rgb.png` | RGB на общем холсте в исходном масштабе опоры |
| `overlap.png` | Пересечение геометрической поддержки и alpha |
| `source_only.png`, `reference_only.png` | Поддержка только одного наблюдения, не изменения |
| `absolute_residual_rgb.png` | Поканальная абсолютная разность; вне overlap нули |
| `rgb_mean_absolute_difference.npy` | Средняя разность RGB в [0,255]; вне overlap NaN |
| `matches.csv`, `diagnostics.json` | Соответствия, inliers, ошибки и покрытие |
| `gallery.html` | Превью совмещения и три детали без изменения масштаба |
| `summary.txt`, `run.json` | Короткий отчёт, конфигурация, версии, статусы и хеши |

`overlap` не исключает физические окклюзии. Чёрные пиксели не считаются фоном автоматически.
Первый снимок не считается неповреждённым. `completed_needs_review` означает готовый расчёт,
который ещё нужно осмотреть; число inliers не является доказательством верного совмещения.
При неудаче сохраняется run.json со статусом failed. Существующие каталоги не перезаписываются.

Для передачи результатов в чат достаточно содержимого `summary.txt` и при необходимости
`diagnostics.json`/`run.json` плюс нескольких изображений. Архив полного датасета не нужен.

## Ближайший порядок работы

Сегодня: подтвердить манифест → осмотреть одну пару SIFT/LoFTR → исправить явные ошибки геометрии.
Затем: новые кропы и контролируемые H0/H1-аугментации → адаптеры существующих детекторов →
сопоставимое оценивание на своём и внешних датасетах. История, компрессионный контекст,
память нормальных участков и абляции строятся поверх этой основы.

Для докладов сохраняем примеры успехов и отказов. Для статьи нужны подтверждённые группы фасадов,
временная разметка, протокол оценки и воспроизводимые результаты; синтетический smoke не заменяет их.
