# Facade Change Benchmark

Единый проект исследования изменений исторических фасадов: COCO → семантическое
состояние → выравнивание RGB → временные и компрессионные оценки → анализ ошибок.
Реальные данные, веса и результаты остаются локально.

## Основной workflow

**Подготовка данных → обучение при необходимости → бенчмаркинг → галерея.**

Единый вход: `python -m facade_change workflow STAGE TASK ...`.
Используйте существующую среду; рабочие Torch/CUDA и веса повторно
не устанавливайте без конкретной причины.

| Стадия | Команда | Что входит |
|---|---|---|
| Подготовка | `python -m facade_change workflow prepare --help` | Реальные/синтетические данные, split, RGB alignment, кропы, аугментации, истории |
| Обучение | `python -m facade_change workflow train --help` | Семантическая голова, MSDZip, ArIB, BCM; готовые модели переиспользуются |
| Бенчмаркинг | `python -m facade_change workflow benchmark --help` | Синтетика, реальные пары, PREVIOUS/EARLIEST/HISTORY, robustness, сохранённые метрики, LOFO и fusion |
| Галерея | `python -m facade_change workflow gallery --help` | Истории, сравнения, ошибки, листы для слайдов, сохранённый LOFO и локальный atlas |

[Основная инструкция, входы/выходы и план переноса кода](docs/2026-10-24-main-workflow.md).
Каждая стадия запускается отдельно; `STAGE TASK --help` показывает её параметры.
Сохранённые данные, модели и карты позволяют продолжать с нужной стадии.
Прежние команды остаются совместимыми. Составной `temporal-experiment`
сохраняет [прежний контракт обучения и resume](docs/2026-10-14_temporal_experiment.md).

Локальный `data/dataset_statistics.py` со статистикой и инкрементальным
выравниванием развивается отдельно. Этот PR его не добавляет и не заменяет;
его завершённая сессия подключается к `prepare crops --alignment-session` и
`prepare real-audit --alignment-session` без повторного выравнивания. Выбор метода,
review, split и ссылки на Canny/cycle/drift сохраняются; синтетика работает как раньше.
После отдельного quality rerun можно явно передать `--quality-report`: импорт
проверяет сохранённые хеши и сохраняет исходный статус preparation без его правки.

Для эмбеддингов историй: `workflow prepare crop-histories` собирает RGB-кропы
в координатах самой ранней фотографии каждого вида, а `workflow prepare history-features`
извлекает frozen DINOv2-признаки и сохраняет интервалы по годам. Геометрия берётся
из существующей сессии; изображения и признаки кэшируются отдельно.
[Команды, формат данных и продолжение эксперимента](docs/2026-10-25_history_features.md).

## Данные и научный контракт

Подготовка берёт только изображения текущего COCO. Хеш-префиксы и
`*image_rename_map.csv` разрешаются без переименования оригиналов. Проблемные
файлы печатаются по именам COCO. Категории и пересечения аннотаций сохраняются;
нераспознанный адрес или год не выдумываются. Подтверждённые соответствия находятся
в одном `configs/2026-10-03_metadata_rules.json`.

Политика `facades-v4`: около 70/10/20 по числу подтверждённых зданий. Все виды и
даты здания остаются вместе. Короткие и длинные серии направляются в TRAIN;
одиночные снимки и неизвестные адреса пригодны для семантического TRAIN, но не
создают временные пары. Доли кропов справочные. Кропы сегментации: 512×512, шаг 448.

При расширении сохраняется split последнего запуска. `semantic_history.json`
удерживает прежнюю принадлежность даже после смены COCO ID или временного удаления
снимка. Ранее неизвестный TRAIN-снимок после уточнения адреса не переносится в
VAL/TEST. Для оставшихся неизвестных адресов физическая независимость от holdout
не доказана; результаты с ними остаются exploratory.

Пары по умолчанию first-anchor: поздний снимок сопоставляется с самым ранним
пригодным снимком того же вида. Опора не объявляется здоровой. Alignment работает
с исходным RGB без EXIF-поворота; source_to_reference задаёт направление.
Геометрическое перекрытие не доказывает отсутствие окклюзий.

Реальные кандидаты по COCO экспортируются в исходном масштабе: весь связный
переход классов и контекст 100 px вокруг. Общая галерея показывает совмещённые
кропы, классовую легенду и тот же участок в доступные годы. Отбор по GT требует
проверки и не заменяет оценку обнаружения на целом фасаде. Готовые SIFT-выравнивания
и синтетические истории переиспользуются.

DINOv2 заморожен, обучается линейная multilabel-голова. Неразмеченные пиксели
не становятся здоровым фоном. VAL оценивается каждую эпоху; полная оценка TRAIN
на оригиналах — каждые 20% эпох и в конце (`--train-eval-fraction 0.2`). Между
ними TRAIN loss, F1, mIoU, precision и recall берутся из уже вычисленных учебных
батчей и явно отмечаются как онлайн-диагностика. Полная оценка имеет равные веса
фасадов и учитывает перекрытия кропов один раз. Основной checkpoint выбирается
по VAL; отдельный лучший TRAIN сохраняется для диагностики. Рядом с весами
сохраняются галереи кропов с разметкой, прогнозом и легендой. Отдельная оценка
`--evaluation-mode originals` строит общую страницу целых фотографий со всеми
классами, GT, прогнозами и легендой. Она использует сохранённый лучший VAL
checkpoint и прежний порог; TEST читается только при явном `--splits test`
(или при перечислении нескольких split, включающем test), без обучения и настройки.

Синтетические истории имеют известную программу событий и независимые условия
наблюдения. Реальные переходы аннотаций после alignment — кандидаты для просмотра,
а не автоматически подтверждённая временная истина. RGB остаётся исходным
сигналом компрессионной ветки; маски служат семантической боковой ветвью.

Каждый запуск имеет новый каталог, входные хеши, конфигурацию и конечный статус.
Основная статистическая единица — фасад. MODEL bits/NLL и реальный декодируемый
поток — разные результаты. Успешный CPU-тест не доказывает качество на фасадах.

## Структура и очистка

| Каталог | Назначение |
|---|---|
| `facade_change/` | Подготовка, геометрия, benchmark; `methods/` — адаптеры, `segmentation/` — семантика, `research/` — исследовательские прототипы и temporal snapshot, `gallery/` — atlas, экспорт и сохранённые галереи |
| `data_analysis/` | Анализ уже вычисленных карт без повторного inference |
| `scripts/` | Установка, настройка, аудит и совместимые входы; real_eval переносится поэтапно |
| `configs/`, `docs/`, `tests/` | Контракты, инструкции и проверки действующего кода |
| `data/`, `weights/`, `models/`, `third_party/`, `runs/` | Локальные данные, зависимости и результаты вне Git |

Дата в имени не означает ненужность: `2026-10-04_msdzip_h0.py` используется
MSDZip, обучением ArIB/BCM и исследовательскими командами. Датированные scripts
сохраняют прежние рабочие протоколы; обычный COCO обновляется через
`scripts/prepare_dataset.py`. Подробные исторические инструкции находятся в
`docs/`, а не повторяются в README.

План очистки строится от результатов, которые нужно сохранить:

```bash
python -s scripts/audit_environment.py --cleanup-plan \
  --keep-run runs/20261011T175248818684449-dataset-402 \
  --keep-run runs/20261011T175248818684449-augmentations-402 \
  --keep-run runs/20261010T131625089776Z-neural-codecs-comparison \
  --keep-run runs/20261011T120819613907687Z-method-recall-analysis \
  --scan-root /home/sasha \
  --out runs/cleanup-review
```

Добавьте `--keep-run` для завершённого обучения, которое хотите оставить.
Незавершённые запуски защищаются автоматически. Аудит ничего не удаляет:
перечисляет зависимости, причины сохранения, кандидаты и неразрешённые ссылки.
Сохраняемые эксперименты могут зависеть от COCO, split, карт и checkpoint из старых запусков.
Для очистки читаются записи о запусках, конфигурации и манифесты с путями к входам.
Содержимое аннотаций COCO, покроповых индексов, масок и карт не проверяется:
их зависимости учитываются по записанным путям, без загрузки этих данных.
Соседние LPOSS/MSDZip/DINO/GeoSCD репозитории могут поставлять код или веса.

Для передачи результатов достаточно `summary.txt` и `cleanup.csv`.
`cleanup.json` хранит сгруппированные диагностические примеры с ограничением
объёма, счётчиками повторений и пропусков. Имена файлов без контекста пути и
обычный текст не считаются файловыми зависимостями; старые cleanup-отчёты
повторно не сканируются. Пропущенное содержимое данных не считается ошибкой чтения.
Если не удалось прочитать запись о запуске или его зависимостях, это отдельно
блокирует рекомендации по очистке. Ограничение вывода не обрезает граф зависимостей.
Причины неполного чтения выделяются в `scan_errors` и печатаются отдельно от
обычных отсутствующих ссылок. Имена исходников в `environment.source_sha256`
разрешаются относительно пакета; отсутствующий старый исходник отмечается как
исторический fingerprint, а не как потерянный файл результата.

Старые локальные `analyze_method_complementarity.py` и
`evaluate_frozen_geoscd_fusion.py` заменены `python -m data_analysis` и в текущем
Git отсутствуют. Оставшиеся копии отмечаются аудитом отдельно.
Новые задачи расширяют существующие команды; новый файл нужен только для отдельной
ответственности, а не для очередного запуска.

## Проверка

```bash
python -s -B -m unittest discover -s tests -v
```

Cloud-окружение: `bash scripts/setup_cloud.sh`. Тесты не скачивают оригинальные
веса и не запускают полное обучение.
